## 1. 本轮要回答什么

W44 两流真实完成各 +512/2，到 14737/update57、tail0、excluded145，但 35 个实际训练回合有 32 个物理失败。最终固定 E30 分别在 11.934/12.742 秒跌倒，均未实际加载材料，合法去返/往返为零。技术交付和科学资格分别报告。

原件显示：N 方向恢复前移的同时，出现了**几乎相同的名义轨迹被视为微小改善，却替换为很不同的反馈策略**的事件。A 的 call163/plan156（2.84 s）alpha=0、成本仅改善约 8.05e−15，名义反馈倍率为 0，安装倍率却变为 1；2.852 s 产生大幅实际反馈。B 的 call173/plan161（3.04 s）同为 alpha=0，约 2.17e−12 的名义改善把倍率 .0133352 变为 1；3.044 s 已有 .499676 rad 有效反馈、.907618 rad 的 H 投影修正，held 目标偏离 accepted 约 .910716 rad；3.052 s 有效反馈进一步达到约 5.144 rad。

这些策略的完整名义 rollout 确实经过评分；问题不是已经证明“偷偷安装了未评分 K”，而是**名义轨迹上的近零误差不能证明离轨反馈的行为值得替换**。数值近似平手时，完整策略的动作、reference、K、H、feedback scaling 不能被不同层级的选择逻辑拼接或重置。B 在 2.9282 s 已先发生 hold 内饱和，因此修复该问题不保证消除所有失稳。 进一步的原件显示，B在约2.7484–2.8032s有54.8ms全足无接触，2.74s的native nominal与alpha0候选也预测了这段腾空，且早段状态很贴近实际。这说明更早的名义支撑行为本身也需评估，不能承诺仅保留baseline就消掉它；A对应最早窗口未保存完整候选，覆盖缺口如实保留。

W45 的主要科学问题是：**保留有意义的 N 运动方向，同时修复上述接纳/保留规则，能否在原 Go2/TM02 任务中得到稳定的合法去程和完整往返？**

为隔离这一控制变化，A/B 固定各自 update57 Actor、归一化和原评价策略，不做 PPO 更新。学习计数维持 14737/57，不新建空训练回合充数。原 PANN 因果观察、cap 输出和完整材料任务仍运行。

## 2. 唯一主改动：完整策略的有效改善与平手保留

拟命名 `S5-r34`，在 spec 中明确区别于已运行的 r33。主机制只改完整策略的接纳与保留；native FD、尺度 D、约束 Riccati 和原成本保留。

### 2.1 当前问题中的完整基线

每个新问题仍按 r32 epoch 规则初始化数值生命周期，对当前状态/时间重评分 incumbent 与合法 nominal 候选。维护一个真实可部署的完整基线对象，包含：actions、times、state reference、K、H、feedback scaling、活动约束语义、目标/阶段/context 身份和评分。旧时刻的低成本不能直接带到新问题作为有效分数。

候选比较沿原 `(trunk violation v, native cost J)` 优先级。真实物理硬条件、.02 材料域、非足接触、跌倒和力矩限制均保持原判据。浮点成本比较规则不用于放宽物理合法性。

### 2.2 数值平手必须有明确、可复算定义

在 spec 记录 native 成本累计方法、机器精度、项数/量级、同输入重复评分的误差，以及据此选择的 absolute/relative comparison tolerance。使用与当前问题成本规模对应的预算；不能随手设置一个绝对 1e−6 或借调整 surprise 人为触发接纳。

当候选的有效改进落在该数值平手范围内，保留当前问题中已重评分的完整基线。平手策略必须确定性选择，并记录被保留对象和被拒绝对象的完整身份。不能只留旧 actions，却换入新 K/H 或将反馈倍率重置为 1。

同一 comparison/alpha0 身份规则必须覆盖 **nominal/BestRollout 的基线选择、r33 `R33Consider`/candidate archive 与继承 r32 的 `Iteration` descent、`accepted_native_descent`、停止/重试和正则状态更新**。只修最终 archive 会让内部仍把舍入下降记为真改善。no-step 的预计/真实改善与 surprise 应明确标注不可作为有效改善依据，不能用极小分母放大比值推动数值状态。保持原新问题重置和同问题有限重试。已检查事件中候选到安装的13类数组完全一致，禁止拼接是修复契约，并非宣称当前已发现安装偷换。

### 2.3 alpha=0 的语义

alpha=0 可以是保留/评分候选，但**不能仅凭名义成本的浮点下降授权替换一套新的离轨反馈**。本轮默认把这类没有可辨识前馈改善的候选作为 no-step：保留已评分基线的完整反馈对象。若 alpha=0 的完整策略身份与基线本来相同，则照常记为保留，不制造一次“优化成功”。

纯反馈更新并非理论上无价值；它需要额外的离轨闭环依据。本轮不以名义轨迹的微小数值差代替这种依据，也不通过全局关闭 TV、人工 K 限幅或修改真实力矩边界绕过问题。

正 alpha 也不自动安全。新完整策略仍须按原约束进行 native rollout、完整评分与一致安装；W45 的真实闭环评价用于检验修正的实际效果。改变后的平均、插值或精修策略需要重新评分，不能继承其输入候选的分数。

针对两规则各自选中的完整策略，可做三个统一初态的诊断：名义初态、一个明确记录的实际状态减reference切空间误差向量、该向量的反向同尺度偏差；保存源时刻、reference身份与缩放比例；正确使用 MuJoCo 切空间/四元数积分，不直接相加 qpos 的四元数。每个初态完整 rollout .35 s，共最多 4×2×3=24 次诊断；记录原 `(v,J)`、动作/力矩/姿态、反馈与投影、接触和失败。偏差诊断是离轨行为证据，不是新物理成功阈值，也不是线上读入未来状态。

记录 solver 调用、实际新 rollout、FD 子调用、缓存命中和墙钟；这些计算与 24 次诊断分开。保存失败/非赢家对象，不只保留优胜索引。此比较只服务当前修复，不增加独立站立、刚地、旧 QP 回放等一串准入试验。

## 5. 第三任务：GPU 完整候选批量筛选支线

GPU 支线与 CPU 并行，使用上面四个问题；不替换 CPU plant，不热改 r34，不重启旧 G5，也不新增第三条 PPO 谱系。

每问题固定32候选槽：两个有真实来源的完整基线身份，加15组正负的结构化动作扰动。复用已存在的 r33 P-family 范围，先写明候选生成与绑定的完整策略；本轮不扩幅值、horizon 或 worker 网格。

32个独立world在device内推进完整350ms：175个2ms控制段，每段10个.2ms物理步，即每问题56,000、四问题224,000 world-step。这是明确工作量，不是时限承诺。预分配、批量上传、device内因果推进、末尾统一取回，避免旧G5每个子步反复host拷贝、同步和49份重复名义world。

若未完整迁移 K/H/投影，GPU 必须标注为近似 proposal 评分；最终候选仍由 CPU 原生完整策略重评分。先计时 GPU 排名后 CPU 确认 top4 与必要基线，再计算剩余候选构成32槽离线真值；不能把已有 native 真值当作免费确认。指标为 top4 召回、约束漏报、按 `(v,J)` 的 regret、相对基线改善和从输入到 CPU 确认的总耗时；编译、离线真值成本、缓存与共卡影响分别记录。

若排序或端到端耗时没有收益，交付有限负结果并自然结束支线。完整实现细节与旧 G1/G2/G5 的实际边界见 [GPU报告](../results/terrain_memory/simulation/tm-s1-go2-local-readiness-r12/reviews/W44-final-review/gpu-report.md)。旧 G5 的既有最终原件可同步收集，不为了补文件而重跑旧评价。
