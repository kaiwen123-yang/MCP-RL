## 1. 这轮要改变的推进方式

W52 的几何修复与双分支均真实执行，但 D2/D3 在 5.6716/6.6278 s 触发 floor–trunk 非法接触；最大前进仅 7.332/29.941 mm，两条轨迹均未加载材料。首个有效 S 的足端目标已到约 5 mm，native 预测中计划摆动的 FR/RL 仍承重约 28.20/33.75 N。两臂真正参考过期均为零。这个结果已足够否定“再修一次相位/再多一个旧局部方向就应恢复行走”的默认推进方式。

下一轮直接比较两个完整控制内核：

| 工作线 | 回答的问题 | 实际工作与完成物 |
|---|---|---|
| **N：R8/S3 运动内核适配** | 历史已能走稳的完整运动机制，接回当前 plant/任务后是否仍能走、失败从何处开始？ | 恢复来源清楚的新基线；一次原 E30；完整物理、视频和材料分段结果 |
| **F：接触力 MPC + 全身控制（WBC）** | 显式协调支撑力、摆腿和身体运动，能否解决当前“几何抬脚但不卸载”的结构问题？ | 独立完整控制器与正确 PD 接口；一次原 E30；同一原任务评价 |
| **C：服务 F 的 GPU 批量模型计算** | GPU 能否承担真正需要的模型/矩阵计算，而非重复已完成的残差归约？ | 既有状态上的 FP64 模型与约束装配、误差及含传输的耗时；不在线安装 |

N/F 是不同完整控制器的实用比较，**不是单变量消融**。不能用两套不同成本函数的 J 数值判断优劣，也不能用成功者倒推某个单一成本、步高或偏置就是唯一原因。第三线不阻塞 N/F，两个控制器不等待对方完成编码才启动各自必要的原任务。

长期目标不变：原 Go2/TM02 合法完整往返 → 稳定重复加载与跨足/返程曝光 → 材料持久状态的因果收益 → 泛化与 Go2/NX。W53 首先取得可用运动内核，并把失败明确分成起步、材料接触、转向、返程或长时间支撑。

### 3.3 当前任务适配边界

将旧运动内核接到当前任务命令、plant 与记录器，核清 foot/body/joint 顺序、参考坐标和时间。N 的旧预测器并没有 TM02 状态模型；它是**材料未知的运动基线**。它收到当前因果高层 cap，并在真实材料上接受原评价，不能宣称 N 已验证材料记忆控制收益。

这条路线允许回答两种有价值的结果：若材料前就能恢复行走，说明当前运动控制包是主要回归范围；若到材料后才失败，则把下一问题收敛到模型/受力与材料相互作用。若 N 在平地也失败，则审查适配差异与实际命令/状态，不继续用旧 9/9 替它背书。

## 4. F：接触力 MPC 与 WBC 构成一条完整新控制链

本轮选择**独立的接触力 MPC + WBC**，不同时开发另外一种“动力学 seed 叠回旧 B”的混合路线。参考 MIT MPC/WBIC 的力与运动组织、Perceptive NMPC 的执行/接触反馈，以及近年的全身逆动力学 MPC 约束；不把任一论文机器人参数直接移植为 Go2/TM02 参数。

### 4.1 高层、接触与身体计划

实现 SRBD/centroidal 接触力 MPC：以当前实际身体位姿、速度及原 mission 命令初始化，输出身体运动、接触力序列和统一接触日程；明确所用模型及近似。身体参考从实测速度连续生成，不能把当前速度瞬间设成目标速度。F 固定使用 Trot、2 Hz、duty .60、名义摆高 .03 m 及一套确定的起步转换，不做本轮调参扫描。N 仍保留 R8 的 .45 软 gait 目标；F 的 .60 是新控制器的显式接触日程，二者语义不同。新控制器可以有自己的确定性起步转换，必须事先写入合同，不能每次重规划把 apex 往后推或反复重置步态。

F 的每对角支撑 .30 s、摆动 .20 s，两对角之间每半周期有 .05 s 四足重叠，没有计划飞行段；这不等于对角双足静态稳定，也不保证成功。摆足 p/v/a 由同一 .20 s swing 的边界与固定 apex 一体生成一套 C2 曲线，不能复用 W52 的 .075 s rise/.20 s descent 或 end−.20 的 apex 公式。3 cm/.20 s 的实际落地冲击仍接受原材料判据。

同一接触日程同时生成支撑足任务和摆足 p/v/a：支撑足规划正法向/摩擦约束，摆动足规划反力为零；身体加速度和剩余支撑腿必须共同提供所需合力与力矩。计划中的零摆足力是优化变量约束，**不得覆盖 MuJoCo/TM02 的真实接触力或接触标记**。接触未按计划解除、提前触地或晚触地时，用当前可测接触/状态反馈处理，并记录模式不一致，不能通过改诊断标签宣称卸载成功。

原 .35 s 预测范围与逻辑 50 Hz MPC 保留；F 可以采用适合其模型的节点离散，必须在首个 E30 前冻结并解释，不能把其节点数和当前 native iLQG FD 数视为等预算。

### 4.2 全身动力学与执行权限

WBC 在原 500 Hz 控制时刻求解全身任务，协调身体与摆足加速度、规划反力和完整关节命令。使用同一 Go2 模型的质量矩阵 M、bias/passive 约定与接触 Jacobian J；浮基动力学与关节力矩必须一致：

\[
S_f(M\ddot q+h-J_c^T f)=0,\qquad
\tau_j=S_a(M\ddot q+h-J_c^T f).
\]

力矩和关节可达限制进入求解，原 plant 限幅始终保留。只有 IK 几何收敛或某瞬间静态 mg 平衡，不算完成 F。不要复用不对应新参考的旧 B 的 K/H、raw 支撑中心或旧 J 比较器来接管 F；F 有自己的完整状态/输入参考与反馈、自己的求解状态与失败记录。

采用明确的一种完整命令接口。若输出为 `(q_d, v_d, tau_ff)` 且期望原 joint PD，则当前 affine actuator 的未截断关系是：

\[
\tau=60(u-q)-5\dot q,
\quad
u=q_d+(\tau_{ff}+5v_d)/60.
\]

这样才包含支撑前馈、位置和速度三个部分；不能只执行 q_d，也不能再次叠加旧承重偏置。若实现改为 WBC 输出已经含全部反馈的 tau_des，须另行采用与其语义一致的映射，不能把同一反馈计算两遍。记录选择的接口，并让预测/执行使用同一保持与饱和模型。瞬时未截断恒等式不证明整个 2 ms hold 内的轨迹等价。

可行性约束必须作用于映射后的 u 和完整总力矩 tau_total=tau_ff+60(q_d−q)+5(v_d−v)，在当前状态满足原 ctrlrange/forcerange；不能仅约束 tau_ff 或 q_d 就声称执行可行。实际 hold 内的总 PD、裁剪和接触响应继续由原物理记录核对。

当前 H/QP 与旧 raw-policy 绑定，F 不经过这套旧控制器投影。F 自己在 WBC 内处理原限位/力矩可行性，随后仍走真实 actuator/ctrlrange/forcerange。不可通过放宽执行器或事后修结果完成任务。

### 4.3 材料相容性

刚地 stance 零法向速度不能机械复制到可压入/回弹的 TM02。F 在材料区必须使用当前可测接触和已有因果局部材料/表面信息，明确法向目标/柔顺关系及未知量；不把世界足点锁死来阻止真实材料压入。不添加未来真值或预知回程。若材料预测内态仍未沿未来动作传播，报告这一限制。

本轮只选一套可解释的 MPC/WBC 参数、接触转换与材料适配，首个 E30 前冻结。技术接线错误可以定向修复，但实际已成立的物理负结果不靠换 seed、换步高、加大力矩或再叠第三方法反复追成功。公开代码的控制族可用，不代表 Go2/TM02 可直接运行；实际构建/模型适配失败如实交付，也不阻塞 N。

## 5. 直接进入原 E30，取消新增 D8 前置轮次

这次新机制直接进行原完整任务，而不是再安排一组 D8：

1. **N-seed1 与 F-seed1 各一次独立原 E30**，同 W44 A 冻结政策、真实 t=0、正常物理提前终止。两者实现和资源就绪即可并行；先就绪者不等待另一者。版本建议 r42/r43，但以现场未占用新身份为准，名字不替代真实 backend/build 身份。
2. E30 必须按现有 `s1_go2_r11_protocol.py` 原标准：观察满 30 s、真实穿过 x=.8–2.2/y±.6 的材料条带且发生材料受载、到达原远端；不能侧绕或只站满 30 s。完整视频、轨迹和物理规则决定结果。
3. 若 N 通过原 E30 且完整记录支持正常持续支撑推进，优先冻结较直接的 N 适配基线；若 N 的原 E30 失败，或 N 已明确技术阻塞/本轮实现终止而未形成可用结果，且 F 达到这些条件，则选 F。N 仍正常构建或运行不算失败；技术未运行与物理失败分开记账。F 尚在运行时保留其真实任务，不为公布 N 结果而强停。不能仅凭几秒早段、略长存活或 J 更低选定。
4. 选定控制器的**这一次已预声明且身份一致的 seed1 E30 可以直接作为其 E60 前序**，不再重跑同一个 E30。另一个计算槽启动所选控制器 W44 B/seed2 的一次 E30。两 case 各自逐级 E30→E60→E300→E600，任何 case 失败仅阻塞自己的后级，不能互借资格。若配置、workers、代码或政策身份改变，既有前序资格不能偷偷延用。
5. E60 是完整合法双向材料往返、回家稳定 2 s 并观察满 60 s；E300/E600 是原 5/10 往返，270/540 s 路线期限及末端保持，独立观察满 300/600 s。物理任务时长不是后台墙钟 deadline。
6. 若两条首轮 E30 都失败，不新增第三个物理控制族、不展开旧 9+3 刚地矩阵、不再开 D8。交付各自完整结果，并将“未形成步态”“正常走到材料后失败”“转向/返程失败”分开。正常运动已经恢复但材料失败，应保留这个进展，后续围绕材料机制设计下一轮。

预声明首轮 N/F 各一次 E30；实现/资源就绪才启动，技术阻塞可少于两次，不能为凑数启动。只有一个控制器进入后续两 case 阶梯，且所有后级均有原前序条件。最多为首轮两个 E30、所选 seed1 的 E60/E300/E600、所选 seed2 的 E30/E60/E300/E600，合计 9 个预声明阶段；这不是 9 次强制启动，更不是失败计数。没有任何固定墙钟结束时刻。

## 6. C：用 GPU 处理 F 真正需要的模型计算

W52 C 已完成 XML 高度序列化修复，MaterialSupportHeight 残差误差 8.88e−16，不能再把它或 114 个已保存残差的 J 归约作为新成果。96 GB 显存不等于当前 CPU native/FD 自动提速。

C 的新范围是 F 所需的批量 Go2 运动学/动力学与矩阵装配：足位置/雅可比、质量矩阵/偏置力或经明确选择的 centroidal 量、最终实际需要的 MPC/WBC 约束/目标矩阵。先与 F 固定接口，再选择其中完整可表达的计算路径；可使用 CasADi/CusADi 或同等 FP64 批量实现。必须列清重建模型中的质量/惯性、关节坐标与自由基表示，不能用另一机器人近似得到的数冒称本模型输出。

输入只用 W52 两条已保存完整 trajectory 的实际状态，一次有限遍历；由同一冻结模型取得必要 CPU 参考。可以计算运动学/动力学函数，但**新 plant stepping、native rollout、FD、PPO 均为 0**。不通过旧错误 bridge，不另开 episode 补缺字段。两条 W52 都未加载材料，因此不能由它们证明材料接触分支已覆盖。

输出包括所需矩阵/约束/目标的误差、真实分支覆盖、单位和对动作/可行性的影响；不以 bit-exact 作为总门。计时区分首次编译、实际完整批量计算、数据传输与总耗时，并给 native/F 实际任务中这部分的占比。若仅支持一部分，按部分能力报告；若小批/单 MPC 延迟没有收益，结束为“当前无在线收益”，不重复扩大 batch 凑显存。

C 只形成可审查的离线路径，不在本轮 N/F 物理任务中途更换 CPU/GPU backend，也不把其完成当作主线前置资格。以后若要在线换后端，另建明确身份与原任务证据。

## 7. 资源与记录：保证有效并行，消除无根据的满载判断

现场有完整 25 核余量时：N 最多 10 核、F 最多 10 核、C/独立记录与分析 2 核、系统/主控/其他项目约 3 核。数学线程库为 1，构建并行总上限先 -j6；构建与运行共享额度，不能每个编译器/子服务再开一份 10 核。两个重物理 job 是并行上限，C 是无 plant 的第三线。F 小 QP 实际用不满 10 核时按真实实现记录，不虚报 workers 或再开无目的重复任务。

W52 的 getrusage 全阶段平均：D2 为 4.737 核、D3 为 4.596 核，/proc 稳定 PID 差分为 4.809/4.647 核。它们说明整项任务未满用分配的 10 核，不证明 native 求解器在热阶段也只用一半。已有阶段计时未覆盖总墙钟的 41.38%/42.56%；完整候选 NPZ 共 648 份、20.918 GB，是记录/压缩/串行开销的具体待核对象。

在下一次正常 job 的同一进程中分开记 native/model/derivative/backward/rollout、RPC、轨迹提取、序列化、压缩/写盘与等待的 wall/CPU。不要另开 worker 扫描、满载 benchmark、全仓 hash 或重复旧保存问题。优化的依据是本次正常任务的实际阶段耗时。

记录策略在首个 E30 前声明。保留完整 500 Hz trajectory、全程 5000 Hz 实际接触力/真实力矩/力评估与积分后双时钟、完整材料时序、命令/反馈/限幅/接触模式和全时段视频；每个实际安装的完整 policy/accepted trajectory 或 F 完整参考/反力/WBC 命令及来源必须可追溯。全部候选保留轻量分数、可行性、步态/前进统计；完整候选 ring 保留起步首次切换、首个有效运动参考、首次材料加载、首个接触模式不一致/执行改写及最终失败等明确事件，按 call_id 去重。对“拒绝了正常候选”之类结论，必须有对应完整原件，否则只能写未知。

可将不可变快照异步写盘/压缩，避免重复落相同对象，但必须在同次候选仍有效时取得副本，不能以稍后 ring 代替、不能补跑轨迹。写入队列有界、不得静默丢实际安装证据；队列阻塞与最终 flush 时间如实单列。不能删除 W52 或任何已引用科研原件来提速。首次新控制器实现可优先使用现有可靠记录路径，但必须明确其成本，不能让记录器改动拖住 N/F。

## 8. 实施、后台与交付约定

实施覆盖真实 spec/build/prepare/runtime/后端/记录/协议身份，而非只增加 r42/r43 名字。现有代码有显式旧版本集合和 `w51_fixed_policy` 合同门；新后端必须接通同次 mission 命令、actor、真实初始化、query/hold、终止与记录。保持原语义的必要编译和定向验证即可，不再写镜像实现的测试、全仓 smoke/mock/shape/import/哈希扫描或额外微物理准入。

**所有新后台 `deadline=null`、`wall_deadline_enabled=false`，省略 `deadline-unix`；无固定墙钟完成时间、无到点 kill、对话结束不杀后台。** 原物理任务长度、真实物理失败、明确技术/数值/资源错误、用户停止与有限科学工作量保留。单次网络请求 timeout 不等于整个实验 deadline。已正常进入 tmux 的长任务可以持续运行，汇报真实 running、进程与下一续接点，不靠等待用户再次说“继续”才推进已授权阶段。

GitHub 是交付处：代码与紧凑结论先推；必要原件和全时段视频从 D57 增量直传 Release。短写串行整合最新 main、不强推；回执不明先核远端。commit/URL/size/digest 核验后结束，**不在用户电脑额外下载、复制、镜像、压缩或归档**。保留服务器仍被引用的 checkpoints/resume/科研原件；只用已授权网络，不自动借用户电脑 VPN/Clash/SSH 转发。

最终报告分别给出：实现是否完成；正常步态是否恢复；原 E30/E60/E300/E600 到哪一级；材料记忆收益是否真的评价；GPU 的真实覆盖/收益；实际物理/技术/任务目标失败、blocked/未运行；工作量、CPU/GPU 与 I/O；GitHub 提交/资产和续接点。发布此计划不等于 W53 已启动，更不等于 S1 已成功。
