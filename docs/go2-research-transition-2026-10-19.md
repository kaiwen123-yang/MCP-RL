# Go2作为下一阶段主要研发载体：二维诊断的边界与推进顺序

日期：2026-10-19。性质：根据用户最新意见调整研究顺序，保留MPC规划、RL执行及既有负结果。**下一阶段优先Go2整机仿真中的基线复现、任务测试与算法迭代；不再要求二维对象先取得性能优势。** 本轮只确认路线与接续记录，没有启动训练、仿真、安装、服务器或实机操作，也不开自动检测。

## 1. 为什么应当转入Go2

二维对象的名义动力学已知、状态完整、传播与优化便宜，直接物理MPC可能成为非常强的对照。它适合检查推导、实现关系、明显目标退化与基本学习流程；却不充分体现我们关心的接触切换、执行历史、部分观测、反馈引起的闭环响应以及在线预测成本。

本项目最近四组实验没有运行完整的直接物理MPC，因此“它可能很强”是合理的对象适用性判断，不写成已经测得的胜负。无需先证明这一可能性，才能转入机器人研究。

Go2也不自动保证共同学习有收益。转入Go2的理由是问题与验证对象更匹配：需要实际比较真实反馈、可预测响应与完整任务的取舍；不是希望用更复杂的平台掩盖旧方法错误。

下一阶段的核心问题是：在接触、历史状态和执行限制影响运动响应时，能否让RL学出对后续任务有用的恢复与转向行为，使MPC获得可信的响应预测，并改善连续任务的成功率、时间或资源代价。先围绕一个任务族和一个主要执行困难展开，不同时承诺解决所有地形与扰动。

原顺序应理解为“基础理论/原型→有代表性的机器人仿真→必要实机”，不应变成“二维必须先显著胜出→才允许进入机器人”。

## 2. 二维结果保留什么，不承担什么

| 既有结论 | 后续处理 |
|---|---|
| 本次codesign在二维固定预算下三seed均劣uniform | 保留为该对象/配置的负结果；不外推Go2共同学习无价值 |
| 固定策略和记录命令时，自由预测器可以通过自身任务项制造乐观 | 保留为结构风险；Go2版本需要改变这条信息流 |
| 目标时域、参考信息、校准语义存在不一致 | 作为下一实现需正确处理的设计问题，不成为无止境小实验 |
| 数学推导、数据/计算计账与实现一致性基础 | 复用必要部分；不为扩大检查数量继续扩展二维模型 |
| 二维直接物理MPC可能很强 | 说明学习法不一定适合以该对象证明优势；不能要求RL先战胜它才进入Go2 |

撤销“二维显著性能增益是进入Go2的必要条件”。不撤销“事实预测与未实现目标要区分”的结论。

## 3. 下一项主交付应是能做研究的Go2测试环境

基线复现与方法修正围绕同一个可运行体系推进，工程检查以正确执行、可采集、可比较为终点。

### A. 先复现一个原生Go2运动基线

从一套有来源的Go2代码、机器人模型和策略出发，固定观测/历史、关节顺序、动作缩放、PD/执行频率与必要控制限制，实际运行速度跟踪、转向、停止和受扰恢复。交付运行入口、固定配置和完整行为/指标，不把文件加载或固定输入前向当作复现完成。

已有两份社区导出策略可作为冻结运行候选，但只有导出权重不等于已有可续训checkpoint。后续需要改actor时，应选择可训练源模型与明确的初始化路径；必要的基线训练属于另行明确预算的基线复现成本，并由所有学习组共享，不算候选免费优势。

不要无限追索原作者全部训练档案后才允许建立新评价配置。来源或模型存在差异时明确标为重新建立的Go2基准，依据实际行为核对适用范围，不冒充原论文数字复现。

### B. 在同一体系上建立完整任务，而非再做一个接接口演示

优先用连续运动、受扰、转向/通过与停稳构成任务族；保留机器人/估计器/策略历史，不在阶段间重置。第一轮先把路线或局部几何作为共同已知信息，集中研究运动执行及动作接续，不同时展开视觉建图、开放场景导航和整套感知研究。

完整任务记录成功率、失败类型、完成时间、轨迹/终态误差、身体与足端几何、输入资源以及实际规划/推理代价。困难应有物理来源，并在开发阶段依据基线与任务需求定义；留出任务在比较前固定，不能看候选结果再挑有利场景。

基线要获得合理等待、减速、转向与绕行权限。研究允许比较两者都能完成时的任务—资源取舍，不要求先证明冻结策略全局无解。

### C. 方法修改直接进入同一个Go2接口

先消除“把未实现的期望直接当事实预测”的通道，再在Go2数据与任务中组织策略学习和响应模型。具体反馈/记忆/任务信用设计由Go2上可观察的限制推动，不强迫机器人迁就二维例子的表示。

“策略诱导响应”是需要保持的因果关系，不等于必须先学出完整、精确、可微的全机器人物理模型。可以依据已有模拟器、真实执行数据或合适的控制结构建立这种关系；模型辅助信用若使用额外信息，应同样开放给对照。不能把“先得到完美F”变成新的平台准入门槛。

部署保持MPC规划、RL执行；算法与基线复用同一执行/评价链。需要什么必要信息，就先在两者都可用的条件下验证，而不是给候选隐藏特权。

## 4. 基线比较怎样安排

优先搭成一个能服务以下比较的公共体系，而不是同时完整移植所有论文：

| 比较层 | 作用 |
|---|---|
| 可信的Go2原生RL运动基线 | 提供能正常运动、转向、停止的实际反馈起点 |
| 冻结强策略＋当前响应辨识＋充分命令MPC | 判断更正确的预测与规划调用能够解释多少收益 |
| 普通任务驱动学习/共同训练＋相同预测接口 | 判断新增机制是否超过成熟训练和一般双向配合 |
| 同信息直接策略优化（PO）及适用的轨迹优化（TO） | 获得相同模型、数据、参考信息和预算，判断收益是否可由直接优化解释；明确其控制权限与在线代价 |
| 修正后的任务驱动闭环响应方法 | 检验真实反馈是否改变、模型是否可靠承接、MPC是否取得完整任务收益 |
| 适用的物理MPC/模型化控制强对照 | 诚实比较物理模型路线的任务效果和计算成本，不预设它在Go2上不行 |

物理MPC若直接控制力矩/接触力，而另一组只选择低层策略命令，应分别说明控制权限和系统成本，不能混成同控制类结论。比较目标是有效的任务系统，不是人为限制强对照。

SPlaTES、ReCo等继续提供方法级直接近邻与基线思路。但应区别“原版复现”和“在Go2上的机制适配”：SPlaTES作者项目包含Ant、Fetch任务，ReCo原任务为腿式移动操作；不能把Go2单体上接入类似模块自动称作原版复现。

## 5. 资产现状及其适当位置

截至已保存的10月17日核验，仓库取得两份真实Go2社区导出策略，核过文件、配置与固定输入输出，尚未运行Go2整机任务。参见[已有资产记录](platform-assets-independent-review-2026-10-17.md)。本轮没有重新下载、推理或刷新这些资产状态。

这说明有可继续工作的起点，不说明基线已复现，也不要求再开展一轮无边界资产审计。下一工程进展应体现为“Go2实际闭环运行与完整任务证据”，而非又一个资产清单。

HIM关于本体观测、内部响应与状态估计的工作，可用于理解Go2反馈与历史信息；其论文主张不作为本项目已有性能。[HIM原始记录](https://arxiv.org/abs/2312.11460)。[ReCo](https://arxiv.org/abs/2610.01612)与[SPlaTES](https://nicoguertler.github.io/splates-pages/)的任务身份与方法覆盖保持准确。

## 6. 当前决策与边界

- Go2作为下一阶段优先的算法研发与整机仿真载体；Piper H保留为后续跨平台验证候选，不要求同时搭两套系统，也不据此承诺最终论文必须只用Go2。
- 二维模型转为理论、诊断与实现回归工具。仅在新机制涉及必要公式或错误时回查，不继续追求其性能优势作为资格证明。
- Go2基线复现、公共任务测试与方法改造并行推进，最终以Go2完整任务与代价证据选择算法。
- 本轮是研究顺序调整，不是启动新的无上限训练或实机操作。既有固定服务器小试已结束；当前没有新训练、环境运行或自动检测。后续运行范围与预算以新的明确执行任务为准。
