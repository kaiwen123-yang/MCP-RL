## 已确认的科学问题和结构

在输入受限、存在扰动和复杂执行动态的机器人上，共同设计“对任务有用、实际能够实现、适合在线优化”的闭环动力学与反馈策略，使规划性能和真实执行性能一起提高。

- **结构：MPC规划、RL执行。** 规划预测描述当前反馈的实际响应；完整任务信用作用于真实反馈，可预测性可以共同设计。事实预测与尚未实现的响应目标分开，不能自由改变预测器来虚构任务改善。
- **首篇范围：**长程多阶段任务中的受扰执行、恢复与接续。评价完整任务成功率、时间和资源取舍，不把局部误差、非零梯度或软件流程完成替代主结果。
- **控制理论的角色：**组织可学习的反馈/响应关系，帮助学习什么、怎样学或怎样可靠预测；不预设只做安全投影或解析控制后的微小残差。
- **SPlaTES：**工程底座与方法级强对照，不限制最终数学机制；组件接入不等于完整原版复现。ReCo、普通共同学习及同信息直接方法的已知能力必须保留。
- **平台与目标：**Go2作为下一阶段优先研发与整机仿真载体，Piper H保留后续跨平台候选，不要求同时建设两套系统；T-RO是目标，不是当前可投稿性结论。NX是部署载体，不主导选题。

## 下一科学证据与剩余缺口

Go2可运行基线与完整任务测试已交付。下一研究缺口是：在相同任务/信息/计算预算下，紧凑事实模型与反馈共同设计能否比普通辨识＋充分规划、同信息PO/TO获得可解释的任务—预测—计算取舍。当前串行精确展开的计算劣势也可能由实现优化消除，不能直接归因为必须学习新反馈。维持本轮不训练边界，不按结果加难度，不回到二维胜出或资产检查作为研究门槛。

本次授权的固定服务器学习比较已经完成并结束。不得自动重复、扩训、调场景/参数或启动后续轮次；不建立自动监测。

四组结果已经否定了“本配置的新增任务度量优于均匀共同训练”的当前证据，停止这一增量主张。若后续继续方法研究，应先解释模型任务目标与真实响应的明显偏离；不能直接把训练量加大，也不能通过重开旧servo/r局部检查挽救本候选。

重审后的优先建议是：任务通过实际策略改变响应，动作条件模型与策略组合描述可实现变化，紧凑g按事实数据压缩当前响应；完整任务与可预测性的取舍仍共同设计。若显式期望响应保留，必须进入真实控制信息并满足动力学/策略一致性。仅删除原模型任务项近于已经失败的weighted_id，不能称完整改法。标准模型辅助PO获得相同模型、梯度、数据与MPC接口，是必须面对的强简单对照；新结构尚未定稿为论文算法。

当前4秒二维go/stop只是前期有限诊断载体，不是真实长程多阶段机器人任务，也不证明RL必要。各组完整成功率都低，公共warmup不是强独立策略充分训练的证明；不把此次负结果扩大成共同学习原则无效。Go2研发优先，臂侧验证保留后续。

已结案的旧servo、r例子和局部方向探针继续保留为基准，不因新代码出现就重开。当前代码仍是候选经验交替方法，不是可投稿主结果。
