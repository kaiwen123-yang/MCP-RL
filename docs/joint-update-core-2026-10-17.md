# 一轮纯功能联合更新：有效提案、完整任务接受与同信息直接方法

日期：2026-10-17。接续e4e1b68独立复审与c56bd4f交接。保留MPC规划、RL执行及狗/臂任务候选，主平台未定。本轮不训练、不采新RL batch、不写神经权重、不运行机器人环境或实机，不开启自动检测。后续真正需要训练时使用用户服务器；本轮未连接或启动服务器训练。

**结果：纯功能核心实际完成了一轮输入—需求—提案—完整重评—响应配对—下一次计划。**在既有解析任务中，固定设置生成r=0→0.1，完整时间5→4.8817418254，两符号均完成，候选被接受。硬净空违反、模型冒配和UNKNOWN分别被正确拒绝/延期。独立直接方法得到相同有限步骤；独立数值同族TO充分求解得到4.1501904，故没有独立学习或计算优势。

## 1. 本轮实现到哪一层

新增[核心源码](../src/joint_update_core.py)及[运行入口](../scripts/run_joint_update_core.py)，不再只有三个算术助手。`run_round`实际执行以下数据流：

```text
不可变旧反馈 B、输入提案锚点 P、完整案例清单
  -> 旧/锚点完整评价（保留所有状态与分母）
  -> 全量受支持需求和共享参数信用；保留全部合同
  -> 固定局部数值提案（或明确标记的外部有限候选）
  -> 有限回溯的完整任务评价
  -> 对比锚点P，并另对比旧配对B
  -> 由候选反馈重新计算配对响应/终局状态
  -> 接受该有限案例配对，或保留旧反馈
  -> 用实际激活反馈的响应产生下一次后段计划
```

本次backend是之前已经定义的解析反馈族，r不是神经actor参数、PPO动作或真实batch。输入“提案锚点”接口本轮传r=0，**没有调用PPO产生它**。响应模型更新是准确函数重算/配对，不是训练F/G。没有把此实现称为完整机器人PPO训练器；实际NN、模型校准与训练数据仍缺。

## 2. 接受目标和PPO保护怎样修正

接受对象是同一物理任务上的**确定性部署表现**。未来随机PPO提供探索及候选，其surrogate不是第二个必须逐步上升的部署目标。因此删除`g_S·d≥0`和“旧batch surrogate绝不下降”的任务质量门；继续记录S和预声明信息/有效域约束，不声称随机任务期望也改善。

这不是调大容差救反例。复用评审已有四样本数学构造，原四个非零步全部KL合格、S下降；旧门全部拒绝。新比较器按该构造原本声明的确定性目标判断四步均改善，没有改优势、奖励、KL限额或S容差。它仍只是**评审逻辑反例**，不是原PPO batch或本轮物理性能数据。

当前解析r没有Gaussian概率分布，本轮局部半径.1来自前稿设计的单位度量与delta=.005，只称解析坐标trust radius，不伪造PPO KL。主轮固定SLSQP maxiter100/ftol1e−12，回溯仅{1,.5,.25,.125}，首次候选通过，未追加步长/权重。

候选是否改善先对比输入锚点P，是否替换则另对比旧反馈B。代码保留两个版本，不能只胜过一个较差PPO提案就发布。当前B=P=0，不宣称验证了真实随机训练后不同版本的性能。

## 3. UNKNOWN、真正失败和完成成本不再混用

[完整规则](../notes/joint-update-core-2026-10-17/acceptance-semantics.md)和代码一致保留：COMPLETED、OBSERVED_TASK_FAIL、HARD_CONSTRAINT_FAIL、MODEL_UNSUPPORTED、SEARCH_UNRESOLVED、EVALUATION_TRUNCATED。

- 只有COMPLETED有完整任务成本；其余为null，另保存原因/已知prefix，不填0、∞或任意罚值。
- 所有案例和权重保留。未知时只给有限集合的已知完成比例区间与已完成交集的条件统计，不称完整平均、成功概率或置信区间。
- 任意UNKNOWN阻止整个案例集替换。已知子集可有改善，但没有已验证scope gate时共享新参数不在未知域生效。首次部分诊断后即延期，缩步长不能补缺失证据。
- 事前采用完成率优先；无未知且硬条件满足时，完成数量提高是有效路线。相同完成集合则比较固定作用域平均成本，允许个别变慢；完成数量相同但成功案例换位时保留TRADEOFF_UNRESOLVED。
- 模型配对保留已知失败标志，不要求模型把所有案例预测成功；硬失败不能被更快时间抵消。当前解析任务只有两支全完成性能路线得到实际验证，13/16→15/16仍不是本轮机器人结果。

本轮三类UNKNOWN使用**同一两案例的证据可用性干预**，不伪装成新的难任务：负冲击一例分别标模型不支持、搜索未解、评价截断。每轮总N=2、已知完成比例.5、未知.5、完整均值null。正冲击支持子集虽改善，最终仍保留r=0，未知例不返回已验证后段计划。

## 4. 任务需求必须经过策略可改变性，取消lambda压缩

当前采用全部受支持入口的

\[
h_i=J_i^T\lambda_i+g_{pre,i}+g_{suffix,i},\qquad
g=\sum_iw_i h_i.
\]

不按响应空间lambda相似性选代表。代码保留同lambda、反J的抵消，J=0也不会被非零lambda伪造成可学方向；若后段直接参数项非零仍须加回。[信用与实现范围](../notes/joint-update-core-2026-10-17/learning-signal-and-scope.md)

主轮两支参数信用均−1.25，原等权聚合仍−1.25；恢复时间已在Y中，解析后段无独立于Y的r依赖，所以此例direct项为0。这个理由不能推广到共享神经actor。

并列约束逐项回传到参数空间：同facet、同margin、逐元素相同梯度的重复行合并并保留来源；不同梯度全部保留。主轮4条合同合为2条局部行，rank=1，不再承诺所有任务都是18维。复审中的+1/−1活动梯度两行都保留，其可行方向只剩零时应据实停止。

当前选择直接全量计算作为基线/核心，没有先支付全量actor反传再宣称packet节省。小维数值子问题不代表总模型、导数或验证便宜。

## 7. 同信息强对照实际做了什么

本次新增[独立直接实现](../scripts/compare_joint_core_direct.py)，不导入联合核心、旧验证器或简化T(r)函数。它按恒加速度相位独立生成两支完整响应、检查全prefix极值/输入/门/终端，并真正运行一次SciPy bounded标量优化。

| 独立数值同族TO原返回内点 | r=.866025390689669，T=4.150190411909861，37次目标评价 | 真正数值求解结果，不是直接抄解析边界 |
| 另计两端点后的闭区间最优 | r=.8660254037844386，T=4.15019039690625 | 支持旧解析同解；充分预算超过单个局部步骤 |

**没有独立方法增量。**同信息标准直接方法完全解释有限步骤和同族最优收益。充分求解不是同墙钟竞争；一般时变自由控制TO类更宽，本次未解其全局最优。若真实固定策略本就允许通过宏命令调节分配，强基线必须得到这项权限，本例也可能只说明更好调用已有能力。

## 8. 实际预算、缺口与服务器训练边界

[完整结果](../notes/joint-update-core-2026-10-17/round-results.json)及[累计账本](../notes/joint-update-core-2026-10-17/execution-ledger.json)保留每次提案/拒绝。最终主轮为6个案例级函数评价、18个恒加速度闭式相位映射、2个需求回传、1次局部QP、1个有限候选；其中模型配对重算单列。`completed_path_evaluations`指完整相位评价，含硬失败，不是成功次数。

核心首版与修订后共72个案例级返回、153个相位映射、8次解析坐标QP；首版未计QP约束回调，新增回调字段只给已记录下界，不能假装累计精确。独立TO及固定坐标核验另40次双支任务评价、240个相位映射、1次数值TO。还有复审已有记录的信用/比较算术，未生成新动力学案例。局部QP与数值TO都是明确的解析坐标优化，**不是RL训练器或神经权重更新**。

当前真正剩余的研究缺口是：在真实执行动态、接触、载荷和观测条件下，用有限数据/总计算得到可接受的共享神经反馈变化，并保持MPC预测与它一致。只有真实冻结策略配准确模型/充分规划后仍有任务—资源取舍空间，且直接同信息方法未以同等成本解释全部收益，才值得争取独立学习/计算贡献。增加packet、约束、模型刷新或平台数量本身不解决这个缺口。

目前没有所定义狗/臂任务的已核checkpoint、配套可微执行模型、真实随机PPO batch或确定性验证数据。此解析问题已经由标准控制解决，**不能以本轮结果作为启动训练的充分理由**。后续若真实任务确需学习，训练只在用户服务器进行；先确认GPU与可用显存、CPU/内存、仿真/驱动兼容及数据盘，再用固定策略推理/模型计算测出单批显存、吞吐和总预算，不能从一维解析核算推GPU小时。本轮未连接服务器、未启动训练/租卡、未操作实机或自动检测。
