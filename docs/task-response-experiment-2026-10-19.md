## 1. 这轮要判断什么

核心假设是：把同一个紧凑闭环响应模型同时用作 MPC 预测和 actor 可实现的响应目标，允许后段任务改变这一目标，并保持真实执行数据的匹配约束，能否在固定模型容量和可执行预算内改善完整任务表现。

最强替代解释有三个：普通任务 PPO 与监督辨识已经足够；收益只是普通双向共同训练；收益只是额外响应正则压低方差而非任务驱动响应目标。比较必须允许这些解释胜出。

本轮六状态平面执行器系统用于检验算法代码和学习机制。它有输入竞争、执行器记忆和后段要求，但不是 Go2/Piper 模型，也不是证明 RL 必不可少的对象；结果不直接外推到真实长程机器人任务。理论解释和网络/规划器无训练前向通过，也不能替代本协议的实际训练结果。

## 2. 当前任务与共同信息

代码来源为[环境](../src/task_response/environment.py)和[规划器](../src/task_response/planner.py)。任务常数必须从固定提交的配置导出，以下为撰写时默认值；若代码修订，先同步本表，再开始正式轮次。

| 项目 | 当前定义 |
|---|---|
| 状态 | `x=[p_x,p_y,v_x,v_y,a_x,a_y]`；全部组可见，同一执行器状态持续推进 |
| 物理推进 | 离散 Euler；`dt=0.05 s`；执行器时间常数 `tau=0.18 s`；速度与交叉阻力 |
| 动作 | 二维请求经同一共享二范数球限幅，半径 `1.5`；限幅是共同物理输入限制，不是替 actor 完成控制的解析反馈 |
| 单次完整任务 | `80` 低层步，`4 s`；每 `4` 低层步更新一次高层命令 |
| 共同初态 | 基础值 `[0,0,0.45,±0.35,0,0]`；纵向速度另加固定seed产生的 `[-0.05,0.05]` 扰动；两种侧向偏差符号分别评价 |
| go 后段 | 到达位置 `(2,0)`，目标速度 `(0.6,0)` |
| stop 后段 | 同一目标位置，目标速度 `(0,0)` |
| 任务上下文 | 目标位置、目标速度、通道半宽、剩余时间；actor、critic、响应模型和比较组使用相同上下文 |
| 几何 | 点体直通道，半宽 `0.65`；规划成本为软越界惩罚，评价另报实际采样越界 |
| 成功 | 完成整个任务时域，终点位置误差≤`0.15`、速度误差≤`0.18`，且全程采样点未越界 |

go/stop 的区别是完整有限时域内的不同终态运动要求，不是两个独立机器人平台，也不等于已经实现转弯、全身过门、抓取释放或任意长程阶段接续。瞬时曾达到目标另报首次到达时间，不能替代终点成功。

`CompactResponse` 在每次规划入口把实际六维状态编码为 `z=[p_x,p_y,v_x,v_y,m_1,m_2]`，随后只推进潜状态。`m` 是学得的响应记忆，不等同于实际执行器状态 `a`。各组共享已知运动学结构、固定归一化、模型容量和编码输入；模型输出的两维平衡量不是实际 actor 动作。不能把模型的结构/数值范围当作每条真实轨迹的输入可实现性证书。

未来扰动不进入观测、响应模型输入或规划器；实际状态可以反映已经发生的扰动。评价的扰动时刻、大小和随机种子必须在训练前固定，并向所有方法一致提供实际扰动序列。当前任务与初态不得在看到某组失败后改成偏向候选的场景。

当前[采样器](../src/task_response/collection.py)把8环境分为4个 go 和4个 stop，二者逐一共用同样的初态和扰动。外部扰动为横向加速度：在零基第40、41拍施加同一 `[-0.25,0.25]` 内的seed确定幅值，其余时刻为零。训练与评价使用相同声明分布、不同seed；它检验未见随机样本，不冒称分布外鲁棒性。

## 3. 比较矩阵与因果问题

所有学习组使用相同 actor/critic/模型结构和初始权重、训练 seeds `11/23/37`、PPO 超参数、交互预算、命令约束及评价集合。模型训练的步数与 batch 上限共同固定；额外任务求导和敏感度计算单独计账。种子以本轮冻结的[配置](../configs/task_response_pilot.json)为准，尚未依据任何学习结果选择。

| 组 | actor | 响应模型 | 主要对比 |
|---|---|---|---|
| `ordinary`：任务 PPO＋监督辨识 | 真实任务 reward | 当前 actor 的数据拟合 | 基础任务学习与更好预测是否已够用 |
| `uniform`：普通共同训练 `W=I` | 真实任务＋响应匹配 | 与候选相同的数据匹配及任务目标项 | 区分普通共同训练与任务敏感度的作用 |
| `codesign`：任务敏感共同训练 | 真实任务＋固定本批 `W` 的响应匹配 | 数据匹配＋任务代价梯度 | 完整候选 |
| `weighted_id`：监督目标的匹配拆解 | 与候选相同的任务敏感匹配 | 只做监督辨识 | 区分任务驱动 `g` 目标与响应正则的作用 |

本轮计划实际比较全部四组。`frozen` 仅可作为共享 warmup 后冻结 actor 的可选诊断，不属于上述四组主比较，也不能据此给学习方法制造弱基线。本轮不得将未完成的原版 SPlaTES、ReCo、TaskMet 复现列为已经运行的基线；这里是机制对照。

同目标 standard PO 不是另造一组弱算法：冻结同批 `g/W` 后，候选 actor 对合成奖励做 PPO，与相同目标、相同数据及相同优化配置的普通 PPO 等价。若这一等价已在实现中成立，应直接披露，而不设计可视化“胜出”。

对每个已训练检查点，额外以**相同学得响应模型**比较 CEM 命令规划与多初值梯度 command-TO。它们都只改高层命令，不改 actor；只能判断已有反馈调用/规划因素。允许改变策略参数的同信息 PO 与 command-TO 是不同权限，不能混称。

## 4. 目标、数据和模型版本

- 正式训练前固定输入/响应归一化和 `W` 构造及尺度。对归一化五维响应的后段敏感度 `v`，使用 `A=I+alpha*vv^T/(1+||v||^2)`、`W=5A/tr(A)`，`alpha=4`。因此 `tr(W)=5=tr(I)`，保留正定 identity 底座，避免候选只是整体匹配罚强度更大。`W` 随本批数据冻结；相同trace仍不保证各方向、各状态或实际梯度范数相同，这正是待检验的度量选择。
- PPO 的 old log-prob、GAE、任务上下文、命令序列、响应目标及 `W` 随采样 batch 保存为同一版本；PPO 数据复用期间不改奖励定义或用新模型重算旧优势。
- 模型的任务代价项必须与真实任务定义保持一致；通过短规划或末命令延拓得到的导数只是声明的代理目标导数，不能称为完整持续重规划的精确梯度。
- 训练 transition、监督训练/留出划分、完整评价 episode 分开。不得把同轨迹相邻样本随机拆开后，将其称为跨 episode 的独立泛化验证。
- 评价阶段冻结 actor 和响应模型，关闭探索噪声，按确定性部署均值执行；如报告随机策略结果，另列其定义和种子。模型不随评价轨迹更新。
- 模型输出的资源值是预测量。执行输入和真实资源积分由物理推进计算；预测资源偏小不能等同于实际省输入。

## 5. 主要指标与结果裁决

**完整任务结果为主：**分别报告 go/stop、正/负侧向偏差和每个训练 seed 的终点成功、任务成本、真实归一化输入积分、最大通道超量、终点位置/速度误差。不得只报成功样本的平均代价而隐藏失败；成本定义对已完成整个时域的失败轨迹仍有效，成功与成本同时展示。

首次达到目标时间是辅助指标；只命中一次而末态失败不能列为成功。评价未完成时标记 `EVALUATION_TRUNCATED`，不把短轨迹成本混入完整任务均值。

**机制证据：**用相同评价条件观察实际响应均值、响应方差、紧凑模型预测误差、任务敏感误差和下一次 MPC 命令变化。响应误差下降而完整任务不改善，不算主假设通过；模型预测更乐观而真实状态不变，也不算能力改善。不同任务/状态混合后的方差不能当作条件响应方差。

**成本证据：**记录物理交互、PPO minibatch 更新、模型拟合更新、任务反向计算、`W` 计算、MPC 求解、模型 forward/reverse 步、实际墙钟、GPU/CPU占用与峰值显存。相同环境步不代表总计算相同；候选使用额外计算时，报告原始对比及任务质量—成本关系，不直接写“同预算更优”。

三训练种子用于早期趋势与失败模式判断。报告全部原始种子值、均值和离散程度；不以三种子给出稳定总体优势或机器人泛化结论。不按评价结果选种子、选检查点或改任务。正式比较采用预先指定的末轮 checkpoint；中间评估只描述学习过程。

继续条件：候选在完整任务上相对普通共同训练出现可重复、可归因的改善，同时预测可用性和成本没有抵消收益。停止或修改候选的条件：普通共同训练解释全部表现；响应目标只在模型中改善；正则使策略更保守但任务更差；比较依赖额外信息或未计成本。一次小试无正结果只否定该配置或机制证据，不扩写为共同学习原则失败。

## 6. 已冻结的小规模预算与规划计算

本轮训练 seeds 固定为 `11/23/37`，每批8个并行环境，各推进完整80步，因此每批640个物理转移。每轮有三批互不替代的新交互：A 以当前 actor 的确定性部署均值采集模型提案数据；B 在新模型冻结后以随机探索策略采集 PPO 数据；C 以新 actor 的确定性均值重新采集并校准预测模型。A/C 的模型对象是实际确定性部署反馈，不把随机动作的平均闭环当作确定性闭环。**每轮交互是 `3*8*80=1,920`，不是只计算 PPO 的640步。**

| 部分 | 每个seed | 三seed合计 |
|---|---:|---:|
| 公共 ordinary warmup，8轮 | `8*1,920=15,360` | `46,080` |
| 每个正式arm，16轮 | `16*1,920=30,720` | `92,160` |
| 四正式arm | `122,880` | `368,640` |
| 共享warmup＋全部主比较 | `138,240` | **`414,720`** |

同一 seed 的四组从同一公共 warmup 权重与状态分支，不给候选额外预训练。共享 warmup 在项目实际总成本中只计一次；报告单个方法从头训练成本时，每组都应包含对应 warmup 成本，不把共同准备当免费数据。开发、评估和失败重试单列。

PPO每轮仅使用B批：640样本，4 epochs，minibatch参数256。上游 Tianshou 0.5.1 的 `Batch.split(..., merge_last=True)` 把末尾不足批合并，因此每个epoch是2个batch，**每轮8次优化器更新**，不能按 `ceil(640/256)` 算成12次。每轮模型提案4次、校准4次，共8次模型优化。正式16轮即每个arm/seed 128次PPO与128次模型优化；公共8轮为64次PPO与64次模型优化。全部计划分别为1728次PPO与1728次模型优化；实际因预算截断减少的次数以日志为准。

小试配置把 CEM 设为 `H=5` 宏步、每宏步4微步、24候选、6 elites、2轮，另评价最终均值。以下是该小试配置的每次、每个环境名义工作量；不同于规划模块较大的类默认值：

| 求解器 | 轨迹评价/编码次数 | 前向模型微步 | 反向等效微步 |
|---|---:|---:|---:|
| CEM | `2*24+1=49` | `49*5*4=980` | `0` |
| command-TO，若保持4初值、12梯度步 | `(12+1)*4=52` | `52*5*4=1,040` | `12*4*5*4=960` |

这些是调用计数，反向成本不能按与前向相等处理，也不是墙钟结论。两求解器没有相同总计算预算；它们是固定、可报告预算的规划比较。80步完整任务最多20次高层重规划。若全部三批均按CEM在线重规划，`414,720/4=103,680` 次环境级命令规划对应 **`101,606,400` 个前向模型微步**，另计编码、模型训练、任务/W求导与评价。`plan` 的账本负责按最终配置核对，不能只报交互步数。

评价在正式分支的开始、第8轮、第16轮进行；“after”与第16轮是同一检查点，只计一次。每次8环境×80步，固定评价 seed `91001`，与训练数据seed生成域不相交。`3 seeds*4 arms*3 checkpoints=36` 个评价batch，共 **23,040** 个评价物理步；训练和计划内评价合计 **437,760** 步。这8个评价条件在训练种子之间复用，不是每个训练种子新增8个独立场景，也不支持广泛扰动分布覆盖结论。默认没有额外公共warmup评价；可选command-TO评价另计。

当前 `plan` 账本列出：评价规划5,644,800个前向模型微步，响应目标437,760步，模型拟合2,211,840步，敏感度计算1,935,360步；加训练规划后合计 **111,836,160** 个前向模型微步。拟合与敏感度的反向等效步分别为2,211,840与1,935,360。该账本不把编码器、神经网络大小、GPU同步或反向开销化成同价FLOPs，也不是运行速度测量。

每个arm/seed设1800秒墙钟上限（包含其评价），每个seed的共享warmup另设1800秒上限。这是执行预算而非预计完成时长。runner在阶段边界检查，因此最多继续到当前阶段结束，并报告实际超时；不是操作系统硬实时终止。未完成记为预算截断，保留权重、配对阶段与已耗成本，不写成完整16轮结果；warmup未完成则对应seed所有正式组不启动。上限触发的组不能与其他完整组一起宣称等训练步比较。预算不足时先把全部组共同预算等比例缩小，不只提前停基线或只延长候选。

现有项目资料记录的候选资源为单 RTX 5080、双 RTX PRO 6000 Blackwell 96GB，另有用户提过的租卡选项。本轮只读本机服务器连接配置，确认已有别名配置存在；**没有验证远端可达、空闲卡、驱动、PyTorch、磁盘或运行吞吐**。不将过往硬件讨论当作本次可用资源证明，公开文件不写私人用户、IP 或本机身份路径。

本轮准备针对单卡执行，多个 seed/组默认顺序运行；双卡优先分配独立 seed，而不是假定自定义模型与 PPO 已支持 DDP。后续训练启用时先核现有环境和空闲资源，在独立项目目录/虚拟环境保存结果；不升级全局软件、不改 SSH 路由、不干扰别人的训练和编辑会话。

在没有远端计时前只给步骤预算，不给训练小时数或 NX 时延。训练日志应保留固定 Git commit、完整配置、依赖版本、设备信息、随机种子、初末权重摘要与进程退出状态。运行失败与重试额外成本保留；未完成不能写成成功。

## 8. Runner入口与执行状态

入口约定为 `scripts/task_response.py`，配置为 `configs/task_response_pilot.json`。从仓库根目录运行：

```bash
python scripts/task_response.py plan --config configs/task_response_pilot.json --output work/task-response-server-pilot
python scripts/task_response.py check --config configs/task_response_pilot.json --output work/task-response-no-train-check
```

`plan`只输出预算与配置，不训练。`check`用于有限固定输入/导数/接口核查，输出应明确模型是否未训练、实际调用预算及是否发生优化器更新；通过不能写成学习有效。

后续用户允许开始服务器小试后，执行训练与冻结评价入口：

```bash
python scripts/task_response.py train --config configs/task_response_pilot.json --device cuda:0 --output work/task-response-server-pilot
python scripts/task_response.py evaluate --config configs/task_response_pilot.json --device cuda:0 --checkpoint work/task-response-server-pilot/seed-11/codesign/checkpoint.pt --planner to --output work/task-response-eval-to-seed11
```

`cuda:0` 是未来单卡运行的设备选择，先核远端兼容性和空闲情况。train允许同输出目录已有 `plan.json`，但不覆盖已有训练结果；重新运行应改为新目录。evaluate必须显式传实际存在的checkpoint，上例对seed11的codesign做额外command-TO评价；其数据与成本不包含在默认437,760步计划中。其他组/seed对应替换路径；`--planner cem`可复查相同检查点的CEM结果。不能把一次无权重前向替代检查点评价。

本轮已读取runner源码、配置和生成的计划JSON核对上述入口及算术；没有执行训练，也没有验证其训练分支实际完成、服务器吞吐或有效性。
