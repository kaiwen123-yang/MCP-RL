所有秒数指**仿真物理时间**，不是墙钟。每一级都是独立预声明任务，从该case相同的独立初始机器人/材料状态开始；同一任务内部的腿、圈、控制更新、文件分片绝不重置历史。

| 级别 | 任务与通过条件 | 可支持的结论 |
|---|---|---|
| E30 | 初始站立2秒后沿原路线实际加载并通过材料条带，按原到达判据到达3m远端；继续原转向/返程逻辑，完整观察至30秒，期间无原物理/材料失效。记录转向/返程时刻和实际进度。 | 去程材料接触与短时执行成立；不是原完整任务成功。 |
| E60 | 原完整0→3→0任务、真实转向、原点原阈值连续稳定2秒，观察至60秒。远端不新增停稳，原截止与阈值保持。 | 首个完整材料往返与停稳成立。 |
| E300 | 独立300秒连续任务，5次整往返须在270秒内完成；两端按原阈值稳定2秒并真实转向。完成后保持到300秒，满足最终连续2秒稳定。 | 重复踩踏/跨足/返程中的中等时长执行可靠性。 |
| E600 | 独立600秒连续任务，10次整往返须在540秒内完成；端点、转向、连续历史及最终保持规则同E300。 | 更长时长执行可靠性，仍不自动证明长期记忆收益。 |

E30不能只站30秒，也不把路线缩短以避开材料。没有新增“30秒必须完成整往返/完成转向”的期限：[R8原Go2完整任务](../results/terrain_memory/simulation/tm-s1-go2-wb-support-r8/index.json)历史上多需36–44秒，强塞到30秒会改变问题。达到远端后继续原路线，不人为停等。真实软材料加载证据与转向/返程进度均保留；不靠绕开条带制造材料资格。

### 5.2 准入绑定同一个case

case身份包括实际控制器/影响轨迹的配置与二进制、FIXED cap或冻结策略checkpoint/normalizer、训练seed、nominal/yaw±5°初态、初始物理/材料状态和本协议版本。共同case身份不直接使用包含全部任务参数的resolved-config hash：本协议预定的时长、short/original/continuous类型、圈数、路线期限及保持语义另记为stage identity，不因规定级差异使前级资格失效。每级完整实际配置与hash仍分别保留；其他影响轨迹的参数变化须重新建立资格。严格执行**E30→E60→E300→E600**：

- 每个case以自己的前一级通过记录进入后一级。nominal不能代替yaw，seed0不能代替seed1/2，RAW不能代替PANN；不设全组必须一起通过的障碍。
- 前一级失败或未执行，只阻塞该case下一级，其余具资格case继续。区分物理/材料失败、任务进度或保持未达标、预算截断、技术中断与未获资格。
- 影响轨迹的源码/配置、权重或normalizer变化后重新建立资格；纯文档/发布变更不要求重跑。改版保留全部原结果，不能混版挑最好表现。
- 同协议、同身份且预声明的开发资格记录可复用一次，标明来源、不重复计数。600秒的前300秒或R10 dev11前30秒不能事后追认为本轮独立评价；训练轨迹不能借作正式资格。
- 所有正式评价冻结Actor/归一化、不做PPO更新；因果PANN状态与MPC仍正常更新。运动中的终点稳定阈值不被错误用作全程静止要求。

### 5.3 清单、优先级与结果解释

全目标为**21个case×4级＝84条材料阶段记录＋1条名义刚地60秒回归**；资格复用减少实际新启动，但不改变清单。21个case＝FIXED三个初态＋RAW/PANN各三个训练seed×三个初态。此数量是预定覆盖范围，不恢复物理启动次数硬上限。

| 优先顺序 | 任务 | 约束 |
|---|---|---|
| P0 | 同版nominal E30→E60，冻结S5；一条刚地60回归 | 先短阶段，再原完整任务 |
| P1 | 固定nominal E300→E600；允许与六流训练重叠 | 自身前级通过，不等学习组或其他初态 |
| P2 | 六流均衡训练并冻结共同主checkpoint；预定RAW/PANN seed0 nominal各自E30→E60→E300→E600 | 两组独立准入，不挑最好seed，不等其他case全过 |
| P3 | 其余预声明case的未执行梯级 | 固定顺序：FIXED yaw+5/yaw−5；随后按seed0剩余yaw、seed1/2各nominal/yaw+5/yaw−5，将每个seed/初态的RAW与PANN成对安排。各自按资格逐级，可并发，不要求对方通过。 |
| P4 | 固定及两学习seed0的nominal1800→3600秒 | 自身600→1800通过、具资格四级核心全部执行且预算足；不抢占四级核心 |

1800/3600仍分别30/60往返、路线期限1620/3240秒，属于四级之后的条件扩展。所有长任务报告每圈、每60秒、末30秒、移动/保持时间与全部超限，达到圈数后保持到规定时长；视频/数组分片不产生新任务。预算截止记budget_truncated，不能拼接成功或计为材料失败。

每级报告预定21、具资格、实际执行、通过、物理/材料失败、任务未达标、技术/预算截断、资格阻塞和预算未执行；给出每case最高通过级别及前级记录ID。报告已执行条件成功率时同时给21个预定case的晋级覆盖，避免只统计长级幸存者造成误导。一次5/10往返不是5/10个独立样本。

“核心完成”指所有具资格的预声明四级case均有完整有效通过或明确真实物理/材料/任务判据失败，其余因前级资格不足明确列出；预算遗漏的具资格case仍是缺项。技术中断或budget_truncated只算启动/部分执行，未解决的截断不能算核心完成、不能解锁后级或可选扩展；剩余预算不足时如实保留缺项，不要求无预算重跑。不能把“清单已全部处置”称为“84条全部执行或通过”，某组失败不取消其他组可行工作。部分nominal阶梯不替代全21个case结论。

## 6. 阶梯节约失败分支成本，但不保证48小时全量完成

dev11 32.5672秒物理耗时1949.4273秒，约59.8586倍慢仿真。其中规划1371.134秒（70.34%），材料402.979秒（20.67%，包含在physics内，不重复相加）；规划p50约838.95ms，1631次逻辑20ms期限全部超期。这是短记录，不能当实测长时吞吐。

仅在假设同等成本下作情景外推：
- 单30/60/300/600秒分别约0.50/1.00/4.99/9.98墙钟小时；一个case完整四级串行约16.46小时，独立环境并发不能消除自身准入依赖。
- 四级清单与刚地共60＋21×(30＋60＋300＋600)＝20850物理秒，比上一版多6930秒。前级失败会取消该case后级启动，这正是阶梯节约成本的位置。
- 六流各32768个完整.5秒转移仍需98304物理秒，加评价为119154秒。假设六环境均保留dev11速度且完全无资源竞争，总约330.20小时；48小时全达需要聚合.68955物理秒/墙钟秒，尚未证实。
- 理想六并发下单评价也约57.78小时，实际门禁与CPU竞争还会延长；材料状态增长、观察器和不同策略成本均可能改变外推。早失败和短末转移可能减量，因此这些不是实际时间承诺。

因此以**实际达到的级别与真实学习量**交付，不因大样本未满拒绝已具资格的阶段评价，也不为跑600秒跳过30/60/300。

资源保持已授权RTX PRO6000 96GB、Xeon8470Q、25vCPU、120GiB RAM（约128.85GB）及SSH/tmux。六训练流初始每环境2 solver workers；评价并发按实际吞吐与余量增加，8是候选而非最低。208核affinity不等于CPU配额，不将8workers机械复制到每流；统筹BLAS/OpenMP/JAX/PyTorch，按聚合有效物理秒/转移吞吐安排，不以GPU占用率作成果。

允许减少重复RPC/FK/无用写盘、批量材料计算和复用常量/编译实例等语义不变提速；不改真实积分、.2ms物理/材料步长、2ms保持、不跳无载恢复、不换快plant。候选导数近似须由已有窗口与完整阶段任务证据支持，不额外开benchmark或测试矩阵，也不为调并发打断活跃任务。

预留至少max(6小时,拟保护评价的实际预计剩余调度成本×1.2)。**成本必须包含P1/P2预声明nominal整梯尚未解锁的后级依赖链**，不能因当前未具资格就记成零；前级失败后才释放对应后级预留。其余拟执行P3一并估计，避免重复计入复用的资格。若整清单或P1/P2仍不可达，按既定优先级和同组公平样本规则保留真实完成量与缺项，不使一个不可能的全矩阵预留取消全部学习，也不承诺所有名义600秒可达。

32768仍是目标，65536/1800/3600仅在具资格核心已执行且预计能在剩余授权时间内完成时启动。48小时从首次真实R11积分统一起钟，包含暂停和后续工作，不能重起或自动延时。到点保存实际checkpoint、任务截断和未执行清单。
