### 3.2 下一步优先检验承载交接

当前 C 是基于少量当前世界足印锚点的局部瞬时接触近似，尚不传播完整材料 q/e 或世界材料记忆。PANN 作为 Actor 的额外观测，并没有自动进入 iLQG 候选动力学。

已有记录包含名义 stance 足悬空、候选轨迹自身身体下降、真实全无支撑间隔，以及真实落足速度偏离参考。r20/dev22 曾出现约 93 ms 全无支撑和约 1745 N 总法向力峰值。因此下一次失败窗口必须区分：

1. **预测本身就丢支撑，却被优化器选中**：处理相容的承载目标、支撑交接与可实现性。
2. **预测支撑充分，但实际卸载/落足与其分离**：处理局部接触近似、执行反馈与离散时序的具体误差。

不要把两种情况都归结为“高度权重再调大一点”。已经关闭的 moving body-twist 分支，不继续无依据扫描权重。短时 relaxation/rate 离线拟合在部分重触地窗口反而更差，例如 .05/.1 秒 RMSE 由约 12.61/15.50 N 增至 28.64/28.66 N；不能当作已验证修复自动叠加。

## 4. 为什么先用 5080，以及本地还缺什么

最新 r21 的 14.358 秒物理消耗约 832.269 秒墙钟。普通 planning 占 657.629 秒、约 79.0%；其 p50≈923.591 ms，718 次均超过 20 ms 逻辑周期。physics 约 128.254 秒，其中材料约 94.099 秒，二者不能重复相加。startup planning 另约 19.333 秒。

PPO 当前代码明确运行 CPU，网络为 64×64、658 维观测；大显存不是这部分的主要需求。PANN 是冻结模型的状态推进与查询，GPU 可服务该部分，但 R11 没有在线 PANN 闭环的实测吞吐。云主机的一次真实任务 CPU 计数约为平均 9.759 核，不能把 20 workers、25 vCPU 或 208 核 affinity 直接当成实际吞吐。

本地资源尚须读取，不假定 5080 一定比原租机快，也不把显示 GPU 型号当作核数或可用内存证据。R12 按实际 CPU 配额、内存、驱动和已有环境选择初始 worker 数，默认考虑 4、资源不足用 2；选择后锁定。**最终固定 E30/E60、刚地回归和最终 pilot 使用同一实际 controller/execution identity 与 worker 数**；pilot 并发不足则顺序执行，不通过偷偷改 worker 数混用资格。

### 5.1 三个源码级问题必须先定点修正

1. [policy 同步](../scripts/s1_go2_r11_policy.py)写死 RAW/PANN×3 seeds，会在仅两流甚至单流时等待不存在的进度。R12 pilot 所有启动和恢复路径均关闭此等待，不制造 dummy progress；未来六流正式训练另用显式 cohort 的均衡策略。
2. 当前先 collect_pending/update 再判断样本目标，会让第 512 条在更新时尚未标外部截断。**必须在该条入 buffer/GAE/update 之前确定**总样本预算截断，使用真实末观测；若同时物理失败，terminated 优先。不补造第 513 条或零时长样本。
3. collection.json 在 update 前写，最终可能与 checkpoint 的更新数/尾 buffer 不一致。更新后、恢复后和退出时刷新权威计数，明确 collected、updated、tail、唯一 serial、恢复代次及退出原因；旧 stopped 文件不能覆盖新恢复结果。

这是必要运行逻辑修复，不要求另建测试框架。真实 pilot 的转移、更新日志与恢复过程就是验收证据。

### 5.2 保存和恢复必须实际发生

每流按以下流程执行：采样到第一次 256 更新 → 继续当前真实会话 → 最近自然物理终止或 60 秒会话边界 → 保存 resume-state 并退出进程 → 新进程恢复 → 累计到第 512 条完成第二次更新。

普通 256 更新和圈切换不 reset。第一次 update 到自然边界之间的尾 buffer 必须保留，包含实际用于行为策略的观测/归一化、raw action、old log_prob、reward、value/next_value、真实末观测、terminated/truncated 及序号；对应 Actor/Critic、optimizer、RNG、归一化、计数和 episode ID 一并保存。

无失败时的示例：

| 时点 | 累计转移 | 已完成更新 | 未更新尾 buffer |
|---|---:|---:|---:|
| 两个 60 秒会话结束 | 240 | 0 | 240 |
| 第三个会话约第 8 秒 | 256 | 1 | 0 |
| 第三个会话结束、保存退出 | 360 | 1 | 104 |
| 恢复后再采 152 条 | 512 | 2 | 0 |

恢复后按目标差额采样，不再固定加 256。正常边界恢复标 planned_boundary_resume，不能虚报为新的物理失败；新会话从独立初态开始，不声称物理/材料/观察器/MPC 的连续状态已无缝恢复。

终止与截断：真实物理/材料失败 terminal，不 bootstrap；60 秒采集边界及第 512 条外部预算截断，用 reset 前真实末观测 bootstrap，切断跨 reset GAE；普通 rollout 边界保留活跃环境。所有外部采集/样本预算截断均不额外产生失败、超时或完成奖励；同条真实失败仍保留原失败惩罚，真实整圈完成仍按原事件计一次。若意外中断且缺乏真实末观测，保留缺项，不伪造 successor 或完整样本。

每次真实更新分别记录 Actor 与 Critic 的参数变化、optimizer 更新计数及行为策略身份；不能只凭 Critic 改变就称策略学习链成立，Actor 更新未得到证实时该项仍为未验证。第一次实际更新后的 Actor 须生成后续样本；第 512 条第二次更新结束后保存权重、核对参数变化及重载在已保存观测上的输出一致，**不额外要求最终 Actor 又驱动一段物理来暗增训练样本**。每流报告真实有效平移转移、初始化/站立阶段样本、reset 数和物理时间，不能靠不移动凑 512。

### P2：用单一支撑交接假说推进合格执行器

先复用已留存的 r20/r21 失效窗口，定位最早预测/实际承载分离。若证据仍支持当前接触交接方向，下一候选为：

- cadence 保持 2 Hz、.35 秒预测时域。
- duty 从 .45 改 .55；在标准对角相位下，25 ms 名义飞行间隔变为 25 ms 名义支撑重叠，下一对角事件仍为 .25 秒。
- 原 swing .275 秒变为 .225 秒；两段 quintic 的高度及时间同时乘 9/11：
  - clearance：5 mm → 4.090909 mm；
  - rise：.075 s → .061363636 s；
  - descent：.200 s → .163636364 s。
- 参考上升/下降峰速仍为 .125/.046875 m/s；净空下降约 18.18%，参考加速度尺度提高约 22.22%。这些都是候选变化，不能宣称只改 duty、其余运动学量不变，或已保证减小真实冲击。

必须同时改 profile，不能只改 duty 后保留 .20 秒下降段；旧公式在 2 Hz、duty≥.60 时上升时间会变为非正。保留静态 C、已修数值逻辑及当前其他权重，避免同时叠加 relaxation、频率整形与新机身权重而失去因果辨识。

这是一项**预声明且可否证的机制假说**，不是保证通过的参数。记录实际而非仅名义的承重重叠、全无支撑区间、四足 Fz/足速、机身姿态/加速度、饱和、材料贯穿与对应计划。如果已有/新证据反驳该方向，明确给出最早失配，再选择一项有证据的修正；不继续扫 duty×height×weights 网格。

### P3：冻结最终执行器，完成本地就绪证据

最终同实际身份的固定 cap 候选通过 E30→E60 后冻结；只做一条名义刚地 60 秒回归。最终版本必须拥有自身两流工程 pilot 和实际恢复证据。早期 pilot 与最终候选不同则独立记录，不能把失败版样本转作合格版结果。

固定 nominal E300 可在必做项已满足且预算允许时继续；其失败应报告，但**E300/E600 不是开始 PPO 或准备云训练的先决条件**。本地不自动扩成 84 条矩阵。

## 8. 时间、并发、停止与上云条件

### 8.1 本地预算

新 R12 首批本地窗口为 **48 小时**，自首个 R12 真实物理积分起算；之后的暂停、构建、修复、采集与评价均使用同一截止。前置迁移和最终上传单列耗时。明确的用户停止优先；不能新建子 run 刷新预算或自动续时。

继续取消 12/61 次启动硬限制。每最多 6 次有物理积分的开发任务形成证据批，所有早停、崩溃、丢记录都计入实际启动；零步失败单列但占时间。仅当连续两批**既无相关改善、又无新的可检验机制**时停止当前分支，不据此全局停止所有工作。相同确定性失败无新依据不重跑。

优先顺序为迁移/有效交互 → 首个真实 pilot → 有根据的控制改进 → 同版 E30/E60/刚地与最终 pilot → 资源/云准备 → 可选固定 E300。不能继续耗完整个窗口做变体而始终不触发已经具备准入条件的 pilot。按真实剩余工作成本预留必做项，目标超过预算则交部分结果，不编造完成。

不再保留一个会压住工程 pilot 的“24 小时控制开发后才许训练”阶段。无需等六流/全部初态，不做独立 benchmark、单元/mock/冒烟/导入/形状测试或无关刚地矩阵。

### 8.2 真实成本与资源

在正常开发和 pilot 中记录：实际物理秒/墙钟、每流真实与有效转移、startup、MPC/导数、反馈/RPC、truth/material、PANN 观察/查询/编译、PPO update、CPU、RAM、VRAM峰值及并发配置。嵌套组件不重复相加，编译/初始化单列。不通过降低真值频率或用未授权快速环境提高表面吞吐。

每个候选 cohort 两流各 512 条，若每条满 .5 秒，一套采样物理约 512 秒；在 r21 单固定任务约 57.97 倍慢仿真的假设下，相当于约 8.24 小时串行任务墙钟。若早期与最终版需要独立两套，则同一情景约 16.49 小时，不能只按一套预留交付时间。两种外推均尚未计入在线 PANN、不同硬件/并发和额外恢复成本；早期失败缩短转移但增加 reset，不能当本地承诺。

正式六流各 32768 条满 .5 秒需要 98304 秒物理（约 27.31 小时），还不含评价。应按测得的聚合吞吐计算训练与阶梯评价时长，并预留约 20% 波动，不用“换更大 GPU”替代成本推算。

### 8.3 AutoDL 准备清单与触发

只有以下条件都真实具备，才记 `ready_for_cloud_training`：

1. 本地可复现的源码/依赖/资产/二进制清单及可迁移入口，无 AutoDL 绝对路径依赖。
2. 最终相同执行身份的固定 nominal 材料 E30→E60 合格，一条原 nominal 刚地 60 秒回归合格。
3. 同一最终身份的 RAW/PANN seed0 pilot 各 512/两次 update、实际保存退出/恢复成功，真实计数和信息边界成立。
4. 完整的组件耗时、内存/显存、真实串行或双环境吞吐证据，以及建议云 CPU/内存/GPU/并发和训练/评价成本。

这只是**可迁移与投入准备**，不等于已经在云端运行、已收敛或 PANN 有优势。若候选通过固定任务但学到的 512 Actor 尚未通过 E60，不据此禁止后续学习；512 Actor 的任务表现如实单列。学习策略自己的正式阶梯以后仍须单独通过。

本轮不租卡、不启动付费作业，不沿用上一轮机器的租赁或长期作业授权。把建议规格、预计小时数和使用预算提供给用户，由用户确定云资源后进入下一阶段。云端新编译/新执行身份需建立本机前置资格，不能直接借用本地二进制资格。

未来正式学习保留标准 PPO、两组 seeds0/1/2、相同公共执行器、每流独立 60→300→600 连续采集课程；同流完整 60 秒且≥1圈才在下一自然会话升 300，完整 300 秒且≥5圈再升 600，不按样本阈值解锁。工程 pilot 权重不混入正式科学比较：正式六流从预声明种子重新初始化，并明确均衡 cohort 和共同样本 checkpoint。32768/流是目标，4096/8192/16384 为进度检查点；是否扩到目标取决于实测预算，不按正式成绩挑权重/seed。

## 9. 论文借鉴：吸收机制，不照搬成功数字

| 原始来源 | 可借鉴内容 | 在本项目中的处理 |
|---|---|---|

| [PPO 原文](https://arxiv.org/abs/1707.06347)；[Gymnasium 时间限制说明](https://gymnasium.farama.org/tutorials/gymnasium_basics/handling_time_limits/) | 真实采样与更新交替；MDP termination 与外部 truncation 影响 bootstrap | 两次真实更新、更新后实际执行、末观测 bootstrap 与 GAE 边界明确。固定控制器先过 E60 是投入前工程选择，不是 PPO 数学上开始学习的必要条件 |

本轮结论来自仓库证据；上述论文帮助提出和限制机制假说，不为未运行方案提供成功背书。长期仍围绕**重复踩踏的四足机器人地面记忆辨识与跨步协同控制**：先建立可靠且可训练的共同执行器，再在同预算/同种子/同任务下研究材料历史是否改变加载和重访时间、是否改善跨足与返程支撑；更复杂动作、泛化、Go2 实机与 NX 部署另有后续证据门槛。
