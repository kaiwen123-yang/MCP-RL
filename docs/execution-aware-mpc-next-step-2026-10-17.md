# 已确认科学问题与下一步：预测实际执行闭环的MPC接口

## 1. 用户本轮确认的首篇科学问题

> 在长程、多阶段机器人任务中，扰动和执行误差会改变后续动作的可完成性。如何根据后续任务需要学习可实现的反馈响应，并让MPC利用这种能力调整计划，在相同模型信息、输入权限和计算预算下，改善完整任务的成功率、完成时间与资源代价？

总主线仍为MPC规划、RL执行。狗和臂双平台目标暂保留，主平台不定。科学问题已确认，具体任务几何、扰动装置、传感型号与测试参数仍为待核设计，见[双平台研究范围](paper1-dual-platform-research-plan-2026-10-17.md)和[实机方案](paper1-hardware-experiments-2026-10-17.md)。不能靠增加第二个平台弥补核心机制未成立。

## 2. 对用户推进顺序的判断

先定义并实现预测实际执行闭环的MPC接口，是针对`b017942`结构性零需求的合理下一步。当前原生planner固定z/design/C后没有actor依赖，继续核查局部Jacobian或更换求解器不会补上这个缺口。

这一步首先建立可比较的科学对象及必要接口。它本身不构成新耦合机制，不预先意味着RL学出能力，也不要求最终在线MPC永远展开整个actor。可用精确展开作为分析基准，后续再研究紧凑模型的表示、误差与计算。

## 3. 接口应保留的对象

已有神经检查点属于原生三状态、17维观测、单动作系统。预测初始条件至少包括实际x、持续参考z、当前design、时间/任务预览及候选宏命令；不能仅从参考z预测，也不能把三状态权重接到六状态经典探针。

一个低层预测步应逐项对应实际执行代码：

1. 根据参考z、候选命令和design计算下一参考及参考输入。
2. 根据实际预测x、参考及固定控制条件计算support/观测。
3. 调用冻结actor，执行其声明的确定性或随机语义，并通过原tanh/support/fallback得到实际动作。
4. 用同一离散物理对象推进x；参考按原规则持续推进，不在段间重置到实际x。
5. 用实际执行状态和实际动作评价原任务，并检查明确的物理/参考/实现条件。

任务时间索引必须和`env.step`一致：原实际成本使用更新后x与本拍目标，之后才增加时间索引。预测目标、作用前/后状态、宏命令映射及约束前缀不可错位。

原`task`成本为位置目标误差、`.005*u²`与`.01*v²`；原训练`total`另有一步实现违反和空区间罚项。选用哪个对象、哪些属于约束，必须准确说明并向全部对照统一。不能把参考成本、实际任务成本和训练罚项混为一个“原目标”，也不能增加Γ奖励来保证非零需求。

未知未来扰动不能由评估seed偷看。名义、固定场景期望和鲁棒目标属于不同语义，若分析多个对象，应分别命名、单列信息与预算。原逐拍扰动界也不能无说明当成另一个L2能量球。

## 4. 三层证据必须分开

| 层次 | 必须看到什么 | 不能据此扩大什么 |
|---|---|---|
| 接口接通 | 固定权重/命令/扰动条件下，闭环预测与原执行映射一致；x/z/观测/动作链及成本一致 | 不等于新学习方法或任务收益 |
| 原任务产生需求 | 同一实际预测问题中，当前策略变化如何影响任务成本/约束/候选决策，导数或有限差异可独立核对 | 非零不等于有用，不等于由MPC最优值提出；CEM分支导数不是KKT乘子 |
| 共同学习增量 | 与同模型、同原任务、同策略类、同信息和预算的直接鲁棒PO/TO比较，明确新增关系解决什么 | 更好模型改善计划不能全部归给RL；同目标同梯度应接受等价 |

不训练验证可使用既有检查点、既有任务及预声明条件进行确定性重放、离线模型求值、导数核验和临时参数向量上的虚拟局部比较。所有计算计账；不调用学习训练循环，不更新/覆盖检查点，不伪造旧PPO优势和概率。需要完整滚动评估时准确标记它是新执行的评估计算，不称零仿真读取。

## 5. 强比较与继续/停止条件

- 精确actor闭环预测、候选方法和直接鲁棒PO/TO必须使用相同实际代价、约束、扰动信息与初始状态。不同预测模型或新增抗扰目标带来的变化不能被称为同问题胜负。
- 固定候选池能隔离预测/需求差异；若重新执行CEM，候选生成规则、预算与随机性应一致。不同分支、可行性变化及非光滑support/fallback必须记录。
- 对虚拟actor变化同时报告更新尺度、原任务/约束代价及跨条件影响；锚点方向存在不等于全任务保持。不能只比较幅度相差很大的两步。
- 若只有更好的闭环预测改善规划，保留其工程/模型价值，停止把它称为反馈学习增量。
- 若原任务需求仍无实质作用，或同信息标准方法完全解释结果，停止当前创新主张，不通过调权重、挑checkpoint、追加训练或换平台回避。
- 若需求与任务相关、方向实际可实现且其代价可接受，才继续研究有区别的联合学习或高效近似；这仍不自动解除用户的不训练边界。
