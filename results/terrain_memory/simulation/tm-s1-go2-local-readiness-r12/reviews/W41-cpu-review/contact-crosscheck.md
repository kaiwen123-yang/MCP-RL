# W41 原生地面接触：独立窄范围交叉核验

基准：`9cc42d5a9189a2bfd7e1e6cd99b9300045a16724`。只读 A/B E30 原始 `trajectory.npz`、`physical-000.npz`、三个 `accepted-reference-gain-H-plan*.npz`、保存的模型 XML 和对应 controller 源码；未运行新物理。机器可复算入口及更广样本见同目录 `controller-input-audit.py/json`。本核验另行解析 prefix，独立检查了时间、初末状态、力坐标及材料来源。

## 结论与数值

**这些具名样本支持预测器与实际系统的前向动力学不一致，不能仅用接触力日志错位解释。** 起始 `qpos/qvel` 完全相同、首 hold 目标几乎相同，原生地面支撑力却差百 N，并在同一 2 ms hold 的末端产生实际状态分离。它们不是随机样本，不代表全部跌倒，也不是已经执行过的严格相同输入重放实验。

|---|---:|---:|---:|---:|---:|---:|
| A / 635 | 12.28 | 5.7115e-8 | 3.4269e-6 | 0.007157 | 127.541057 | 0.433510 |
| B / 712 | 13.82 | 5.9536e-8 | 3.5722e-6 | 0.007191 | 113.940128 | 0.385749 |
| B / 713 | 13.84 | 5.1513e-6 | 3.0908e-4 | 0.013398 | 246.876524 | 0.437117 |

**B713 的目标差是 5.15e-6 rad，不能写成与前两个同为 1e-8 量级。** 三者的初始状态最大差、十个子步的起点时钟最大差、prefix 第十步末状态与 `accepted_states[1]` 最大差均为 0。目标差由 prefix 中 PD 和步前状态反算，再与实际 `q_target` 对比；执行器力直接比较 prefix 与 physical。

## 为什么不是仅有一行时间或力坐标错位

1. **相同时间约定。** `mjpc/trajectory.cc:342–360` 先保存步前时刻和状态，再 `mj_step`，随后保存步末状态、力和接触。实际 `scripts/s1_go2_r11_runtime.py:598–648` 同样保存 `sample_t` 后积分，再记录力。两者均把该次积分所用的接触评估与步前时刻对应。500 Hz trajectory 的 `mj_forward` 不推进 qpos/qvel，见该文件 564–572 行。两条路径均将同一目标保持十个 0.2 ms 子步。
2. **差异持续整个首 hold。** A635 的预测 Fz 范围为 0.0072–1.6525 N，实际为 127.4065–259.6714 N；B712 为 0.0072–1.3677 对 113.9401–114.9986 N；B713 为 0.0134–3.5027 对 179.9145–246.8765 N。不是只比较单个边沿。再由真实 2 ms 末 `qvel` 与 prefix 末 `qvel` 的独立状态差，排除“只有力日志显示不同、实际推进一致”的解释。
3. **这些特定接触的坐标可比较。** 保存模型中 geom 0 是未旋转的水平 plane，26/39/52/65 是足部 sphere。prefix 首步接触仅为 floor 0 → 足部，故其接触法向为世界竖直方向，可求和 `mj_contactForce` 的首分量。实际 `contact_state` 在 runtime 124–133 行用 `frame.T @ wrench[:3]` 转成世界力；physical 第 44 列为总世界 Fz。三处非足力和非足接触计数均为 0，故此处总 Fz 等于足部 Fz。prefix 未保存通用接触 frame，不能把这个简化用于任意接触。
4. **没有把材料力混进来。** 三处四足中心最大 x 分别为 0.763161、0.744375、0.753815 m，均在材料入口 0.8 m 之前，足部半径也未跨入入口。实际首次材料载荷边界在 A 12.8428 s、B 14.3302 s。`s1_go2_joint_material.py:55–62,72–97` 只替换/施加 soft 足材料力；预测侧 `mjpc/tasks/quadruped/r10_contact.h:10–16,41–59` 同样只给材料内足施力。首步 prefix 的浮动基座六维 `qfrc_passive` 也全为 0。因此这里是在比较原生刚性地面支持，不是“预测只统计 native、实际还包含 TM02”。

## 能定位到哪里，尚不能定位到哪里

当前 controller 的 `mjpc/agent.cc:299–318` 在规划时调用 `MakeDifferentiable` 并关闭 warmstart；`mjpc/utilities.cc:59–74` 将 joint/geom/pair 的 `solimp[0]` 置 0。实际模型保存的地面/足部 `solimp[0]` 为 0.99；规划结束后才恢复模型参数。这是可指认的预测/实际模型差异，与本次现象相容。

但起始 qpos/qvel 相同不等于全部求解器内部状态相同；动作也并非位级相同。现有记录不能独立拆分接触平滑、coldstart、其他求解配置各自的贡献，也没有证明全部后续 Kδx 或全部跌倒由这一项造成。下一步应把**首 hold 状态推进一致性、相关导数质量、控制结果**一起评价，而不是仅追求某条接触力曲线相等。

## 为什么不能照搬旧 S5-r17 重试

`experiments/terrain_memory/s1-go2-r11-S5-r17.json` 已明确试过在 `MakeDifferentiable` 后恢复 geom/pair 原生 `solimp[0]`，保留 joint-limit 平滑、其他接触参数、0.2 ms 积分及 2 ms hold。旧记录 `results/terrain_memory/simulation/tm-s1-go2-material-continuation-r11/dev19-S5-r17-E30.json` 在 15.3628 s 发生 `invalid_contact:[[0,13,0,1]]`，最大 x=1.03166 m，已加载材料但未完成合法穿越；它不是因技术异常而无效的样本。

因此，“把 native impedance 恢复回来”本身不是新的已证实修复。旧失败也不证明所有更准确的接触预测都无用：旧控制器与当前 r30 不是同一整体配置。新工作必须说明与 r17 的实质差别，以当前具名首 hold 作为可审查对照，同时检查非平滑接触附近的导数/优化行为；不得把旧开关原样改名后直接扩训。
