# W39 原始学习数据与材料失效复核

审查基线：`07b0ee3e15c9f10e9b1a6a1de3997bec36f39556`。本文件是 W40 启动前的原始数据复核，不是新增物理实验。可复算脚本为同目录 `material-learning-audit.py`，逐维、逐动作、逐事件及末端 0.2 ms 数据见 `material-learning-audit.json`。

## 结论先行

原始数据支持继续优先修复低层闭环稳定性。它没有显示 rollout 损坏、PPO 使用了错位 successor、PANN 通道接反或未传入 actor；也没有显示材料 Newton 求解器大规模发散。比紧凑结果更明确的新事实是：

1. **2048 条动作中，1820 条的四个未来查询足点全部在材料条带外。** 进入材料查询范围的只有 228 条，其中 86 条实际获得非零 PANN。剩余 142 条中的 140 条查询了此前没有真实加载记录的世界格；最后 2 条的真实短负载全部落在观察器 2 ms 采样端点之间。这解释了本轮为何绝大多数 actor 输入没有材料记忆信号。
2. **原始 658 维输入、原始日志与紧凑结果相互一致。** 两流 1986 条同回合相邻 transition 的 `next_obs → 下一条 obs` 逐元素完全一致。所有保存数组有限，PANN/动作/行为 log-prob/value/终止标志对紧凑数据一致；reward 的差别仅为保存 float32 时不超过 `4.73e-7` 的舍入。
3. **材料域退出主要是高速触地在极短时间内穿过 1 mm 压入界线。** 选中的 A254、B256 原始全量材料与物理力记录逐条相符，终末触地垂直速度分别为约 −1.959、−1.410 m/s；从这次加载的位移边界到越域边界只有 0.4、0.8 ms。这个时间尺度既短于 2 ms 反馈周期，也远短于 500 ms PPO 动作周期。
4. **B272 的 60 秒不是任务推进稳定。** 20–60 秒实际 x 仅前进约 2.69 mm，而命令仍明确要求向前。它表现为控制器长期停滞，不是 PPO 把 cap 调成零。

这些事实支持保持本轮 PANN、658 维 schema、奖励、TM02 `.02` 域限和原任务成功条件不变。在控制修复的同一运行中补上查询暴露、短负载漏采、触地冲击、实际进展的诊断，避免把“多活了几秒”当成材料记忆方法有效。

### 2.2 原始输入有很尖的力冲击特征，但还不能据此宣布网络饱和

`PolicyMaterial.observation` 使用固定工程尺度，GRF 以单足平均承重 `15.206408×9.81/4 N` 归一化，PANN 以 `0.001 m` 归一化。`GaussianActor.forward` 将该向量直接送入两层 Linear/Tanh；这里没有运行均值方差归一化、LayerNorm 或输入裁剪。PPO 的 advantage normalization 不是 observation normalization。

实际输入历史块最大绝对值 A 为 **86.5254**、B 为 **56.3564**；PANN 块最大值分别只有 **0.04427**、**0.09803**。这些是 actor 真正收到的数值，不是尚待二次归一化的中间变量。它提示在少量冲击样本上，各特征块的数值规模相差很大，应保持可见。

但是，没有加载每个行为版本的权重并计算隐藏单元激活，本轮不能把此差异直接写成“actor 已饱和”或“PANN 被神经网络忽略”。本轮应保留冻结输入合同，记录尺度分布和 PANN 动作依赖；若未来单独改变归一化，应明确标记学习版本边界，不能在继续旧 checkpoint 时悄悄换尺度。

## 3. 为什么 PANN 大多数时候为零

### 3.1 主要原因是没有查询到已形成历史的世界位置

观察器每 2 ms 用实际足底运动更新自己的材料状态；actor 每 0.5 s 才作一次 cap 决策。actor 的 PANN 查询位置是**最新完成计划中接近 `当前时间+0.2 s` 的四个未来足点**，不是当前实际足点，也不是已经被加载过的全材料格平均值。返回的是条件卸载后 2/200/500 ms 的残余压入量，单位米。某处真实接触过材料，并不保证下次 actor 所查询的未来足点覆盖那片历史。

| 每条动作按当前 PANN 分类 | A | B | 合计 |
|---|---:|---:|---:|
| 四个未来 query 足均在材料外 | 922 | 898 | **1820** |
| query 在材料内，但查询格无此前真实加载历史，PANN=0 | 71 | 69 | **140** |
| query 覆盖真实加载历史，但该短脉冲被 2 ms 观察遗漏，PANN=0 | 1 | 1 | **2** |
| PANN 非零 | 30 | 56 | **86** |
| 总计 | 1024 | 1024 | **2048** |

因此，本轮 **88.867%** 的动作连未来材料查询位置都没有进入；86/2048 的非零率主要是暴露不足，而不是已经证实观察器失灵。存在非零信号的 101 个足级查询，三个 horizon 均无负值、无超 `1e-12 m` 的反向增长；这与卸载残余压入逐步恢复的定义一致，但本轮没有用真值替代观察器，亦未声称已验证其完整预测精度。

另有 100 条 `next_obs` 含非零 PANN，其中 14 条是真实物理终止后的 successor。它们不是 14 次额外获得材料反馈后继续行动的机会，真实终止的 bootstrap 仍为零。比较训练暴露时应按实际用于选动作的当前 obs 计数，不能把终端 successor 合并成策略已经体验过的有效决策。

表中“真实加载历史”来自保存的 ReferenceColumns 事件，**只用于离线诊断解释零值**。不能因此把真值 `q/e`、真值加载掩码或真值 recovery 加入 actor 输入。

### 3.2 最后两条例外确实是短脉冲和空间格移动

**A269，transition 8136，actor 时间 17.5 s。** FR 未来 query 覆盖世界格 `(48,-4)`、`(48,-3)` 的旧负载。原始事件记录加载/释放在 material-state 时间 15.4488/15.4502 s，对应施加位移的 physical boundary 区间 `[15.4486,15.4500)`，仅 1.4 ms。原始 trajectory 显示：

- 在观察器的 15.448 s 采样时，FR 足底最右端约 `0.959382 m`，尚未覆盖从 `x=0.96 m` 开始的这两个格。
- 在 15.450 s 采样时，足已覆盖该格，但足底已经高于未变形表面约 **5.405 µm**。

**B258，transition 7808，actor 时间 13.5 s。** FR query 覆盖世界格 `(52,1)`。真值负载 physical boundary 区间 `[13.1056,13.1060)`，仅 0.4 ms：

- 13.104 s 时，足底最右端 `1.039193 m`，尚未覆盖从 `x=1.04 m` 开始的格。
- 13.106 s 时已经覆盖，但足底高于表面约 **0.410 µm**。

两例都无需重算材料模型就能解释：观察器在两个端点都没有见到“这个空间格被压入”的边界，不能凭未来查询自动恢复中间发生过的历史。这是现有 2 ms 端点采样的真实局限，源码 `MaterialObserver.timing()` 已明确声明不解析 0.2 ms 窗口内的 load/unload。它与 PANN 本构模型本身是否拟合准确是不同的问题。

本轮不应直接提高 observer 频率或增加真值修正，与 r29 的控制修复混在一起。应记录 query 足点、query 世界格、观察器看到的最近加载时间、计划来源时间，以及短负载漏采的离线标签。待低层稳定后，再把观察器时间分辨率作为独立机制研究。

## 4. 材料域退出的原始边界与力记录

### 4.1 `.02` 的固定应变域等价于 1 mm 法向压入界线

`Ground.step` 对已接触格施加 `e11=bottom_z/H`，`H=0.05 m`，保存的最大主应变域限为 `.02`。在这些触地案例中，越域的是法向压缩，因此对应 `0.05×0.02=0.001 m`。这不是新的阈值，也不是本轮建议放宽的阈值。

当前 TM02 参数的瞬时等效杨氏模量按 `9KG/(3K+G)` 为约 2454.5 MPa；结合原 `.001 m²` 足面积、`.05 m` 厚度和 `.025` 接触尺度，对应线性瞬时切线约 `1.227×10^6 N/m`。这仅是原参数的量纲核对，不是替代非线性黏弹性求解；它解释为何 1 mm 级压入会产生约 1200 N 候选法向力，而不是几牛顿。

全部 14 次域退出的已有逐次 rate-extrema 表中，最大 Newton 残差均不超过 `1e-8` 原 MPa 数值；13 次终末峰值对应连续加载格，B268 对应新格激活。涉及 FL 7 次、FR 6 次、RL 1 次。不能把新格在一次边界更新中获得有限应变，或已有格的高压入速度，误报为求解残差发散。

进一步逐条读完全部 14 个原始失败记录后，**每次失败的最大应变都与该次实际已接触足的 `-bottom_z/.05` 完全相等**，与紧凑结果中的终止时间/应变也完全一致；material-state 比 physical-state 前移 0.2 ms，误差仅浮点舍入。四足候选切向力与原摩擦公式重算的最大差为 `2.28e-13 N`。

其中 B268 的最大内部 qdot 的确落在一个面积约 `7.36e-7 m²` 的新格，但原始失败记录显示 RL 整足已压入 **1.04185 mm**，整足候选法向力 **1261.85 N**。同足所有位移加载格共享 `e11=bottom_z/H`，因此不能把“最大 qdot 的格很小”改写成“只是一个小格造成的假域退出”。上述 13/1 是峰值所在格的边界类别，不是已经证明的互斥根因分类。

### 4.2 两个完整高频案例

| 原始证据 | A254 | B256 |
|---|---:|---:|
| 终末触地足 | FR | FL |
| 末次加载的 boundary 时间 | 12.2356 s | 24.4610 s |
| 该次加载刚开始的压入 | 0.37725 mm | 0.16659 mm |
| 该次加载刚开始的足垂直速度 | −1.95918 m/s | −1.40968 m/s |
| 越域 physical boundary 时间 | 12.2360 s | 24.4618 s |
| boundary 到 boundary 间隔 | **0.4 ms** | **0.8 ms** |
| 终末候选压入 | 1.02803 mm | 1.00712 mm |
| 终末仍向下的垂直速度 | −1.46256 m/s | −0.69849 m/s |
| 最后一条实际施加的该足法向力 | 897.90 N | 1054.76 N |
| 越域计算得到但未施加的候选力 | 1251.10 N | 1220.65 N |

A254 的 61,180 条、B256 的 122,309 条实际物理力行，与相同时刻原始 `material.foot` 软足力逐元素差为 0。两者都各多出一条 material 终端候选行，没有对应 physics 行。原因就在执行顺序：`before_physics` 先以当前足底边界计算材料到 `t+0.2 ms`，发现越域立即返回 false，尚未执行 `mj_applyFT` 和 `mj_step`。

因此，终端 `material-failures.force_N` 应标成“导致越域的候选力”，不能用它宣称机器人已经承受了该力。实际已施加的大冲击同样存在，但应取之前的合法物理行。这一对齐没有显示脚序、力单位、面积重复计数或反馈日志与真实软足力不一致的证据。

### 4.3 A260 的首次加载即失败也得到解释

A260 首次真实 load 的 material-state 时间为 14.3636 s；失败 physical state 为 14.3648 s，即已有报告的约 1.2 ms。首载时仅约 **0.12572 mm** 压入，终端是 **1.01895 mm**；峰值向下足速约 **−0.84173 m/s**，终末仍为 **−0.36479 m/s**。

原始 14.356–14.362 s trajectory 显示，该足在条带内已经悬于表面上方，再快速下落；此例不是“跨越软硬边缘时突然携带超限硬地穿透”的直接证据。最后一次 PPO cap 决策在 14.0 s，下次 14.5 s 尚未来到；策略没有一次完整机会在首次加载以后再根据新 PANN 调节 cap。应优先阻止低层将高速触地点带到这个状态，不能把每次终止都归为 PPO 尚未学会材料记忆。

## 5. 60 秒无终止仍可能没有任务能力

B272 的完整 30,001 行 trajectory 表明，任务在 2.002 s 后持续处于 outbound，没有进入 turn/return。10 秒后请求 cap 均值约 0.19784 m/s，命令 x 速度均值约 0.19636 m/s，20–60 秒实际 base x 仅从 0.288839 增至 0.291531 m，y 长期约 −0.348 m。

本回合不是“PPO 学会把速度设成零而得高分”。原动作映射本来也只能输出 0.18–0.25 m/s 的 cap；真实问题是仍有持续前进命令时，低层没有实现持续前进。原始记录有 1363 个控制采样的未裁剪 PD 需求超出原力矩界，最大绝对需求约 305.12 Nm；之后长时间停留在非进展姿态。后者的具体优化器/运动参考原因由控制原始数据审查进一步核对。

所以必须同时报告存活、净前进、材料加载、合法穿越和回程。原 E30/E60/E300/E600、原合法通过条件不变；这个训练回合不能代替正式 E60 通过。

## 6. W40 在启动前应补上的内容

1. **保留控制稳定性优先级。** 本轮证据没有给出先扩大 PPO 预算、修改 reward、重训 PANN 的理由。r29 的可行性修复仍需按控制审查的完整执行模型核对；瞬时输入有界也不能自动保证 2 ms 持有期间或高速触地时不越材料域。
2. **增加 PANN 暴露分母。** 每回合/每 stream 报告未来 query 在条带内的动作数、查询已观察历史的动作数、PANN 非零数、非零持续时间、首次 load 至下一 actor tick 的余量。不要仅报“启用了 PANN”或零值比例。真值重叠与短脉冲标签只保留为分析字段。
3. **触地事件增加时间尺度。** 从真实运动量记录 first-load/revisit 前后的足底高度、垂直速度、接触面积和压力、已施加力、材料候选力、physical boundary/material-state 时间及下一次控制/actor 更新时间。对终端必须分清候选力是否进入 physics。
4. **保留输入尺度和原始查询原件。** 658 维输入分布、历史力峰值、query 足点/plan 时间、观察器可见世界格信息应可追踪；不要在旧 checkpoint continuation 中静默重设 normalization。
5. **记录未前进的长期存活。** 命令 cap、命令 vx 与实际 progress 应一起呈现。B272 类停滞仍属于低层任务能力不足，不能被较长 survival 掩盖。
6. **避免 trajectory 末行时间错配。** 现有 runtime 终止时复制前一行，仅替换 `time/qpos/qvel/rpy`，其它 feet/GRF/torque 字段保留 `diagnostic_time`。分析按 `diagnostic_time` 对齐；新增终端日志应明确各字段物理时刻，不得把复制的力当成真实 terminal state 的力。

本审查没有运行物理仿真、没有更改模型/学习配置、没有调用隐藏真值给 actor，也没有替用户删除服务器原件。它为当前 W40 计划增加分析约束和可观察证据，不声称尚未执行的修复已解决稳定性。
