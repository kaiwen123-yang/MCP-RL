# W39 原始控制、预测轨迹与执行链复审

基准：`07b0ee3e15c9f10e9b1a6a1de3997bec36f39556`。本次读取已补传 Release 原件，不沿用上一轮事件窗口作为完整回合的替代。没有启动物理实验、没有重新积分历史状态、没有修改运行代码。计算使用保存的数组、已执行动作记录、矩阵运算和四元数状态差。

## 1. 总判断：r29 的优先方向保留，但论证和验收必须补正

补传数据**加强了先处理局部反馈与执行器可实现域的依据**，没有发现足以把主因改写为“上传缺失”“用错 reference”“20 ms/2 ms 时钟整体错位”或“PD 没有真正执行”的证据。全 62 个训练回合中，60 个出现过 `max|raw Kδx|>0.5 rad` 和执行 PD 饱和；两个没有出现的回合是尚未走到问题区域就完成 checkpoint 截断的 A284、B280。在实际发生过材料 load 的 58 个回合中，57 个的首次大反馈及首次执行 PD 饱和都早于第一次 load。唯一例外是 A256：load 14.4398 s，大反馈/执行饱和 14.784 s。另有 B263、B272 从未实际 load，仍出现大反馈和饱和。

这是一组完整回合的事件先后统计，不是 58 次相互独立的因果试验。它支持把执行反馈作为本轮优先干预，却不能证明全部 fall、材料越域和长期停滞都只由一个因素造成。尤其不能把 raw 反馈的数十或数百 rad 当成真实目标、关节角或实际施加扭矩。

本轮最重要的新增更正有四项：

1. B E30 在 **首次材料 load 前**已经出现 48.914271 rad 的原始反馈峰；上一轮离散事件窗口漏掉了该时刻。
2. 20 ms 的 actual−accepted 差异更早就存在，有些较大误差此前并未立即伴随大反馈、饱和或终止。误差出现本身不是失稳的充分条件。
3. 训练中确实存在 accepted trunk 仍不可行、规划调用未产生新策略以及失稳后长期停在畸变姿态的情况。两 E30 的 accepted 全部 trunk 可行不能推广到全训练。
4. `少饱和、少 fall、活得久` 不能单独作为下一轮稳定性通过标准。B272 的后半段同时满足这些表面条件，却基本不前进。

## 4. 已确认控制策略身份；20 ms 差不能叫固定同输入误差

完整原始数据给出了比旧窗口更强的身份核对：

- 每个动作都满足 `u_before=u_nom+feedback_scaling*raw_K_delta_x`，最大误差 0；最终 ctrlrange 裁剪最大误差 0。两 E30 所有部署 `feedback_scaling=1`。
- 525/881 条 packet 与 trajectory 的 96D userdata 最后 12 个通道逐元素误差 0；未来 actor 引用为 0。同步逻辑延迟为 0，与昂贵的实际 wall time 是两个概念。
- 以完整 prediction 的参考状态、原线性插值、float32 query time 和四元数状态差重算 **全部 14,034 个** `state_delta`，最大误差仅 `3.25e-15`。nominal action 重算误差 0；保存的 planner reference 节点与 prediction 对应节点误差 0。
- 所有有节点记录的计划，其 node 0 的 37D initial q/v 与对应实际状态逐元素相等。以该计划自己的 `reference/u_ff/K` 重算 accepted 节点动作，A/B 最大误差为 `1.33e-15 / 3.45e-13 rad`。
- 原始 PD 请求重算与 trajectory 记录误差 0。按返回的 float32 target 重算原扭矩 clip，与实际 actuator_force 最大差约 `7.14e-6 Nm`；这远小于首事件的数十 Nm 超限，且处于浮点目标与 MuJoCo 原 ctrlrange 再裁剪差异的量级。

因此没有证据把本轮失败归结为 reference/accepted 混淆或明显使用了错误的计划状态。r28 保留产生 accepted 的原候选策略、不用 accepted 去重新锚定原 K 的做法是正确的。

但候选 action rollout 用离散节点 K，而部署 `Action` 按查询时间插值；显式 `GetAction(time=t)` 会量化时间和返回动作。两 E30 最大时钟量化误差约 0.473/0.946 μs。首大反馈时，量化引起的参考速度差范数 A `4.37e-6`、B `9.22e-5`，而记录的真实 reference 速度误差范数是 1.214/1.408；此处时间量化不是所观察的大状态误差的主要量级。晚期高敏感策略的计划起点动作仍可能因时间插值相对离散 node 0 有 A `1.60e-4`、B `3.76e-3 rad` 的差，不能称两个执行路径逐位相同。

更根本地，accepted rollout 与真实 plant 使用同一反馈形式，却在状态开始偏离后给出不同输入。因此 20 ms 的 actual−accepted 是**同一控制策略下的闭环轨迹差**，不是在固定相同输入序列下测得的纯动力学模型残差。预测的 native 接触 `MakeDifferentiable`、禁用 warmstart、冻结四个因果材料 patch 等与实际 plant 的差异，都仍可能参与其中。现有原始数据没有保存全部 accepted +2/+4 ms、全 K、qacc_warmstart、完整 task 内部 phase state，不能据此做逐位历史恢复或把差异唯一归因到一个 native contact 参数。

### 更早已有较大差异，尚未进入反馈爆发

完整节点记录显示：A 7.72→7.74 s 的 mixed qvel 差范数已为 0.60590；B 13.64→13.66 s 已为 2.26188，其中 FR thigh +1.82997 rad/s、FR calf −1.18023 rad/s。B 这一差异早于 14.734 s 首次 PD 饱和和 15.044 s 首大反馈。

这些范数混合 m/s 与 rad/s，只能比较同一状态坐标下的误差，不能解释为物理能量。新结论应是：**已有预测/跟踪误差与后续增益和饱和活跃集变化交互，最终出现无法实现的局部纠正**。旧窗口中最早看到的误差不是误差真正第一次出现，更不能单凭某个非零误差宣布失稳原因已经唯一确定。

## 5. 全训练的可行性与未更新策略，原报告需要扩展

62 训练回合共调用 planner **51,693 次**（普通 50,453 + startup 1,240），实际输出新计划记录 **51,685 条**：

| 按前后真实违反量分类 | 已记录计划数 |
|---|---:|
| nominal 与 accepted 均 trunk 可行 | 51,451 |
| nominal 不可行、恢复至 accepted 可行 | 165 |
| accepted 仍 trunk 不可行 | 69 |

最后一类分布在 18 个训练回合。它是控制器显式有限候选 restoration 的结果，不等于代码偷偷把不可行标成成功；也证明预测 trunk 可行性并非每次都有可行解。日志字符串 `acceptance_mode` 仍把“恢复至可行”写为 `feasible_cost`，统计应以两个违反量为准。两 E30 的全部 accepted 确实 trunk 可行；B 新增两次恢复位于 16.58/16.66 s，nominal 违反分别 9.088/2.064 mm，已在 16.1296 s 非足端承载之后，不能把这些晚期恢复改写成更早的失稳首因。

69 个 accepted 仍不可行的记录全部晚于各自回合首次大反馈。57 个 load 前首大反馈的提前量为 0.1272–4.2152 s，远大于一个物理子步和 RPC 时间量化，事件顺序不是同一时刻的舍入排列造成。

### 8 次 planner 调用没有新策略，全部在 B276 尾部

缺口是 13.48 s 与 13.52、13.54、13.56、13.58、13.60、13.62、13.64 s。reference-packets 记录了这些调用的实际 planning wall time，feedback `plan_id` 则继续使用 694 或 695；这不是仅仅漏了一个文本索引。

13.46 s 的 μafter=1e-6，13.50 s 的 μbefore=0.032768，恰为 `1e-6×2×4×8×16×32`，与源码允许的五次 backward regularization 失败后提前返回一致。后七次没有 terminal status，不能从现有记录唯一分辨 backward 失败还是全部 action rollout 失败。相关早退都位于成功记录输出之前。最后两份成功发布的计划代价已达约 `1.215e9 / 6.031e9`，accepted trunk 仍违反约 0.631/0.411 mm。

时序必须保留：该回合首大反馈/执行饱和 11.524 s，首 load 12.9166 s，无新策略始于 13.48 s。最后新 policy 695 的原点为 13.50 s，继续使用到最后实际控制 13.650 s，策略年龄达到 **150 ms**；随后 13.652 s 触发 body fall。八次早退是晚期退化，不能用它代替本回合更早的首发解释。

W40 的每次 planner 调用必须留下 `call_id、attempted origin、return reason、是否更新 policy、实际复用的 plan_id/age`。这只是把既有分支记清楚，不能为修补日志另创静默冻结、重置或成功规则。

## 6. B272：长期存活可以是失稳后的畸变平衡

B272 不是一直平稳地选择低速站住。其首大反馈、目标 clip、反馈新增 PD 饱和都发生于 9.966 s，raw 反馈为 1.431889 rad；nominal 首饱和在 9.980 s。

11–15 s 的 2,000 个实际控制时刻中，1,346 个存在 PD 饱和，47 个 `raw Kδx>0.5 rad`，峰值 56.87026 rad；roll 曾达到 1.16472 rad、base z 最低 0.15793 m，接近原 fall 条件。该段已有 5 个 accepted trunk 不可行计划。随后它落入了仍未触发原失败规则的异常姿态。

20–60 s，base 从约 `(0.28884,−0.34852,0.25576)` 只移到 `(0.29153,−0.34692,0.25576)`。RR 足端中心 z 约 0.273 m，足底离地约 0.251 m；RR thigh target 在原上界 4.5379 rad 的比例为 99.8%，calf target 在原上界 −0.83776 rad 为 100%，hip 在上界为 80.365%。

这个尾段仍有 2,000 次新规划，所有计划十个候选均 trunk 可行，α始终大于 0，accepted 代价稳定在约 1.193；raw 反馈峰只有 0.08944 rad，20,000 个控制时刻里仅 1 个 PD 饱和。与此同时 reference packet 始终 active、endpoint=3 m，command vx 仍约 0.2 m/s。现有证据支持“控制退化后陷入不能通行的异常局部平衡”，不支持把它解释为 PPO 故意选择零速或规划进程停止。

下一版因此应同时观察：是否避免初始失稳、是否维持可行姿态并推进原合法路线、是否进入类似 B272 的长时间非进展尾段。增加停滞诊断不能悄悄替换原失败判据或奖励定义。

## 7. r29 必须保留的实现与解释边界

本复审支持继续实现原计划的状态相关、耦合的 12D 受约束局部反馈，统一候选 rollout 与真实部署；并不支持把它简化为在最后逐轴截断 K 或目标。B 的 nominal 饱和必须包含在处理范围内。

仍需注意以下事实：

- predictor 和实际 plant 都是 0.2 ms 积分、2 ms target hold。原 runtime 第 268 行的 `.01s` 是陈旧默认说明；W39 campaign 已在后续分支用实际 controller settings 覆盖该字段，resolved 明确为 `.0002×10=.002s`。可清理新版本说明，不可修改历史结果冒充修复了实际 timestep。
- 瞬时 PD 区间约束不保证整个 2 ms hold。原物理数据已存在起点不饱和、后续子步饱和：A 4 个、B 2 个 hold，均为较晚事件。原十子步 PD clip 必须保留；新结果应记录整 hold 的状态和饱和，而非只报告 QP 起点可行。
- accepted `(v,J)` 只证明已有候选的 trunk 几何排序，不是接触、材料有效域、可执行扭矩和长期路线的联合稳定保证。
- `MakeDifferentiable`、native 接触近似和材料冻结历史仍是下一层待区分因素。先修反馈后若同类跟踪/接触差仍在，应重新定位，不应只靠多跑 episode 或增大 trunk 权重。
- 对无法复现的历史失败不得补写 H/C、完整 K 或不存在的 accepted 中间节点。下一轮应保存完整关键 horizon、actual 作用时刻对应 K/H/C/活跃集、足以恢复 task phase/userdata/mocap/hold phase 的上下文，以及 planner 失败返回信息。

## 8. 对 W40 的直接影响

**不建议原样延长 r28 的训练；也无需因为补传而改掉 r29 的主方向。** 应把以上完整回合证据和边界补进 W40 执行说明：保留两条各自 lineage 的正式流与独立 GPU 测试任务，先完成同路径受约束反馈，明确每次新策略是否成功发布，保持原 PD、扭矩、native/TM02、原任务和阶段阶梯。

验收不能只看 raw K 峰或饱和次数下降。它还要同时检查首 load 前的失稳是否缓解、实际材料接触后的合法存活/进展、预测与实际闭环差、无新 policy 的调用、以及 B272 式姿态退化后的停滞。以上均使用已有物理和路线判据；诊断阈值不新增成功条件。
