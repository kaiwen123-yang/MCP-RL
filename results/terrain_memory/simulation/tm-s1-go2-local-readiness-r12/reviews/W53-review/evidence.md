## 1. 这一轮实际到达哪里

## 2. N：可以确认短段向前走了，稳定资格仍然不足

### 2.1 实际运动与接触

取建立运动后的 **3.0000–6.0274 s**，不把起步过渡和材料接触混在一起：base 前进 0.590670 m，平均 vx=0.195168 m/s，1514 个 500 Hz 轨迹样本的 vx 全部为正；z 在 0.282440–0.302198 m，roll/pitch 最大绝对值分别 0.066617/0.072506 rad，最大横向偏移 0.014927 m。四足最大净离地高度依次为 27.78/23.67/27.33/28.28 mm，每足都有持续超过 50 ms 的卸载段。这些原始量支持“短段向前运动已经恢复”。

这不等于低冲击或长程可靠。上述硬地运动窗中四足 Fz 峰值为 **1314.86/1964.07/1828.65/1563.13 N**，平均各足约 31.6–41.3 N；高峰是原始 5 kHz 接触流中的实际瞬态，不能因为视频机身平稳而忽略。2.002 s 起步后的更宽窗口仍含一次降高过渡，最低 z=0.272552 m；不应选取较好窗口后宣称全程稳定。

整个有效运行只有一种子的一小段路。能据此继续做有明确根因目标的修复实验，但还不能升级为长程任务、材料记忆收益或 RL 训练就绪的资格。

### 2.2 首次材料接触与任务字段的区别

首次前足进入软区 footprint 的报告时刻是 5.994 s；**首次正的、实际施加的材料法向力**发生在 force boundary **6.0274 s**，对应材料更新状态时钟 6.0276 s。此时 base x 约 0.602141 m，前足已伸到材料区域。FL 接触前向下速度约 −0.616431 m/s，foot bottom −0.030643 mm，首次材料 Fz 37.5895 N。FR 首次正材料力为 6.3742 s，后足尚未进入材料承载。

因此 route 字段 `material_loaded=false` 不能概括成“从未碰过材料”：它与 base/任务路线进度关联，base 尚未到 x=0.8 m；足端真实材料加载已经发生。从首次正材料力到停机只有 **0.4382 s**。

材料末态有 48 个 world cells，其中 24 个曾承载；事件流包含 load=24、release=73、revisit=64。这里 **64 是同一足对网格单元的再次激活次数**，cross-leg revisit=0，返回路段=0。它不是 64 次走路实验、64 个新步态周期，也不能证明跨足复访或长期材料记忆已获收益。

F 的直接运行问题不是仅在 3.12 s 突然出现一个求解错误。之前约 0.8 s 内已经反复发生真实触地滞后和支撑丢失。下游失败矩阵的矛盾由控制审计报告单列；修掉最后矩阵矛盾不足以证明步态已经稳定。

### 3.2 最初落脚偏差不能归因于执行器饱和

首个摆动 2.052–2.254 s 的 **1010 个物理子步**，执行器实际力矩与请求 PD 力矩最大差仅 2.66e−14 Nm，最大请求力矩为关节限值的 **35.8572%**，没有执行器削顶。hold 内 PD 力矩相对该控制 tick 的 WBC 总力矩，最大差 0.878340 Nm（FR calf，2.0798 s）；FR/RL calf 的 RMS 差分别为 0.328034/0.228547 Nm。扩大到首个双足实际落地前，最大 hold 差为 2.172708 Nm。

这证明应优先检查摆动轨迹、真实地面高度、脚端跟踪、时序切换和保持期间的实现一致性，而不是直接加大电机能力。hold 内差异存在，但这些数组还不能隔离出它是早期毫米级离地误差的唯一原因。明显请求超限只发生在最后 9 个物理子步，从 3.1182 s 开始，远晚于第一轮触地延迟。

全部 control 记录中的 `tau_total` 与当前 tick 的 `requested_pd` 最大差为 1.60e−14 Nm，floating-base dynamics residual 最大约 3.44e−5；这些局部一致性是有价值的，但不保证计划触地事件、未来脚端位置或全时域 MPC 约束正确。

源：F `w53-f/control-00001..00004.npz`、`trajectory.npz`、全部 physical 流；`evidence.json:F`。涉及足端 anchor、删力后的机身加速度、未来 foot_plan 以及零行矛盾的源码/矩阵结论见并行审计 `control.md` 与 `f-control-evidence.json`，本报告不把那些问题简化为 OSQP 随机失败。

## 4. 并行与算力：资源分区存在，有效物理任务没有实际并行

从 N-A/F-A 每个实际 attempt02 的 UNIX 起止时刻独立求交集：

|---|---|---|---:|
| F attempt02 | 2026-11-17 10:38:47.858 | 10:39:15.968 | 1 |
| N attempt02 | 2026-11-17 10:41:07.710 | 10:44:05.737 | 10 |
| C 有限离线遍历 | 2026-11-17 10:30:07.154 | 10:30:12.979 | 独立 GPU 数据任务 |

**N/F 有效物理任务的重叠时长为 0 s**；F 完成到 N 开始相隔 111.7424 s，C 更早已经完成。两次零物理步的 attempt01 曾有约 8.827 s 重叠，不构成有效双实验并行。`0–9 / 10–19 / 20–21` affinity 只说明允许使用哪些核，不能作为“三任务并行已经兑现”的证据。后续启动器需记录实际 PID、开始结束时间、有效物理进度和重叠区间；独立数据/分析第三路可与两个实跑并行，但不应只是先后启动后在文案上叫并行。

N 的有效作业 wall 为 178.0264 s，user+system CPU=1064.7907 s，整作业平均 **5.9811 核**；eval wall=166.9195 s，约 25.8166 wall seconds / physical second。完整 344 次 native 调用中，导数阶段 wall=64.7014 s、CPU=634.2953 s，热段平均 **9.80 核**。因此不能用 5.98 核整段平均简单判断“10 核配置只用了一半”：串行、调度和记录等段会拉低整段值，而导数热段已经接近给定 10 workers 的并行容量。

F 作业 wall=28.1100 s，CPU=28.7076 s，平均 **1.0213 核**；eval wall=19.1328 s，命令是 **`--workers 1`**。允许 10 个核不表示其中的 Python 矩阵组装和 QP 已经被并行实现。F 与 N 的问题、物理时长和实现也不相同，不能直接用两者 wall 比值声称算法加速。

### 4.1 实际工作量与记录开销

N 的 `calls.jsonl` 全部 344 条独立求和：344 次安装，6880 次 full rollouts，120744 次 transition-FD C API 调用，risk FD=0。120744 是记录的 API 调用次数，每次调用有其内部工作；它不是可直接换成标量扰动样本数的计数。完整候选只在 call 1/121/323 保留。

已发布 N 记录统计：374 个 native 文件＝344 installed+30 key candidates，329,161,888 B；native write、Python write、flush、stream compression、trajectory compression 合计约 2.461 s。相对于 166.92 s eval，当前主要耗时仍在优化和导数，而不是上一轮普通候选环的巨量归档。这个合计不包括所有模型加载、视频渲染、发布与外部 I/O，不能写成“全流程 I/O 只花 2.46 s”。完整 policy binaries 本审计没有逐个解码，因此这些文件计数/写入时长保留为已发布仪表证据，不冒称独立重建。

F 原已发布计时中，模型组 0.7682 s，占 eval 4.0%；full MPC matrix assembly 5.2478 s，占 27.4%；MPC solve 2.6131 s、WBC assembly 0.7555 s、WBC solve 1.6797 s、记录约 0.3428 s。应该依据这些热段决定向量化或并行，不能只因为有 96 GB 显存就扩大没有科学意义的 rollout/FD 数量。

## 5. C 路 GPU 工作的实际资格

C 对旧 W52 的 6152 个已存状态进行一次有限 FP64 比较，并未生成新物理、FD、rollout 或训练。它只覆盖部分几何与 stage matrix 计算；M/h/Jdot、完整稀疏 horizon 组装、MPC/WBC QP、材料动力学、接触积分和 native iLQG/FD 未全迁移。

原记录 CPU 参考总时长 2.223719 s，hybrid 包含 CPU h 前置计算和数据传输后为 1.908132 s；计入初始化为 2.303026 s。速度比分别 1.1654 和 0.9656；单状态首次 GPU 路径约 0.263907 s。**没有建立在线控制器加速收益**。GPU 张量 peak allocated 8,958,464 B、reserved 23,068,672 B，作业 wall 5.8255 s。设备记录为 NVIDIA RTX PRO 6000 Blackwell Server Edition。

模型组与矩阵组装合计占 F eval 31.4433%，不等于本轮 GPU 实现覆盖 31.4433%：其中含有未迁移项，真实覆盖比例为 unknown。不能乘上离线 1.1654 就声称控制器整体有确定加速。CPU/GPU stage matrix 一致也不能验证静态力矩近似正确，更不会消除 F 原矩阵中的结构矛盾。

源：`w53/task-c.json` 及其 Release 原件。此处读取记录和统计，没有重新跑 benchmark。

## 7. 由证据直接支持的下一步优先级

1. **N 与 F 的稳定性原因分开修复，并行推进。** N 保留恢复的运动内核，优先检查接触前落足速度和材料可行性；F 一次性处理真实触地事件、摆动跟踪/anchor、支撑转移、未来脚端计划与动态一致的力矩约束，而不是只修终点 solver exception。
2. **作业预检与实跑解耦。** 零物理初始化错误在任务启动前解决；正式有效物理任务记录实际同时运行的证据，避免两路名称并行而运行时间完全错开。
3. **阶段资格保持原义。** 修复后先让完整 E30 成为实证，再依据原成功门槛走 E60/E300/E600 与第二种子；不能把材料域限值放宽、提前换路线或忽略支撑失效当作提高成功率。
4. **C 路做与热段相符的可复用工作。** 可并行做固定已存状态的数值一致性、稀疏结构/向量化分析与资源审计。只有线上测量说明收益后，才把 GPU 工作写成控制器加速；不为填满显存制造无效实验。

以上是原始证据支持的方向。具体修复清单、工作范围和启动提示词见 W54 主计划；本次审计没有擅自开启后续物理实验，也没有替用户另做本地归档交付。
