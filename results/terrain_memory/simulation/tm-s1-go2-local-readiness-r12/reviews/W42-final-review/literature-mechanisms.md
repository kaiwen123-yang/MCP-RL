# W42：先恢复优化器的有效搜索，再讨论接触探索与 GPU 扩展

日期：2026-11-10。审查基线：`c4b3f9adc698b15de5c94ef952e2884f3abfec62`。本文将本轮原始证据、外部方法事实与本项目设计建议分开；论文中的成功不作为 Go2 材料任务已经解决的证据。此前 HOUND CI-DDP、DiffMJX、DiffContact、SNS-MPC、ROM-guided CI-MPC、ReCo 和 Residual MPC 的讨论保留在 [W41 文献审查](../W41-cpu-review/literature-mechanisms.md)，本次新增七组主要来源。

## 1. 本轮证据改变了方法优先级

**第一优先是正则化与收敛状态的管理；现有结果不足以把四足不动归因于缺少采样、奖励、步态或记忆。** W42 已经实际完成两路各 2048 条新样本、8 次更新，累计各 13713/53。36 个训练回合中，34 个在原有 60 s 采集边界结束，2 个按样本目标截断；结果级技术错误为零。这些回合和两次最终 E30 都没有材料加载或合法材料任务成绩，不能把长时间站立解释为稳定通行。[本轮统计](cpu-summary.json)

两次完整 E30 给出了更早、更具体的机制链：

1. 两路最初 20 次规划都发生在 `t=0`，尚未进入物理推进。plan 1–11 将站立问题的成本从约 5.467 降到 0.0251458，末次实际改善约 `3.68e-9`，正则化已降到 `1e-6`。
2. plan 12–20 在同一个静止问题上连续出现 `no_native_cost_decrease`、`alpha=0`，正则化及其累乘增长率将 λ 推到 `1e6`。第一物理重规划在 0.02 s 已携带最大 λ；Stand→outbound 在 2.002 s 才发生。此后物理重规划持续处于上限。[完整启动序列](cpu-planner-startup.json)
3. A/B 的 4 s 与 29.9 s 176 状态节点/175 控制区间快照中的全部 175 控制节点复算中，约束 active-set 全零。`H` 的对角约为 `1e6 + (0.00065–0.00149)`，而 `max|Qu|` 约 `1.5e-4`，重建前馈步约 `1.5e-10 rad`，最大反馈增益约 `2.0e-7`。这给出了“阻尼占据整个 Hessian，动作改进消失”的直接数值解释；不能凭微小动作或微小预计下降宣布真实任务已经收敛。[矩阵复算](cpu-full-plan-matrices.json)

这条时间链先于去程命令、材料接触与 PPO 的材料学习。r31 的首保持 native 前向误差确有明显改善，但这不自动解决求解器状态跨问题延续的缺陷，也不证明 smooth surrogate 在所有接触状态下提供真实下降方向。当前应先修正这个可定位的问题，再观察是否还存在接触模式探索不足。**解除阻尼锁定后能够迈步、稳定加载、完成往返，均尚未由本轮证明。**

## 2. 与当前问题直接相关的官方实现和新理论

### 2.1 MJPC / Tassa：正则化是局部搜索状态，不是物理安全裕度

[Tassa、Erez、Todorov，IROS 2012 原文](https://roboti.us/lab/papers/TassaIROS12.pdf) §II-C、D、F 解释了控制正则化增大为何令步骤保守、反馈增益趋小，以及接近最优时降低正则化的必要性；其实际/预计下降比较和累乘更新是当前代码的重要来源。这里引用旧文是核查算法来历，不将它计入新论文。

本次同时阅读了 [官方 MJPC planner.cc](https://github.com/google-deepmind/mujoco_mpc/blob/main/mjpc/planners/ilqg/planner.cc) 和 [backward_pass.cc](https://github.com/google-deepmind/mujoco_mpc/blob/main/mjpc/planners/ilqg/backward_pass.cc)。后者 Git blob 为 `3355bf83d9ab82aa747bfcb7312ae7eb6b017981`：`Allocate/Reset` 同时初始化 λ、增长率与增长因子；普通 `OptimizePolicy` 并不每次重新初始化。`UpdateRegularization` 仍按改善比与步长调整 λ。

**不能声称“官方 MJPC 已规定每次控制周期重置 λ”，也不能因代码来自上游就认定当前生命周期正确。** 本项目增加了原生前向、有偏代理导数、完整约束与实际成本接受规则，需要重新明确这些状态在初始化、时间前移与参考变化之间的有效范围。若决定重置或恢复阻尼，应同时处理累乘增长率，不能只写回 λ 而保留此前快速增长的倍率。

### 2.2 Crocoddyl：轨迹 warm start 与 solver 初始化可以分离

[官方 DDP 源码](https://gepettoweb.laas.fr/doc/loco-3d/crocoddyl/devel/doxygen-html/ddp_8cpp_source.html) 的 `solve(init_xs, init_us, ..., init_reg)` 将初始轨迹与初始正则化分别接收，具有独立停止判定与达到最大阻尼后的失败返回。这提供的是状态管理范例：继续使用上一条有用轨迹，不必无条件继承上一问题全部搜索失败状态。

但其停止量和默认阈值不能直接拷贝到当前实现。尤其这里的 tiny step 或 tiny expected decrease 可能由 `λ=1e6` 人为制造；若用它们单独触发“已收敛”，只是把锁定换一个标签。需要区分低阻尼时已没有可分辨改进、QP/分解失败、代理方向不被 native 接受，以及高阻尼压扁动作四种情况。原生方向检查也只能证明所测方向，不能升级成整个非光滑任务的最优性证明。

### 2.3 新增论文 1：iLQR/DDP 的全局与局部收敛，JMLR 2025

**On Global and Local Convergence of Iterative Linear Quadratic Optimization Algorithms for Discrete Time Nonlinear Control**，Roulet 等，JMLR 26(107):1–85，2025。[正式记录](https://www.jmlr.org/papers/v26/22-1271.html)；[原文 §4.2、Algorithm 2](https://www.jmlr.org/papers/volume26/22-1271/22-1271.pdf)；[作者代码](https://github.com/vroulet/ilqc)（GPLv3）。

论文把正则化 iLQR 与广义 Gauss–Newton 联系起来：大阻尼时步骤近似按 `1/ν` 缩放的梯度步；适当让阻尼随当前梯度尺度变化，并以真实目标的充分下降校验，可兼顾远处稳健性和附近收敛速度。其结论依赖光滑性、代价及线性化动力学条件，不覆盖本项目任意接触代理梯度。

**本项目借鉴：** λ 必须服务于当前问题中的有效下降，不能把“数值更保守”当作任务更稳定；测量未被大阻尼除小的残差与原生目标改善。该文没有证明“任意参考变化都应直接设 λ=0”，也没有给出 r31 的稳定保证。

## 4. 两个可执行优先方向

### 首选：保留 r31 物理与学习接口，修复求解器生命周期

此方向只处理已经有明确时间链和矩阵证据的搜索状态问题，优先于增加模型、奖励或动作维度。

- **分离三种状态。** 可继续使用的轨迹/目标、已经验证过的反馈策略、当前问题的 λ/增长率/收敛状态分别维护。后一次问题可使用前一次轨迹作为初值，但不能无条件继承“已无改进”的判定和最大阻尼。
- **明确问题变化。** 初始化完成、物理时间前移、参考/任务阶段或模型身份发生有效变化时，旧问题的停止状态应失效；λ 与增长率如何重建，必须由新的实现/spec 明确。无需宣称每个微小状态变化都必须彻底丢弃轨迹，也不把最小 λ 当作永远正确的答案。
- **正确区分无改进。** 同一静止问题已到数值可分辨极限时，应停止无意义的阻尼升级；真正的非下降方向与 QP 失败仍如实记录。单凭 `alpha=0`、tiny `k` 或 tiny `dV` 不足以判收敛；检查未被阻尼压小的投影/梯度残差，并保留 native 实际代价。对有偏代理，记录“代理停止”与“native 未找到下降”而不冒称真实最优。
- **用已有真实记录验证针对性。** 对本轮初始化尾部和首个 outbound 问题复核修复是否消除 λ 上限继承、是否恢复非零可评价动作，直接服务这个变更；不再建立一串纯 MPC、刚地、smoke 或多轮 2048/8 的前置考试。后续真实联合运行仍必须报告推进、材料接触与合法路线，而非仅报求解器字段正常。

与 r17 的 native 接触开关、r18 的 body-twist 路线、r25 撤回的 MovingSupport/SupportPlacement/support-share 等项均不同：这里不再改物理零阶值，不再添加有利于站立或移动的补偿代价，也不改变 PPO 2 Hz cap 权限。保留 r31 的模型分离、r30 完整 k/K/value、qp2 与现有任务口径。是否足以恢复有效运动，由实际运行决定。

### 条件第二选择：结构化候选 + native 选择 + 可选局部精化

只有当上述修复后仍出现“求解器可动、参考明确要求前进，但持续找不到卸载/抬足/重接触候选”时，才选这条。它可以作为独立 GPU 支线开发，但不能直接替换主线成绩。

1. **在现有关节目标空间构造少量可解释的候选族。** 包括移位后的旧可行轨迹、当前名义轨迹以及低频样条扰动；先覆盖完整的动作变化，避免对每个 0.2 ms 子步独立加噪。若进一步采用相位/足端等低维种子，必须明确其到现有关节目标的映射，而不是悄悄新增学习动作权限或恢复 r25 代价。
2. **每条候选按原执行契约计分。** 同一 native 接触、十子步 PD/饱和、材料状态和原成本/约束。GPU 后端只在已确认其 forward/状态协议适用的范围内用于提议与批量计算；采用的候选仍需与实际部署一致地评价。不同候选的状态/材料恢复历史不能互相串用。
3. **保留实际评价过的赢家。** 样本加权平均可以作为下一轮搜索中心，但它本身也是一条新轨迹，需要重新 rollout；不能将多个不同接触模式平均后直接执行。局部 r31 精化若失败，不能静默覆盖已经有效的候选；安装哪个策略、采用哪种 K、为何采用，都要可追溯。
4. **明确它回答什么。** 若原成本下已有可行且明显下降的推进候选，而纯局部搜索仍停住，才形成搜索范围不足的证据；若各种候选都被原成本排在站立之后，应继续检查成本/参考，而非无限加样本。若预测改善但执行仍偏离，仍应回到前向/执行一致性。

这与简单增大 PPO 样本量不同：当前 PPO 只能调速度 cap，无法修正被最大 λ 消掉的 MPC 动作；W42 的零材料接触轨迹也不适合作为“已学习材料记忆”的证据。候选探索不要求立刻另训练一个生成模型。待真正积累可用加载、跨足与返程轨迹后，再研究学习候选提议或历史检索，才与长期同地块记忆目标衔接。

## 5. CPU/GPU 资源安排如何服务这些问题

建议将并行性用于不同工作：一条真实修复后的联合实验、一条独立对照/机制实现，以及修复 G4/G5 接线后的 GPU 批量候选计算。是否同时开启两条完整 CPU 训练，以实测 CPU 与内存余量为准；不能在同一最大阻尼缺陷上并行积累更多重复站立样本。25 vCPU、96 GB 显存只是资源上限，吞吐、原生目标改善、任务进度才是扩批依据。

GPU 的 176 节点计算完成与完整闭环评价成功是不同里程碑；G4 未进物理、G5 类型异常不能由本节任何论文补成方法成绩。后续批量工作优先服务最耗时的动力学/轨迹评价与候选多样性，QP 迁 GPU 不是当前首要工作。线程、批量数和设备内存由现场可用资源与实际峰值分配；数值迭代预算和物理任务时长保留，**新后台作业不设固定墙钟完成期限**。

论文带来的下一步判断很具体：先修正现有求解器在问题变化后的搜索能力；只有仍缺接触探索时，才增加有结构、可被 native 成本否决的候选。任何一步都以实际合法材料任务评价验收，不把站立时间、显存利用率或训练更新数当作通行能力。
