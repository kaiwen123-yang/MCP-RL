## 1. 结论与当前资格

**原任务层面已有可以冻结、继续实验的稳定基线。** r55 A/B 与 r60 A/B 四条原 E600 均完整观察到 600 s、完成十次合法材料往返并在回家后持续稳定超过 129 s。独立读取四条完整 500 Hz 轨迹得到的全部材料进入、贯穿、返回、加载、侧向退出与圈数，和原评估器一致。这个结论已经超出“视频看起来能走”的程度。

**稳定范围仍然有限。** 它对应原场景、原材料、原路线、冻结 A/B 两个 actor 身份的名义运行；各阶梯从相同身份重置起跑，短阶段与长阶段包含相关前缀。不能把 24 个阶段通过、四条 E600，或十圈往返当成 24/4/40 个独立随机样本，从而宣称普遍成功率或对扰动的鲁棒性。没有本轮新 PPO 学习或新的材料记忆收益证明。

**r60 的主要新成绩是材料接口能够完成长任务及执行效率改善。** 与 r55 配对，E600 完成时间略早，roll/pitch 峰值略低，但两个 actor 的归一化滑移积分都更高，峰值材料应变都更高。因此不宜把 r60 写成整体步态或材料保护性能已经提高。r58 的两次 E300 是计算路径中断；N59 是完成原时长后仍未贯穿材料的任务失败。这三件事不能合并解释成 F 基线仍频繁摔倒。

## 5. r55/r57/r60 的配对性能及材料记忆机会

### 5.1 先固定滑移指标的意义

原结果 `material.integral_slip_sq_s` 是对实际 `Fz>1 N` 的承重足，逐 0.2 ms 累计平均归一化水平球底滑速平方：

\[
J_{slip}=\int \operatorname{mean}_{\mathrm{loaded\ feet}}\left(\frac{\|v_{\mathrm{bottom},xy}\|}{0.25\,\mathrm{m/s}}\right)^2dt.
\]

它是单位为秒的积分代价，不是滑移距离，也并非只统计软材料区域。公式来源 `scripts/s1_go2_joint_material.py` 的 `after_physics`；配对提取来源 `scripts/compare_s1_w56_cap.py`。不能把该值的 0.14 解释成滑了 14 cm。

**对下一轮的直接意义：先验证材料历史的因果进入路径、单步反事实差异及可获得的任务收益，再决定是否训练。** 如果原路线/恢复时间尺度没有强可用信号，单纯增加同一路线长跑或解冻更多参数不会自动得到显著世界记忆收益。改变情景来增加信息量必须作为新实验明确标记，原 S1 基线保持可比较。

来源：`evidence-summary.json.exposure[].{summary,recomputed_grouped_cells,counts_agree,area_agrees}`，原文件映射为 `source`；`observer_q11` 为记录中因果重建观测状态，不冒称未观测材料真值的全状态证明。

## 6. 实际并行、计算成本与 GPU 的合理位置

### 6.1 两条 E600 确实并行，但每条约只使用一个 CPU 核

以下有效区间取原 runner/phase 的实际首个与最后一个物理积分墙钟时刻；不是拿 `resources.jsonl` 的覆盖范围代替物理区间。UTC 时间可据原 Unix 秒无歧义复算。

|E600|实际物理开始 UTC|实际物理结束 UTC|物理区间墙钟 s|整个进程 CPU s / 进程 wall s|平均使用核数|
|---|---|---|---:|---|---:|
|r55 A|11-20 07:15:40.434|11-20 12:31:57.985|18,977.551|21,503.386 / 19,013.989|1.131|
|r55 B|11-20 07:36:51.918|11-20 12:55:56.425|19,144.506|21,780.108 / 19,181.218|1.135|
|r60 A|11-21 05:36:56.173|11-21 09:45:19.680|14,903.508|14,945.326 / 14,941.284|1.0003|
|r60 B|11-21 05:40:22.103|11-21 09:51:54.677|15,092.574|15,128.033 / 15,128.694|1.0000|

r55 双 E600 有效物理区间重叠 **17,706.067 s = 4.918 h**；r60 双 E600 重叠 **14,697.577 s = 4.083 h**。W56 全部任务有效物理区间中，双物理重叠 **59,996.406 s = 16.666 h**，最多同时两条重物理。r58 中断任务的区间截止于最后持久化 MPC 写入，不把之后空挂时间当有效推进。该区间口径仍是任务从首末推进证据界定的活动包络，不等价于逐微秒 CPU 连续算术忙碌。

W56 所有实际进程合计 **170,942.176 CPU-s =47.484 核时**，包括中断前后的进程 CPU；其中中断两进程占 **76,570.353 CPU-s**。这说明技术停滞确实消耗了大量本轮时间。N59 整进程平均约 **3.889 核**，10 workers 是上限/配置，不是恒定吃满 10 核。

`resources.jsonl` 的相邻同 PID 集合快照差分也与 F 近单核一致：r60 A/B 区间核使用中位数 **1.00068/1.00062**，p95 **1.00271/1.00270**；两进程峰值 RSS 约 **4.114/4.123 GiB**。这是整个采样覆盖中的进程树区间统计，没有独立隔离“纯求解热段”。没有整台机器其他任务的完整指标，因此不能断言其余 23 核在整个区间全部空闲。

**allocation ≠ usage：** 设置 25 核配额、线程 affinity、worker 数或准备三条任务，不会自动并行化每条 F 的依赖链。已有证据支持“两条真实机器人任务 + 一条有限材料批计算”并行；要进一步利用 CPU/GPU，应把独立候选/保存状态/批量历史做成有效批次并记录实际吞吐，不能只靠加配额或复制无信息任务。

来源：`evidence-summary.json.{e600_actual_intervals,overlap,counts,attempts[].process_cpu_s,attempts[].process_wall_s}`；`evidence-resources.json` 与可复算脚本 `evidence_recompute_resources.py`；原 `R/w56/phase.json` 和逐任务 `stage_record`。两个重物理加材料线的独立已有测量重叠 **16.014904 s**，直接 CPU/GPU 测量与双原机器人物理区间重叠 **14.591742 s**，见 `two_physics_plus_material_measurements`。

### 6.2 r60 比 r58 快很多，仍非实时

匹配 r58/r60 原 E60，物理区间墙钟 A **10,417.840→1,300.463 s**，约 **8.011×**；B **9,773.621→1,340.257 s**，约 **7.292×**。这是相同窗口/法向参考的 CPU 后端替换对照，比直接把 r55 与 r60 的全部差值当作后端收益更合适。

r60 全 E600 `result.wall_s` A/B 为 **14,908.957/15,097.992 s**，约每 1 s 仿真用 **24.85/25.16 s 墙钟**。四条 E600 的全部 feedback 计数均超过原 2 ms 性能预算；r60 feedback 中位数 **3.772/3.781 ms**，p95 **52.437/52.404 ms**。这里的 deadline miss 是性能统计，不是后台到点终止；当前是稳定的非实时仿真基线，不能宣传成硬件实时 500 Hz 控制已经完成。

来源：`evidence-summary.json.pair_arithmetic[].r58_r60_physics_wall` 与 `r60_physics_speedup`；`attempts[].{wall_s,timing}`；`evidence-arrays.json.cases.*.feedback_ms`。所有新 runner 记录的 `deadline=null`、`wall_deadline_enabled=false`、`kill_on_conversation_end=false`，原物理任务时长与原失败判据仍有效。

### 6.3 96 GB 显存应服务独立批次，不应强行塞入单序列在线路径

本轮直接单次调用测量，输入已经装配好，计入 native binding、分配、H2D、材料内核、D2H 和同步；cold 包含相应上下文初始化。每个条件只有一份冷/热样本，不能外推成稳定延迟分布。

|真实历史工作量|CPU 冷/热 s|GPU 冷/热 s|热调用比较|
|---|---|---|---|
|1 条历史 ×600 步|0.027948 / 0.021993|1.142547 / 0.827288|GPU 约慢 37.6×|
|174 条不同真实历史 ×600 步|1.854884 / 1.871800|1.317944 / 1.074801|GPU 约快 1.742×|

这是已知同输入 FP64 材料路径的直接测量，不能说 GPU 一律没用，也不能说完整 MPC/WBC 已迁移至 GPU。单条历史串行时间推进不适合靠大显存解决；独立历史批次已经显示吞吐收益，可作为第三计算线。GPU 优化离线实现的差分/内核与正式 r60 CPU central-FD 路径仍需区分。

来源：`R/w56/c/cpu-gpu-direct-single-launch.json` 的 `calls`、`samples_per_temperature_and_workload`、`results.{single,batch}.{cpu,gpu,warm_second_call_cpu_over_gpu}`；该文件逐调用给出原输入 SHA256 与一致性误差。

## 8. 对下一轮计划的证据约束

1. 用 r55 与 r60 的已完成双 E600 作为明确、可追溯的基线；后续每项改动都说明它解决“当前步态质量、材料历史效应还是计算吞吐”中的哪一项，不再把“先能走”无限重复当作尚未完成的目标。
2. 步态质量的优先可查问题是触地后的毫米级回弹、实际承重建立/卸载和对角支撑交接；四条名义任务未倒下不等于这些问题不存在，但也不能靠它们重新宣称整个基线不稳定。
3. 材料世界历史的主要未闭环处是历史输入如何改变可执行预测、规划/控制和最终任务收益。当前同圈短时间跨足恢复信号比约 48 s 的跨圈信号强得多；下一步应围绕有信号的严格反事实，而非把重复圈数当作记忆有效性的替代指标。
4. 优先保留已经完成长任务的在线 CPU 材料路径，把有吞吐证据的 GPU 独立批计算放在第三线；用真实进程 CPU/wall 和实际重叠考核并行，不用 worker/affinity/显存预留量冒充利用率。
5. 继续保留 `deadline=null` 的后台语义；原物理任务长度、失败条件和明确技术故障处理仍执行。发布到 GitHub 后以 commit/Release 回执收尾，不再在用户电脑增加归档步骤。

这些建议基于已经保存的证据，不代表下一轮实验已经实施或科学主张已经得到证明。
