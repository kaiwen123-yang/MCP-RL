# W55 对 W54 原任务、视频、资源与 GPU 结果的独立证据审查

基准：仓库提交 `1ae25272c86f551f8c6b3a65073bc05b24e3d8f6`。本审查读取 W54 已发生的实验，未启动新物理步、模型有限差分、rollout、QP 求解或训练。用 NumPy 对已经保存的完整数值流重新计算；对保存速度求时间差分属于日志分析，不产生新模型评估。

## 2. F 最重要的新定位：运动学偏差在硬地就已累积

### 2.1 真实受载时序先排除错误归因

F r45/r46/r47/r49/r50 的全部实际材料力均为零。特别是 r46、r47 已在硬地 body_fall；r49 在从未材料受载的情况下明显降高后控制中断。不能把这些失败归为材料应力预测或材料冻结训练不足。

F r51、r52 都在 **4.880 s** 首次低于 z=0.28 m，在约 4.920 s 低于 0.27 m；材料首次承载分别是 **5.3196、5.3250 s**。即明显降高比实际材料力早约 **0.440/0.445 s**。r52 在首次材料接触前，实际全足 Fz 均不超过 1 N 的时长为 **0**，所以“所有脚同时离地”也不能独自解释该段高度损失。

这条时序只说明受载后材料误差不是这些硬地现象的必要前提；不能仅凭时序断言 PANN 的速度指令、静态先验等所有通道都无关。材料 PANN 和冻结问题另有专项审计，应避免将它与已定位的控制运动学问题合并成同一原因。

### 2.2 对 `mj_jacDot` 缺项进行了第二份独立验证

控制源码审查定位到固定 MuJoCo 3.2.3 的 `mj_jacDot` 缺项，官方后续修复见 [MuJoCo commit de48f417](https://github.com/google-deepmind/mujoco/commit/de48f4178f971d945fc135afb42699b8ca6bec8e)。本证据分支没有依赖“版本旧所以可能有 bug”的猜测，而是从当前 r51/r52 保存数据独立验证缺少的缩并项：

`missing = foot_angular_velocity_world × foot_velocity_world`。

先验证 5 kHz physical 每十个子步处的足速度，与 500 Hz trajectory 足速度及 control 足速度一致；前两者逐元素差为 0。然后在每个已保存 MPC Jacobian 的时刻，构造：

`kinematic_error = actual_foot_acceleration − saved_foot_acceleration_achieved − J × (actual_qacc − saved_qacc)`。

这样先排除了实际广义加速度与 WBC 期望不一致的影响，主要检查 `Jdot × qvel` 的运动学恒等式。检查只取 **2.002≤t<4.880 s** 的摆动足，F r51 为 160 个足×时刻样本，F r52 为 162 个；此时两个任务还没有真实材料承载。

| 已保存速度的差分方式 | r51 原误差 RMS | r51 加入缺项后 RMS | r52 原误差 RMS | r52 加入缺项后 RMS |
|---|---:|---:|---:|---:|
| 前向差分，t 到 t+2 ms | 2.579192 | 0.130975 | 2.609765 | 0.127848 |
| 中心差分，t−2 ms 到 t+2 ms | 2.565798 | 0.009796 | 2.594999 | 0.009986 |

单位均为 m/s²，RMS 对全部样本的 XYZ 分量求均方再开方，不是向量范数 RMS。两种差分方法都支持同一缺项；中心差分减少离散截断误差，因此数值更小，不能将两行随意混用。中心差分下，缺项与原残差的展平相关系数分别为 0.9999925 和 0.9999928。r52 竖直平均残差从 +2.351867 m/s² 降为 −0.000411 m/s²。

这为“摆足加速度模型存在确定缺项，应该先修”提供了很强的记录内证据，优先级高于盲目改跟踪 gain 或加新训练。**它尚未证明修复后 QP、接触转移和整个原任务一定成功**：本次没有重新求修复后的控制量，也没有跑修复闭环。图 `w54-jacdot-crosscheck.png` 左侧展示 r52 原竖直误差与缺项随时间重合，右侧明确区分两版本中心差分 RMS。

### 2.3 F r50 的 30 s 稳定停留不等于稳定行走

r50 前 2.002–4.000 s 的平均 vx=0.18273 m/s，确实能够向前走；但约 5 s 后大部分时间停在 x≈0.60–0.62 m，末态 x≈0.598 m，最大 x=0.623944 m。最后一秒平均实际 vx 只有 **0.000774 m/s**，而 command vx 仍为 **0.222323 m/s**。没有材料力、没有材料单元承载、没有回程。完整 30 s 未摔倒是支撑保持方面的进步，但走路与任务进度发生停滞，不能作为 E30 成功。

独立完整控制流中的零支撑时长为 0；具体 load-bearing 状态机死锁与 preload 更改见控制审计。图 `w54-r50-stall.png` 保留整个 30 s，不裁掉后 25 s 来制造持续移动的印象。

## 3. N：材料域限制有改善，但稳定承载并没有随之成立

### 3.1 r44 比 W53 多走了一段，原材料域问题仍在

W53 N r42 停在 6.4656 s、x=0.72384 m；r44 停在 7.0058 s、x=0.86483 m。r44 已建立运动的 3.0000–5.9336 s 硬地窗口平均 vx=0.20645 m/s，z=0.28179–0.30405 m。真实材料暴露从 5.9336 s 到终止共 **1.0722 s**，比 W53 的 0.4382 s 更长。

r44 E 第一次在 **5.538 s** 活跃，共 306 个控制 tick。但它仍在材料候选更新时越域：最后已施加状态的最大应变为 **0.0188723**，拒绝的候选最大应变 **0.0217453**。FL 最大已施加材料 Fz=1102.595 N，候选 1292.854 N 从未施加。不能把候选评估记录当成实际越限力，也不能因终止机身仍有 0.2727 m 高度而忽略材料失败。

### 3.2 r48 让四足都遇到材料，足端域内不代表整机可行

r48 首次真实材料力为 **5.8968 s**，E 首次活跃为 **5.864 s**，共 710 tick；E 确实参与执行。各足首次材料承载分别为 FR=5.8968、FL=6.6584、RL=7.1166、RR=7.1372 s。材料暴露达到 **2.4600 s**，最大应变 **0.013724**，未发生材料域拒绝。

但实际运动在材料区变得更差：首次非足承载 **6.9074 s**，非足合力峰 1217.225 N，z<0.25 m 为 7.302 s，终止为 8.3568 s 的 floor–trunk 非法接触。整个移动段没有任何足 Fz>1 N 的时间是 **1.0646 s**；其中材料暴露后 **1.0514 s，占该段 42.74%**，最长连续 55 ms。最后一秒无足承载比例为 56.9%。因此不能用“x 到了 1.312 m、材料域不再退出”推断已稳定行走。

记录中有 301 个曾承载 cell、1365 次 cell revisit，其中 **12 次跨足 cell revisit**，首次在 **7.5550 s**。这是相比 W53/r44 的实际覆盖进步，但 12 是单元事件数量，不是 12 次完整步态/回程试验，也不是 12 次独立材料记忆收益验证。所有任务始终只到 outbound，没有完整材料穿越/返回。

r48 材料之前 3.0000–5.8968 s 的 z=0.28450–0.30176 m、vx 持续为正；本轮明确的持续支撑损失主要发生在材料暴露后。不能把 F 的“硬地已出问题”时间结论原样套给 N。对 N 足端投影、自由浮基近似、接触支撑耦合与软成本的责任分解，仍需控制源码及被选轨迹审查。本证据分支没有逐个解码所有 native `.bin`，不独立声称已验证每个预测候选。

图 `w54-material-and-support.png` 将 r48 的支撑数、实际非足力与域内应变，和 F r52 的材料前降高放在同一张图内，避免把两个失败机制混为一谈。

## 4. 并行运行与资源：只有一个有效双物理重叠窗口

从每次结果的 `physical_started_unix_s`、`physical_ended_unix_s` 重新求区间交集。这一时钟在第一次/最后一次实际 `mj_step` 前后记录，因此代表有效物理任务活跃窗口，包含期间正常控制计算，不是把物理模拟秒当作墙钟秒。

唯一双物理窗口是 **N r44 与 F r46**，重叠 **41.132414 s**；三个物理任务并行时长为 0。C r46-corrective 的 3.225545 s 与 N r44 重叠，但此时 F r46 已结束，因此也未形成 N+F+C 三路重叠。其余四个 C 批次没有与有效物理窗口重叠。

九个物理窗口的并集为 1066.215726 s；第一有效物理开始到最后结束的墙钟跨度 3951.526285 s。跨度中包含修改、分析、准备及任务间隔，不可据此把整个服务器其余时间直接算成空闲；记录还显示有未触碰的其他项目训练。应报告本项目真实重叠，而不是把 affinity 分区当作已经利用 25 核的证据。

| 版本 | stage wall / s | user+system CPU / s | 全 stage 平均核 | 实际 workers |
|---|---:|---:|---:|---:|
| N r44 | 271.794 | 1673.916 | 6.159 | 10 |
| N r48 | 373.693 | 2017.927 | 5.400 | 10 |
| F r50 | 264.106 | 264.995 | 1.003 | 1 |
| F r52 | 67.712 | 68.905 | 1.018 | 1 |

全部九任务 CPU 合计 **4263.539333 s（1.184316 h）**。完整原始 `/proc` 资源流已读，单任务 root PID 一致；N 的采样峰 RSS 约 5.08/5.17 GB，F 约 2.02–2.79 GB。不能从这些记录得出整个 GPU 或整台机器没有其他用户负载。

N 导数热段的 CPU/wall 比分别约 **9.74、9.77 核**，接近10 workers容量。整 stage 平均较低包含串行/调度/记录段；不能据 5.4 核全段平均简单判定 native 导数只用了一半。F 的 workers 始终为 1，扩大 affinity 并不会自动并行化 Python 组装或当前 QP。

后续可以把修复后的独立 N/F 原任务实际同时启动，第三路做已有加载路径上的材料模型核查和必要的 GPU 训练；需要用真实 PID 和有效窗口证明并行。保持无 wall deadline，不应为了持续占满资源，在同一个未解根因上重复制造更多种子或放大 FD 网格。

### 4.1 FD 工作量的字段含义变了

N r44 有 371 次安装、7420 次 full rollouts；r48 有 438 次安装、8760 次 full rollouts。r48 选择来源为 action_rollout=430、current_reassessed_nominal=8，backward failures=0；r44 旧日志没有 selection_source 字段，不能将缺失误记为零。

W53 的 `transition_fd_calls` 公式是 `2*(horizon−1)+1=351`，属于 API 层口径；W54 r44/r48 的 patch 改成 `(horizon−1)*(1+state_derivative_dimension+action_dimension)+(1+state_derivative_dimension)=8612` 次已定义函数评估/每调用。故 r44 的 3,195,052 与 r48 的 3,772,056 **不能直接除以 W53 的 120,744，声称 FD 工作暴增数十倍**。两种字段名字相同但计数对象不同。该变化可在 `experiments/terrain_memory/{w53_n_records,w54_n_records,w54_n_records_r48}.inc` 直接看到。

当前 stream/trajectory 压缩写入报告分别约为 N r44 2.165 s、N r48 2.548 s、F r50 4.603 s、F r52 0.820 s，远小于相应 eval wall。它们不是完整 I/O 总开销，也不包含所有 native 记录、渲染、发布；但现有证据不支持把主要不稳定性归因于日志归档耗时。

## 5. GPU：本轮已经做到完整 SRB 力序列优化，离在线控制资格仍有距离

这轮 C 相比 W53 的部分 stage matrix 比较有实质进步：执行了 **14 个节点×4 足×3 方向** 的独立力变量、完整状态代价、力正则、力差正则与接触摩擦投影，用 JAX FP64 做固定 4096 次加速投影梯度迭代，并与同问题 OSQP FP64 参考解对照。

本审计从全部 **306 个已保存 horizon** 的输入、GPU/CPU 状态与力重新做递推、代价和摩擦检查，没有重新求解优化问题。历史批次和当前输入/摩擦合同必须分开：

| 已存批次 | horizons | 最大相对目标差 | GPU 原物理圆锥最大违约 / N | CPU assembly+solve / s | GPU warm含传输 / s | GPU含初始化编译 / s |
|---|---:|---:|---:|---:|---:|---:|
| legacy Stand | 98 | 1.4211e−6 | 0 | 3.8311 | 0.5182 | 2.7516 |
| natural r45 | 160 | 7.9150e−4 | 16.4071 | 7.0733 | 9.5596 | 11.5261 |
| r46 corrective | 16 | 1.6206e−4 | 11.4407 | 0.7150 | 0.3898 | 2.3430 |
| r49 final | 16 | 1.9296e−4 | 0.3070 | 0.6961 | 0.3895 | 2.1767 |
| **r52 inner friction，当前** | **16** | **1.3415e−4** | **0** | **0.6659** | **0.3508** | **2.1720** |

历史四面外接摩擦方锥中的可行力可能超出原 `mu=0.5` 圆锥；不能把历史“QP feasible”写成物理摩擦已满足，也不能合并 306 个样本宣称最新 r52 已有 306 例资格。最新 r52 使用内接方锥 axis slope=`0.5/sqrt(2)`，16 例原圆锥检查均通过；CPU 参考最大圆锥残差约 4.55e−8 N。最大第一步力差为 **0.16281 N**，完整目标相对差约 **0.0134%**。

当前 16 例 GPU warm路径含同步/传输约0.35078 s，相比 CPU assembly+solve 0.66593 s 的批次比值约 **1.90 倍**；但含初始化/编译后GPU为2.17198 s，约为CPU的 **3.26倍耗时**。CPU 和 GPU 的算法/迭代预算不相同；这是该固定离线批次的质量与耗时证据，不是普遍硬件加速比。把16个问题的批次时间除以16，只得到摊销吞吐，不是单步闭环时延。

最新 r52 GPU peak JAX bytes 为 **34,174,464 B，约32.6 MiB**。尚未覆盖完整关节 WBC、未来关节轨迹、材料动力学、真实 plant 或在线控制器安装。因此有推进 GPU 求解器的价值，但它不会自动补上 CPU 动力学/运动学合同错误，更不能用“显存有96 GB”直接推导应开更大的无效训练。

计时值来自保存的已执行仪表；独立重算的是数值质量和约束，不把再次计算日志的时间包装为原 GPU benchmark。完整每例复算在 `gpu-evidence.json`，紧凑发布用 `evidence-summary.json:GPU_batches`。

## 6. 视频、哈希与读取范围

下载通过 16 个 ZIP 的 HTTP 合并 byte ranges 选择提取：**4093 个成员，解压后572,690,041 B，实际下载range529,113,570 B**。每个提取成员都显式验证大小，并用 `hashlib.sha256` 与发布 `sources.json` 中该成员 SHA-256 匹配，4093/4093 通过。**未完整获取ZIP，故没有宣称整包SHA-256验证**；所有 native `.bin` 和 `model.mjb` 均未提取，也未重跑模型。下载器为 `fetch_w54_originals.py`，完整原件清单保存在临时审计 `original-ledger.json`，无需再推送大包。

九段原视频全部解码，共 **2314帧**：F r45=125、N r44=212、F r46=140、F r47=145、F r49=182、F r50=901、N r48=252、F r51=188、F r52=169。主审已经逐张查看全部九张按时序 overview，并查看 N r48/F r52/F r50 最后完整 overlay 帧；本证据代理独立查看这三张 overview 与三个完整末帧。

overview常规2 Hz，失败末秒约10 Hz；r50前6秒较密、后段5秒间隔。**全部解码覆盖与视觉抽样覆盖分别记账**，不声称2314帧逐帧人工观看。每张图的实际帧索引和原视频元信息见 `video/manifest.json`。例如N r48最后编码位置约8.3667 s，但overlay/plant终点8.3568 s；不能把视频编码帧时长当作额外仿真时间。高频接触和1ms级错误都以完整5kHz数组为准，视频仅支持姿态和事件顺序判断。

为了避免重复原件，建议只发布三张核心 overview（N r48/F r52/F r50）、完整视频manifest、紧凑统计、必要曲线/交叉验证图和复算脚本；完整视频继续引用已有Release资产。

## 7. 证据支持的下一步

F 当前有明确、可复核的运动学缺项，先修并用同一保存状态核查身份、坐标和 `Jdot*qvel`，再进入原任务闭环验证；先不要用 gain、摩擦限值、材料参数、PANN重训掩盖该项。保留 forward 与 central 日志验证两种口径，闭环结果单独记录。

N 应保留“材料应变进入域内”的进步，同时把非足承载、实际支持足、机身高度和材料接触耦合列为同时满足的条件。r48的数据证明材料单元已真实承载和跨足重访，但不能证明材料记忆收益，也不能证明只是调整一个法向阈值即可稳定。

PANN冻结是否过早需要独立分析辨识误差、受载历史与控制器实际使用通道。本报告已经建立哪些任务未材料受载、哪些错误先于受载的边界；对N的材料后失败和F的硬地运动学缺项应分别验证，不从一次失败直接要求整体重训。

两条修复路可以真正并行，第三路使用已有真实加载历史做 PANN/材料适用域核查与必要的定向 GPU 训练。后续仍应保留原任务标准和原材料域，不设置后台wall deadline、不制造本机归档副本，也不以停住30秒替代行走完成。
