# W54 执行结果的控制审查：W55 优先级与可实施修复边界

审查对象：MCP-RL `1ae25272c86f551f8c6b3a65073bc05b24e3d8f6`，相对 W54 计划提交 `df07c4bb690f831745879af3a86800c2c3ec427d`。本审查阅读 F r45→r52 的控制代码与版本修订、N r44/r48 的 E 算子和 native 接入、C 的完整 GPU 力时域优化，以及同次保存的控制/预测/物理/轨迹数组。原始包由独立证据审查统一下载并验证。

本审查没有运行 MuJoCo、物理步、native rollout、模型/transition FD、QP、训练；计算仅使用已保存数组和 XML。没有修改仓库或发布内容。

## 1. 优先结论

**F 当前最有把握的首修项已从“可能的接触/权重不匹配”，收敛到一个可定位到官方源代码的运动学缺项：冻结的 MuJoCo 3.2.3 的 `mj_jacDot` 平移部分漏掉了点的运动项。** F 的足心加速度、逐 body COM 加速度和由足心构成的 rolling 加速度都调用了受影响的接口。官方在 MuJoCo 3.3.1 修复了它。保持当前 plant 和所有实验协议不变，在控制计算中补齐此项即可处理这个已确认错误；不需要先把整个工程升级到新版 MuJoCo。

该结论同时有三层相互独立的证据：

1. 官方修复 commit 明确指出并给出缺失项，旧版源码与当前调用相符。
2. 保存的足速度、广义速度和 Jacobian 可以直接复核运动学恒等式。用同一段轨迹的中心差分后，r52 摆动足误差 RMS 从 **2.5950 降至 0.00999 m/s²**，r51 从 **2.5658 降至 0.00980 m/s²**；缺项与原残差的相关系数均大于 **0.999992**。
3. 最早数步之后逐渐增大的落足高度和落足迟延与这一误差同在材料接触前出现；不能把 F 的前段失稳归咎于 PANN 材料预测冻结。

这不是已经证明“补一个公式必定完整完成任务”。我们没有重解修后 WBC，也没有新物理轨迹；接触力实现、有限 hold、浮基预测仍有剩余误差。正确次序是：**把这个确定错误在所有受影响控制调用中一次修完整，保留 r52 已正确的组修，再直接走原始任务 E30；用新的首因决定是否追加因果顺应接触模型。** 在此之前全面重写接触层，会把已隔离的运动学错误和尚未隔离的接触误差混在一起。

N 不受同一 `mj_jacDot` 问题影响：r48 的法向 `Jdotv` 来自对随配置更新的 `mj_jacGeom` 的中心方向差分。N 当前更具体的问题是 E 的可用制动和总加速度使用**无支撑反力的自由浮基响应**，却可同时大幅改变已承载支撑腿的力矩；候选可行性又只看材料脚法向间隙，缺全身恢复能力。

C 已完成同一 SRB 力时域问题的 GPU 优化及独立 CPU 验算。它不包含 WBC 和材料动力学，也未在线安装。W55 不应为展示 GPU 利用率而重复这个已经完成的 16 状态任务。

## 3. 确定错误：`mj_jacDot` 平移部分缺运动点项

### 3.1 上游依据与补丁公式

官方修复：

- MuJoCo 3.3.1 changelog：<https://mujoco.readthedocs.io/en/stable/changelog.html>
- commit `de48f4178f971d945fc135afb42699b8ca6bec8e`：<https://github.com/google-deepmind/mujoco/commit/de48f4178f971d945fc135afb42699b8ca6bec8e>
- 对照旧版：`google-deepmind/mujoco`, tag `3.2.3`, `src/engine/engine_support.c` 的 `mj_jacDot`。

官方修复在每个 DOF 的平移 Jacobian 时间导数中加入 `cross(cdof_angular, point_velocity)`。与当前广义速度相乘后，可在控制层直接写为：

\[
(\dot J_p v)_{correct}=(\dot J_p v)_{3.2.3}+\omega_{body,world}\times v_{point,world}.
\]

也可以补完整矩阵 `ΔJdot_p = -skew(v_point_world) @ J_omega_world`；当前 F 只消费 `Jdotv`，直接修正收缩量更小。`omega` 必须是该点所属刚体的世界系角速度，`v_point` 必须是**同一几何点**的世界系线速度。不能把世界角速度与 body/local 线速度混用。

适用边界：这里明确针对工程冻结的 **3.2.3**。3.3.1 及已包含官方修复的构建不能再加一次。应在控制 helper 的版本/实现声明中把“使用旧接口 + 控制补项”写清楚，避免未来升级时双重修正；不需要把此事扩张成新的全库 hash/smoke 矩阵。

### 3.2 当前 F 的所有调用点

下列行号针对审查提交的 `scripts/s1_w54_f_r52_backend.py`。

| 调用/输出 | 代码范围 | 处理 |
|---|---|---|
| 每个足心 `mj_jacGeom`、平移 `mj_jacDot`、输出 `Jdotv` | 191–194，210–211 | 加该足 body 世界角速度 × 足心世界线速度 |
| 逐 body COM `data.xipos[b]` 的平移 `mj_jacDot`，再质量平均为 `Jcomdotv` | 195–204，212 | **先逐 body 加** `ω_b × v_COM,b`，再乘 `mass_b / total_mass` 汇总；不能只加根机身 `ω × v_subtreeCOM` |
| 根机身 angular `Jr/Jrdotv` | 205–207，213 | 官方缺项在平移部分；angular 项不加本补丁 |
| 足 body angular `Jomega/Jomegadot` | 219–226，242 | 同样不加平移补项 |
| 球足 rolling `Jroll/Jrolldotv` | 214–218，240–241 | 使用已经修好的足心 `Jdotv`，再减 `skew(r) @ Jomega_dot_v`；不额外添加第二个“材料点向心加速度” |
| 当前实际接触点 `Jforce` | 227–239 | 此处调用 `mj_jac` 而非 `mj_jacDot`，不属于本 bug |

平地 rolling 中 `r=[0,0,-radius]` 是世界固定方向，所以代码对 `v_contact=v_center+ω×r` 的导数结构本身合理。此次修正的是它输入的足心加速度漂移项，不是推翻 r47 的球足模型。

### 3.3 不是缺少 `mj_comVel` 处理阶段

官方 3.2.3 API 文档要求在调用前完成 kinematics、comPos、comVel。`scripts/s1_go2_r11_runtime.py` 的控制循环在约 502 行先调用 `mujoco.mj_forward(model,data)`，之后才进入 F update；F 的 `model_quantities` 前未改写 qpos/qvel。这一完整 forward 已覆盖所需阶段。因此，现有证据没有显示 F 在这里漏了速度缓存更新。不能把已确认的上游缺项写成“再多调用一次 forward 就能修好”。

N r48 的 `W54NormalJdotV` / Python 同构实现则先作 `q±εv`、重算 kinematics/comPos 和同一足心 Jacobian，再恢复原 q；它没有使用这个有缺项的接口，不能重复加 `ω×v`。

## 4. 保存数据如何把该缺项与接触动力学分开

如果只比较 QP 的 `qacc` 与实测加速度，接触力、摩擦、hold 都会混入。这里使用已保存的**实际广义速度变化**，把动力学模型差异剔除后检查运动学恒等式：

\[
e_{kin}=D_t v_{foot}-a_{foot,QP}^{old}-J_{saved}(D_t v_{gen}-qacc_{QP}).
\]

因 `a_foot,QP^old=J_saved qacc_QP+Jdotv_old`，上式就是 `D_t v_foot − J_saved D_t v_gen − Jdotv_old`。它不用假设 QP 的 qacc、实际接触力或执行力矩正确。

我们将 `e_kin` 与保存的 `foot_angular_velocity × foot_velocity` 对照。原件的 5 kHz 物理足速度按每十行采样，与 500 Hz 轨迹足速度逐元素完全一致；时钟对齐也一致。独立证据 agent 从物理流重写了相同计算，并进一步用 ±2 ms 轨迹中心差分减少有限时间离散误差。

范围：`2.002 ≤ t < 4.88 s`，只取已保存同次 MPC Jacobian 时刻的摆动脚；r51 有 160 个 foot×time 点，r52 有 162 个。该时间段在材料首次受力前。

| 数据/导数口径 | 原运动学残差 RMS | 加缺项后 RMS | 缺项与原残差相关 |
|---|---:|---:|---:|
| r51，前向 2 ms | 2.579192 | 0.130975 | 0.998644 |
| r51，中心 ±2 ms | 2.565798 | 0.009796 | 0.9999925 |
| r52，前向 2 ms | 2.609765 | 0.127848 | 0.998746 |
| r52，中心 ±2 ms | 2.594999 | 0.009986 | 0.9999928 |

单位为 m/s²，RMS 对所有保留点的 xyz 分量计算，不是三个方向范数再平均。改善到百分之一量级且在两个版本复现，是漏项的强证据。

例如 r52 `t=4.740 s`、FL 足，中心差分得到的原竖直运动学残差为 **15.8245 m/s²**，缺项的竖直量为 **15.8613 m/s²**，补后约 **−0.0368 m/s²**。这远大于同一时刻 QP 报出的任务残差；`feet_acceleration_achieved` 本身是用错误 Jdot 计算的**模型输出**，不能当作实测足加速度。

另一个较弱但更贴近执行的对照，是不修改旧 QP 的 qacc，只把旧预测的足加速度补上该项，再与实际速度差分比较：

| r52 摆动区间 | 旧预测与实际 RMS | 仅补缺项后的 RMS | 竖直误差均值：旧→补后 |
|---|---:|---:|---:|
| 2.052–2.252 s | 0.6748 | 0.6062 | +0.0830→+0.0794 |
| 2.254–4.680 s | 1.9601 | 0.7062 | +1.7581→−0.0474 |
| 4.680–4.880 s | 6.0670 | 1.3936 | +7.6147→−0.5273 |

这里未消除实际 qacc 与旧 QP qacc 的差，因此补后有明显剩余是正常的。最初低速一步受该项影响小，后来越来越显著，解释了为何有些启动/首步测试看不出来，却在后续速度和姿态变化后不断迟落足。

### 与其他候选解释的关系

- r52 材料首次受力在 5.325 s；机身降到 0.28 m 以下在 4.880 s，低于 0.27 m 在约 4.92 s。r51 也有相同顺序。因此此前的摆动/身体下降不是由材料本构首先触发。
- r52 在材料前没有所有脚都失去 >1 N 支撑的片段。不能把机身下降全部解释成“全脚离地”。
- r50 起加入的 hold 均值模型有实际价值。r52 材料前若干窗口中，实测十子步均值力矩与解中 `tau_mean` 的差通常约 0.012–0.018 Nm RMS，4.68–4.88 s 约 0.032 Nm；它不是上述十余 m/s² 运动学漏项的替代解释。
- XML 干摩擦、有限 hold、接触力方向/反力实现仍有剩余模型误差；现有数组代数无法把每个剩余项精确隔离成独立因果贡献。
- 仓库已有 `f-r51-rigid-closure-evidence.json`：持续承载安静支撑子集的 actual-vs-model 约束误差远小于摆动足的上述漂移。不能仅因 WBC 采用加权 stance task，就断言改成所有足硬等式一定是当前主修。

## 5. F 的最小完整 W55 实施包

### 首包，立即可实施且不依赖 N/PANN 完成

1. 基于 r52 建新修订，集中定义旧版 `mj_jacDot` 平移修正 helper；足心、逐 body COM 以及 rolling 下游一次接全。angular Jdot 不变。
2. 继续保存 old/raw Jdotv、missing term、corrected Jdotv 或足够还原它们的字段，让下一个真实 run 能直接区分模型量和实测量；无需新增昂贵的全库验证矩阵。
3. 保留 r52 的实际接触可用性、touchdown anchor、负载 transfer/preload、未来落点、优化机身参考、hold 约束、真实摩擦锥和原 PD。不要同时另调一组摆动增益掩盖本次错误是否消失。
4. 必要验证只针对这次公式和接口：当前状态上确认 foot/COM 的世界坐标系和 helper 调用完整；在代表性保存状态或当前状态验证相同运动学恒等式。已有纯数组复算已经提供很强先验，不要重新排一长串启动 smoke 作为实跑前置。
5. 首次组修完成后直接进入原始 E30，保留原站立→前进→转弯→返回→终站目标、速度/距离、原 plant、材料、PD、力矩界和结束判定。F 不等待 N 大改或 PANN 分支。

需要读出的验收是：相同动力学状态下运动学恒等式恢复；真实摆动跟踪误差和每步迟延不再单调放大；承载 transfer 有持续进展；机身高度/姿态在到材料前稳定；随后进入材料的足法向速度、载荷、变形和任务进度有同次日志与视频支持。仅“solver solved”“QP任务残差低”“30 s 未倒”不足以通过。

### 仅在修后证据仍指向接触实现时，追加同轮顺应层

F 目前对材料 stance 的处理是一个当前刚度/载荷下的脚高偏置，未来 SRB 仍把 GRF 当独立变量。它还没有把材料变形状态、触地速度、载荷增长与机身运动放在同一个因果时域内。若 corrected kinematics 后，短时实际接触力和足/机身加速度仍显示同源系统差异，适合在**保留现有接口**的情况下补：

- 按脚维护或显式传入当前因果压入/恢复状态及法向速度，不读取未来/隐藏真值；
- 上层 force horizon 的法向力由短时材料/接触状态的可实现区间或动态关系限制，而非任意瞬间跳变；
- 下层 WBC 的正常受力、允许压入/速度、切向滚动/滑动使用同一接触状态；在材料上不同时施加零压入硬锚和变化中的有限刚度力；
- 当前完整浮基、原关节/力矩/输入及真实摩擦边界仍保留；future SRB 不能假装已经有未建模的完整关节可行性。

这比再给某个 soft cost 加权更有物理针对性，但目前它是后续条件性修复，不应在已确认 Jdot 缺项前被指定成唯一原因。

## 6. N-r48：修了总加速度定义，但支撑条件仍缺失

### 已完成的修订与保留能力

`experiments/terrain_memory/w54_e_core_r48.h` 把 r44 的“力矩修正产生多少向上加速度”改成总法向加速度目标；`w54_e_native_r48.h` 和 `scripts/s1_go2_w54_n_execution_r48.py` 同构加入漂移项和正确方向差分的 Jdotv。每个 native transition 和其 perturbed FD 都经同一 E，2 ms 命令 hold 由两个 1 ms native 步表达；实际 plant 仍为十个 0.2 ms 步。这个组合的一致性比“只在真实执行时加一个 shield、预测完全看不见”正确。

但 `H=J_z M^{-1} S^T` 与 `drift=Jdotv+J_z M^{-1}(-bias+passive-friction)` 仍是**没有其他脚支撑反力的 articulated 自由响应**。四足共同站着时，这个模型可以给多只已承载脚计算几十甚至上百 m/s² 的向下加速度。对这种模型的可用制动力再乘 0.25，并不会自动变成带支撑的真实可用制动。

现有 core 从原输入/力矩交集内的 raw torque 出发，执行 24 步投影梯度，只优化四个脚的法向增量。当前目标不惩罚/约束对已有支撑反力、机身姿态、机身高度及关节恢复能力的影响。各脚独立用各关节上/下界求 `a_max` 也不意味着多脚、浮基和当前支撑能够同时达到这些最大值。

### 保存数据确认问题在非足触地之前已经发生

新增纯数组脚本 `audit_w54_n_saved.py` 以**同一原输入/力矩交集内 clipped raw torque**为基准，因此不会把原动作本来就会发生的 clip 误算成 E 的改变量。

- 在 E 首次激活约 5.864 s 至 500 Hz 记录首次非足触地 6.908 s 之前，有 243 个激活 tick，其中 **169 个**修改了当前 >10 N 支撑腿的命令力矩。
- 这些激活 tick 中，支撑关节的修正 RMS 为 **10.424 Nm**，最大绝对改变量 **71.984 Nm**。后者是两个合法力矩之差，不是超出力矩上限 71.984 Nm。
- `t=6.380 s` 时 FL/RR 分别承载约 **83.0/233.1 N**，FR/RL 不承载。E 对 FR 预接触激活，却把 FL/RR hip 分别改 **+6.68/+6.47 Nm**，FR calf 相对 clipped raw 改 **−41.24 Nm**。
- 同一 tick 中 E 给 FR 报出的“目标/实现总法向加速度”仍为 **−53.47 m/s²**。因此 gate 后的目标有时仍是向下加速，不能把这个字段称为已实现的制动或保证的 0.05 m/s 落足。

这证实了耦合修正发生在损坏姿态之前、且作用到已有支撑。它没有隔离“如果没有这次 E 修正就一定不会倒”的反事实，不能越界写成唯一因果。

### 候选可行性缺全身覆盖

`W54PredictedDomainOkay` 只在已知材料区域检查足底 `gap ≥ −0.001 m`。它不是完整材料主应变验证，更不是全身恢复能力验证。

同次 `n-r48-analysis.json` 的已保存候选显示，6.380 s 被选候选的终端机身高度约 **0.244 m**，6.580 s 被选候选约 **0.206 m**；6.580 s 的十个候选全部通过足法向代理，却所有终端机身高度都不高于约 **0.2193 m**。该时刻实际机身尚约 **0.2784 m**。因此是在前瞻已经看到持续下降时，目标/约束仍允许安装这些候选，而不是最后倒地才突然出现问题。

名义候选本身不是越权旧 policy 逃生：r48 明确在当前状态重新 rollout、同排序后才可选。已查分析仅有一次运动中的 reassessed nominal 被接受（约 2.20 s），不能把后段失败笼统归为“旧 policy 过期”。应保留这种同状态重评能力，再让它接受正确全身约束。

## 7. N 的可实施完整替换，避免仅加高度阈值

接口继续是确定性的 `E(q,v,u_raw; current causal support/material state)`；共享 core、Python 执行和 native rollout/FD 必须相同。若接入顺应状态，该状态必须作为明确的因果输入在预测状态中同步，不能在 Python 一边额外藏历史、native 一边没有。

### 7.1 支撑条件下的执行投影

建议在现有 `W54ApplyE` 的位置建立小型浮基联合投影，未知量为 `(qacc, tau, lambda_support)`，或对它作等价消元后再向现有 12 维 core 提供响应。其基本关系为：

\[
M a+h=S^T\tau+J_{support}^{T}\lambda+f_{known}.
\]

当前支撑脚必须使用当前接触点、正常/切向几何、真实单边及摩擦边界；硬地球足采用与接触点一致的 rolling/支撑模型，材料承载脚的法向通过当前因果顺应状态联系加速度/速度/变形与力。不能把自由 `M^{-1}` 用一个统一折扣系数变成所谓支撑感知，也不能把有压入的软材料足硬钉在未变形平面。

在固定支撑模式的硬约束极限，其响应应具有接触条件投影，例如：

\[
A_c=M^{-1}-M^{-1}J_c^T(J_cM^{-1}J_c^T)^{\dagger}J_cM^{-1},\qquad H_c=J_{swing,z}A_cS^T.
\]

有接触正则化/顺应时需使用相应物理关系的 Schur 系统；不能不说明 R 的来源就把任意 `+R` 当真实 MuJoCo 接触。直接联合求解的好处是可以同时保留反力单边/摩擦界、浮基约束和力矩界，避免投影后反力落到不可行区域。

优先级应清楚：原动力学/输入/力矩/接触物理边界为硬界；支撑和机身可恢复性优先；下降且尚未承载脚的低冲击速度是可达目标。目标不可达时报告其剩余量，不以牺牲另一脚支撑或盲目全关节饱和来假装达到。原 2 ms hold 的输入持续性和关节可达性也进入同一投影，不仅约束当前瞬间 `tau`。

涉及的精确改动范围：`w54_e_native_r48.h` 的 22–54 行负责几何/动力学/支撑条件构造；`w54_e_core_r48.h` 的 9–49 行负责原边界、目标与投影；Python `PrecontactE.apply` 必须调用同一实现/同一输入。现有中心差分 Jdotv 保留，不补 F 的解析缺项。

### 7.2 所有候选统一全身检查，并给优化器生成可行候选的能力

在原 `W54PredictedDomainOkay` 和 trajectory/native 接入位置，每一个 native 子步统一检查：原允许的接触 body 集合与非足几何接近、原机身失效边界之前的可恢复下降/姿态裕度、原关节/输入/力矩界，以及因果材料状态/域。机身裕度应与速度、支撑和制动能力相关，不能单独把高度阈值提高后宣布修好了。

新 rollout、line-search 候选和当前状态重新评估的 nominal 必须经过相同检查和排序。同样需要在生成侧有明确的可行 warm start / 恢复候选：由上述支撑感知投影形成，短时降低前进加速度、保持支撑和恢复机身，但仍按原任务目标和完整同一预测 horizon 重评。它是一个公开的、被打分的当前候选，不能成为跳过检查的暗中备用控制器。

否则，6.58 s 已保存的十个候选会因新增高度阈值一起被拒绝，只把 body fall 改成较早 controller_infeasible。新增检查必须与新增可行候选生成成组实施。

若同状态重评后仍无任何满足硬界的候选，该次真实尝试应明确返回 `controller_infeasible`，保存第一违反约束和候选残差。不能偷偷安装旧 policy、放松原材料/力矩界或把任务缩短为站立。整个 W55 工作继续修复生成器/模型，不以“两次失败”或墙钟截止作为总停止条件。

## 8. C 全 GPU 的现有证据和正确后续角色

已完整阅读 `s1_w54_gpu_force.py`、`w54_gpu_force_horizon.py`、`w54_gpu_prepare_inputs.py`。最新 r52 C 不是一小段单节点矩阵运算：

- 14 个 interval，每节点独立四脚 xyz 力，共 14×12 决策；12 状态 SRB dynamics 被完整 condense；状态/终端/力及相邻力差目标均覆盖。
- JAX FP64 的 4096 次 accelerated projected gradient 在 GPU 上优化；投影实现了四面内接摩擦金字塔的 Euclidean 投影。
- CPU OSQP 使用同一全状态/逐节点力 convex QP 作参考；CPU 还独立重算动态、目标、swing zero、法向上下界、金字塔和物理圆锥。
- r52 的 16 个自然保存状态、224 个力区间全部通过其 SRB 可行性检查；每个受力力臂是保存的真实/预测接触点而非球心。

边界也很明确：CPU/GPU 不是相同优化预算；时延是离线 batch 口径；单一名义接触 continuation；无全身 WBC、无材料动态、无在线安装。输入来自失败轨迹不影响“同一数学问题的完整求解”这个结论，却不能证明该数学问题足以让机器人稳定走。

W55 可以将空出的 GPU 用于独立 PANN/材料域核验或在 F 物理稳定后在线集成真实有效算子；不应把再做一次同样 16 个 force horizon 作为新稳定性任务。两条主控制线和材料审查可以并行，F 的首个修后 E30 不需要等三条都冻结。
