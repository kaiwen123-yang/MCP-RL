# 真实资产上的强冻结基线与最多两个候选问题

日期：2026-10-17（Asia/Shanghai）。依据当前接续状态、`24b392c`对应独立复审、狗/臂物理合同及本轮源码/公开资产核查。本文不运行策略、环境、训练或硬件，不选择主平台，不继续扩展已经收尾的解析例。

**结论先行：当前没有“强冻结机器人反馈仍失败”的证据。**已有Go2权重候选可以用于后续原生接口核验，但任务响应、全体扫掠与闭环性能尚未验证；Piper H已有SDK/独立模型及视觉模仿学习资产，却没有核到可直接接入本研究MPC命令的成熟低层RL执行器。下一步优先分清接口、状态估计、历史、预测及规划问题，而不是预设必须训练。

本阶段只保留一个共同科学问题：**在合法命令、实际观测/history和输入权限相同，且固定反馈已经配有当前响应模型、完整几何及充分规划后，阶段入口的残余平移/转动运动是否仍造成可测的等待或重接近；若有，改变真实反馈能否在不降低完成/约束质量的前提下改善完整任务时间，同时使新的条件响应仍能以可负担成本被MPC预测？**下面D/A是这个问题的两个资产候选，不是两个已确认瓶颈或两项创新，也不据此锁定主平台。

## 2. “冻结反馈”必须冻结完整执行函数

基线的低层对象应是

\[
\Pi_B=(\text{actor权重、estimator权重、归一化、history更新、动作映射、PD/伺服、延迟/保持规则}),
\]

而不只是一个actor文件。至少记录checkpoint及配置hash、网络/关节顺序、输入单位、命令坐标、history初始化与持续更新、确定性推理规则、动作缩放/限幅、低层模式、伺服增益、真实反馈字段、时间戳与已核延迟。

HIM作者源码中，45维当前观测由命令、角速度、重力投影、关节偏差、关节速度和上一动作组成；六帧历史输入estimator，actor再接当前观测、估计速度和latent。真实速度/外力等训练特权量不因为出现在critic记录中就成为部署actor输入。[观测与history实现](https://github.com/InternRobotics/HIMLoco/blob/ef289acaa62795009363b7b819c9186690630441/legged_gym/legged_gym/envs/base/legged_robot.py)、[actor接口](https://github.com/InternRobotics/HIMLoco/blob/ef289acaa62795009363b7b819c9186690630441/rsl_rl/rsl_rl/modules/him_actor_critic.py)、[estimator](https://github.com/InternRobotics/HIMLoco/blob/ef289acaa62795009363b7b819c9186690630441/rsl_rl/rsl_rl/modules/him_estimator.py)。

若只更换estimator而冻结actor，实际闭环仍会改变。这是合法的“估计改进”对照，但不能同时称为同一个冻结反馈。若模型/候选获得更准的外部位姿、速度、接触或载荷信息，基线也须获得同样合法信息；评价真值与控制输入分别标明。

history、控制器记忆、命令队列及伺服状态跨阶段保持。不能在每个MPC候选开头把它们归零，也不能把HIM latent、一个关节角快照或一张图像未经验证地当作未来响应的充分状态。

## 3. 强冻结基线的最低完整规格

| 环节 | 基线必须获得什么 | 未满足时优先归因 |
|---|---|---|
| 合法命令适配 | 使用原接口全部允许字段、原训练/已验证范围、真实更新率与保持规则；支持连续命令搜索、参考时间缩放和合适的preview | 原命令利用不足，而非低层不会 |
| 状态与history | 原生estimator/历史和与候选相同的可用外部估计；保留时间同步、接触/模式及动作历史 | 估计或信息缺口 |
| 当前反馈响应模型 | 针对同一完整 \(\Pi_B\) 校准，条件含必要历史/模式；验证多步及接续，而非把命令当瞬时执行 | predictor错配或表示不足 |
| 几何/约束 | 同一全体扫掠、载物/足端、限位、输入模式、允许接触及测量余量；正确用于选支 | 几何遗漏或选择器错误 |
| 求解与路线 | 合理warm start、连续命令/轨迹优化、足够参考预览、合法等待/减速/重接近/绕行 | 有限搜索或时域不足 |
| 确定性部署 | mean输出经原动作/PD/伺服链，使用同一初始化与持续状态 | 接口/随机性对象不同 |
| 模型不确定性 | 当前policy的误差范围、状态估计延迟和已声明外扰历史；未支持时返回UNKNOWN | 证据不足，不能说策略失败 |
| 成本预算 | 交互/辨识/模型推演、估计、优化、训练及端到端时间全部记账 | 不能以候选数相同冒充同预算 |

“准确当前模型”在此是一个要验证的条件，不是免费oracle。仅有全局MSE较小不够：至少要知道任务查询的方向、命令转换和多步终端误差是否可靠；转弯/制动瞬态、动作接续及几何边界附近应单独覆盖。历史不足导致多模态响应时，先允许基线增加合法的history/状态表示或不确定性模型，不强迫一个错误单值低阶模型。

为排除规划预算解释，可将充分离线命令优化作为诊断，允许它使用更多计算但如实记账；它找到可行/更好方案说明原能力可被更好调用，不证明该额外预算已适合在线。找不到仍是UNKNOWN，不是神经不可达。

## 4. Go2：候选问题D，仅保留一条具体链

**问题D：在侧向脉冲之后，当前冻结策略的横向速度、偏航角速度与接触/历史状态怎样影响转弯—全身过门—停车的时间和余量？** 本轮只确认需要哪些状态与接口，不预判策略已经做不好。

### 4.1 可依托的真实资产与接口

`rl_sar`两候选各有实权重与对应配置，但观测顺序、history、默认站姿、关节mapping、命令缩放及PD不同，不能共用一个“差不多”的输入向量。HIM版用45×6历史，单帧版用45维；原配置的目标为5ms控制环、4倍decimation的20ms策略调用，这是源码配置，不是本机实测端到端控制率。[Go2基础配置](https://github.com/fan-ziqi/rl_sar/blob/376d42c9b128f963ab08579762d5a216a976ce39/policy/go2/base.yaml)、[HIM版配置](https://github.com/fan-ziqi/rl_sar/blob/376d42c9b128f963ab08579762d5a216a976ce39/policy/go2/himloco/config.yaml)、[单帧版配置](https://github.com/fan-ziqi/rl_sar/blob/376d42c9b128f963ab08579762d5a216a976ce39/policy/go2/robot_lab/config.yaml)。

真实接口接收持续 `/cmd_vel`；不能把强基线限制成一个事先固定且永不调整的速度命令。实际发送链是关节q/dq及PD字段，`tau=0`，不是任意足地力权限。代码另算的PD torque clip与真实发布路径须区分；yaml中的23.5/33.5不能直接当作已强制执行的实际力矩上限。默认FSM的模型选择也应显式核验，不能以为改了文件名就运行另一个policy。[Go2真实执行源码](https://github.com/fan-ziqi/rl_sar/blob/376d42c9b128f963ab08579762d5a216a976ce39/src/rl_sar/src/rl_real_go2.cpp)、[RLControl实际消费与输出](https://github.com/fan-ziqi/rl_sar/blob/376d42c9b128f963ab08579762d5a216a976ce39/src/rl_sar/library/core/rl_sdk/rl_sdk.cpp#L589-L607)。

### 4.2 具体状态与模型查询

任务级模型至少要能区分：相对门/转角位置与朝向、\(v_x,v_y,\omega_z\)、roll/pitch、关节/上一动作及必要history、可用的接触/模式估计、当前命令与保持时钟。HIM latent可以作为候选条件，但不宣称它独自包含全体扫掠与未来命令响应。

查询是“同一当前可用信息下，若现在减速、转向、侧移或先等待再进入，当前冻结反馈会怎样推进全体几何与停车状态”，不是“命令值就是实际速度”。门框安全必须覆盖躯干、连杆、足端摆动和独立测量余量；只预测base中心不能区分通行完成。

### 4.3 最强替代解释先行

1. 若正确时间同步、history与状态估计已减少所见偏差，归因估计，不归因新任务反馈。
2. 若加入当前policy的制动/转向滞后或步态/历史条件后，固定policy的MPC已能提前减速并通过，归因响应建模/规划。
3. 若合法命令适配、宽路、等待或充分求解已达到完整任务取舍，停止该实例的反馈创新主张。
4. 若只在更换policy时保留旧模型才出现差异，先归因模型版本错配，不当作共同学习必要性。

**未证研究假设D：**在上述强基线到位后，如果同信息的可靠预测必须非常复杂/昂贵，或者固定反馈在完整任务中持续付出可测的等待/重接近代价，是否能通过真实反馈与紧凑响应表示的共同改变，在匹配完成质量和总预算下得到更好取舍？这是待检验假设，不是已经发现的失败或贡献。ReCo的低阶响应、HIM的history估计和SPlaTES的共同学习已经覆盖它的重要前提。

## 5. Piper H：候选问题A先降到执行链与任务资产的门槛

**问题A：在真实H伺服模式与同一载荷下，关节/物体残余运动及命令历史是否影响“通道后转姿态—承托—释放”的完整任务，而合法轨迹时间缩放和正确模型仍留下可测差距？** 当前未取得支持后半句的实验事实。

官方H型号的SDK/URDF存在，但H与普通Piper的J4/J5范围、MDH和力矩转换不同。强基线必须使用实际机型/固件/模式；写出机器人力矩方程不代表本研究拥有直接力矩控制。具体版本与接口证据见本轮Piper资产核查，不从Go2或普通Piper推移权限。

已核的Kavin pi0-fast-Piper-H资产属于视觉模仿学习：当前右臂关节与夹爪、front/腕部图像和语言条件，输出动作chunk。它没有经本轮核验的MPC局部命令输入、状态history、\(\dot q\)/力反馈或受扰通道放置验证。`ft-v2`转换记录把同一插值telemetry同时放进state与action字段，因此不能直接将该数据当作实际执行指令到响应的辨识标签。重采样20fps也不是硬件反馈或闭环伺服速率。[模型卡](https://huggingface.co/Kavin60606/pi0-fast-piper-h-plate-pick)、[模型修订](https://huggingface.co/Kavin60606/pi0-fast-piper-h-plate-pick-ft-v2)。

这类资产可作为其声明视觉任务的IL来源，不能drop-in命名为“已经具备的低层RL＋MPC执行器”。若要把动作chunk外接MPC，必须明确MPC能改变的是chunk目标、时间、关节指令还是底层控制；修改策略接口属于新适配，不算原模型已支持。

当前应先具备：实际H模式下的可核冻结执行器/跟踪器、固定载物变换、附着物与全连杆碰撞几何、允许的关节/速度/伺服输入、夹持/释放模块、时间同步及外部物体测量。模型必须区分目标指令、已执行反馈和遥测，保留命令队列/历史与载荷条件。FK不能独立证明物体没有滑移或最终已经放稳。

强冻结对照包括合法轨迹重定时、提前转姿态、低速接近、停稳后释放、宽路和重新接近。若这些完成任务，就不能通过禁止它们、缩托盘或要求不合理速度来制造反馈必要性。

**未证研究假设A：**只有获得实际命令条件执行策略及其模型后，才讨论载荷/接近状态下的反馈—预测共同改善。当前更强的替代解释是接口、模式、遥测标签或轨迹规划不足；没有已确认的学习缺口。因此A保留为任务/资产候选，不与D争夺一个预先决定的“主平台”。

## 6. 同信息直接方法应面对同一个问题

真正的强直接对照应共享：同一actor及完整执行链、观测/history、任务预览、场景/扰动信息、模型及误差、命令权限、几何、约束、风险口径和总预算。

- **冻结策略＋准确当前模型＋正确规划：**先判断已有能力是否足够，避免重演旧servo中模型/选支/搜索误差被误称反馈缺陷。
- **同信息model-based PO／robust PO：**对相同任务、部署mean策略和完整反馈链计算直接信用。与本研究相同梯度或相同有限步骤是正常结果，不是需要绕开的反例。
- **受策略约束TO：**若动作必须由同一神经策略及合法命令产生，消去状态后的任务导数可以与直接策略梯度相同。若TO自由选择任意关节力矩/反馈矩阵，应标为更宽控制类，不拿它与位置伺服策略假装同权限。
- **经典估计/控制增强：**HIM式估计、延迟补偿、指令整形、输入前馈和已验证PD/阻抗选项在真实接口允许时均应开放；若改变了完整反馈本体，单列归因与预算。

SPlaTES已覆盖技能/模型共塑、任务规划引导数据；ReCo已覆盖响应塑形、冻结策略辨识与policy-aware规划；HIM已覆盖从本体历史获取控制所需估计。当前不能把三者重新拼接成三个创新。若最终只是在完整信息下再实现一次标准任务costate，应保留为基线并停止独立算法优势主张。

## 7. 继续/停止所需的最小证据

| 状态 | 需要什么证据 | 当前允许结论 |
|---|---|---|
| 资产可读取 | 固定checkpoint、配置和源码、输入输出及原生映射一致 | 具备后续静态/离线核验入口，不等于能走/能抓 |
| 固定反馈可执行 | 原生控制链、实际状态/时序、对应机器人与条件均核验 | 该条件下有冻结反馈基线 |
| 模型/规划缺口 | 当前反馈数据与预测误差、合法命令及正确约束的完整任务证据 | 可归因到估计/模型/搜索，不自动需要学习 |
| 待研究反馈取舍 | 强冻结基线已允许合理等待/减速/绕行，仍有同信息可复查的时间/资源/可靠性差距 | 有具体控制需求，仍不等于新算法 |
| 共同学习增量 | 候选实际改变反馈、配套模型被规划消费，并在匹配总预算下优于强直接方法或给出独立可靠性/计算收益 | 才能讨论独立研究贡献 |

只改预测、估计或规划就解释收益时，停止对应反馈创新主张。有限求解未找到、状态估计不可信、错误接口或未知硬件限额时，结论是未判定/资产不足，不能写“机器人需要RL补能力”。如果强直接方法已经解释全部效果，停止该方法优势主张，不停止用户的整体科学问题。

当前两候选均未运行强冻结基线，所以本文不报告失败、成功率、制动能力或在线延迟结果。下一阶段的实验/训练是否必要，须由真实资产与完整任务证据决定；主平台仍未选。后续确需训练时按用户要求在服务器执行，本轮未连接或启动训练。

### 8.2 未来最小配对闭环记录应包含什么

`c6b03c5`已更正范围：匹配策略/模型/现有环境具备时，事前有上限的headless冻结仿真已允许；不以“不训练”为由一概禁止评价。实机与训练仍不在本轮范围。本轮实际未产生这类闭环记录，具体环境/模型缺件见[整轮报告](../../docs/platform-assets-and-research-gap-2026-10-17.md)。先固定同一个完整低层策略与共同任务，比较原生规划和**正确估计/当前响应/几何/合法命令增强的冻结基线**，优先检查已有能力能否解决问题，而不是先训练候选。

每条记录从共同启动到最终完成/失败/截尾连续保存：

1. 传感、状态估计、history/latent及对应时间戳；没有导出latent权限时保留可重建它的真实输入。评价外部真值与控制器实际使用信息分列。
2. MPC提出、经过映射/限幅、实际保持/发送的命令，以及actor原输出、实际q/dq/PD等执行字段；目标指令、已执行量和遥测不能共用一个含混的action列。
3. 连续物理/伺服状态、接触或夹持状态、允许获得的载荷/滑移信息；未知量按估计来源及误差记录。
4. 实际几何与阶段事件、全体扫掠/物体终态测量；Go2不只报base中心，Piper不只报FK TCP误差。
5. 扰动的已发生时序和测量来源、命令/反馈/推理/规划延迟；不得给任何方法本次未来波形。
6. 完整任务成本、等待/慢行/绕行/重接近时间、失败/保护介入、评价截尾和UNKNOWN原因；全部进入共同分母。
7. 与当前policy对应的辨识/校准来源，以及独立评价记录；拟合片段不能同时被当作独立闭环检验。

配对指相同任务定义、可用信息、初态/扰动族及公平预算，不假设真实硬件每次扰动和轨迹能逐点完全重复。具体次数、幅值与阈值必须待真实测量和任务冻结后确定，本页不给虚构样本量或安全限额。

若这些记录表明差距首先来自history/估计、真实动作映射、缺少命令响应标签、模型模式混合或规划路线/时间安排，就优先归入相应基线修复。只有完整强冻结基线仍有可复查的任务—资源取舍，才讨论是否需要反馈学习；届时真正训练按用户要求在服务器，不从本轮静态资产缺口直接启动。
