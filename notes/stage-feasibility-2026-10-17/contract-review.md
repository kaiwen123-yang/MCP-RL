# 阶段可完成性合同：先排除规划与选支缺口，再判断反馈瓶颈

日期：2026-10-17（Asia/Shanghai）。依据`fcbdde7`的[执行闭环独立评审](../../docs/execution-aware-mpc-independent-review-2026-10-17.md)、[首篇共同科学问题](../../docs/paper1-dual-platform-research-plan-2026-10-17.md)及[双平台实机设计稿](../../docs/paper1-hardware-experiments-2026-10-17.md)。本页只作任务合同与强比较审查，不运行模型、MPC、环境或训练，不改checkpoint，不新增文献泛读。

**主要决定：**不能从原reference-only选择器的tube违反，直接推出冻结反馈能力不足。先给冻结策略准确执行模型、所有已声明执行约束和充分的连续命令规划，再判断是否存在无法完成后段的状态。**当前原任务没有物理阶段完成定义，本轮不建立或运行新的数值阶段成功实验。**交付的是可执行合同schema、尚缺的物理输入及由后段合同反推入口的定义；不采用P椭球/64tick切换时间拼成新的阶段成功标准。

## 1. 原任务有哪些事实，尚未包含什么

原生servo的目标每64个低层tick更新，dt=.02，即每1.28 s更新；命令每10tick更新，预测80tick。原任务只逐拍累计

\[
\ell_n=(p_{n+1}-g_n)^2+0.005u_n^2+0.01v_{n+1}^2,
\]

并记录实际域、参考域及 \((x-z)^TP(x-z)\) 的tube预算。**原代码没有“每64拍必须到达并停稳”“每阶段必须进入目标椭球”或完整阶段成功率定义。**原PPO的total另含一步超量及空support罚项，不等于该task成本。[原配置与指标](../../src/response_ppo/env.py#L20)

最近评审已经指出：在244个已有共同可行候选的penalty查询中，新主选择器仍163次选择tube超界轨迹。这首先是目标/选支合同未使用已知执行要求的证据。另有140个有限池查询未找到共同可行候选，但有限池失败不证明连续命令问题无解。

后续不重复证明“actor已接通”或“任务梯度非零”代替研究。需要新的证据是：**即使预测准确、约束正确使用且命令规划充分，当前反馈仍限制了合法后续动作；改变反馈在同权限下能够解除这种限制，并值得付出学习成本。**

## 2. P/tube能否定义目标平衡的阶段捕获集

### 2.1 平衡点本身成立，但范围是名义对象

原实际状态为 \(x=(p,v,a)\)。在w=0、目标g恒定时，名义静止平衡为

\[
x^*(g)=(g,0,\sin g),\qquad u^*(g)=\sin g.
\tag{C1}
\]

代入原显式Euler方程即可检查；g在原目标幅值范围内时，该平衡输入不触及原U。参考z在命令c=g时也具有同一名义平衡，但**冻结神经actor未必恰好输出该平衡输入**，需要独立验证，不能由参考模型的平衡推给实际actor。

持续非零负载w下，平衡执行器值应为 \(a=\sin g-w\)。因此(C1)不是所有受扰条件下共同的精确平衡。把a偏离 \(\sin g\)一概解释为恢复不足，会把正确负载补偿也算进偏差；阶段合同和结论必须保留这一边界。

### 2.2 原tube不等于目标捕获

原预算是

\[
V_e(x,z)=(x-z)^TP(x-z)\le b_{tube},\qquad b_{tube}=2\times10^{-4}.
\]

若改为

\[
\mathcal C_g=\{x:(x-x^*(g))^TP(x-x^*(g))\le2\times10^{-4}\},
\tag{C2}
\]

若采用它，就会形成**新阶段达成合同**，不是原条件的重新命名；本轮不采用它。即使x=z离g很远，原tube也为零，而(C2)可能不成立。更一般地，

\[
\|x-x^*\|_P\le\|x-z\|_P+\|z-x^*\|_P.
\tag{C3}
\]

原tube没有控制第二项。P来自原固定名义线性设计，也没有自动给出各目标、实际网络、输入饱和和扰动下 \(\mathcal C_g\) 的不变性。

**未采用的诊断选项：**即使在看新增结果前借用原P/预算定义(C2)，也只是另造一个servo阶段末采样达成条件，不能因此获得机械任务依据。原目标每64tick切换，同样不表示每1.28 s必须到达并停稳。此前可构想的“四个64tick内进入(C2)”方案（SC-1）**不被本轮采用、未运行，也不是接下来默认任务**。

**不允许的用法：**查看轨迹后调椭球半径、截止时刻或保持时间；把旧tube通过追认成阶段成功；仅因某个新阈值让固定策略失败，就认定RL必须改变。

## 3. 物理任务合同schema：缺少字段时不生成成功数值

后续合同应首先说明“做完后段”在物理上意味着什么，再由这个要求定义入口。以下schema可供实现器读取；当前缺失项保持`UNSPECIFIED`，**不填入P预算、旧成本均值或结果分位数来补空缺**。它不是一份已锁定的四阶段servo成功协议。

| 字段 | 必须给出的物理/算法内容 | 当前已有与缺失 |
|---|---|---|
| `task_instance` | 有序阶段或任务图、各阶段对象/几何目标、完整run身份 | 原servo只有随时间切换的位置目标；狗/臂阶段图仍是设计稿 |
| `initial_condition` | 实际状态、控制器/参考/执行器记忆及初始可用任务信息 | 原servo的x、持续z、冻结design/actor、持有命令可读；不能只保存位置 |
| `stage_entry[j]` | 后段需要的可测位置/姿态、速度、接触/负载等条件，及其来源 | **UNSPECIFIED**；不能把tube直接当入口，也不要求所有阶段先停稳 |
| `stage_goal[j]` | 阶段完成的事件/集合及几何含义；传感误差怎样进入判定 | **UNSPECIFIED**；目标信号g不自动等于成功事件 |
| `transition_rule` | 达成后允许何时切换、是否允许提前进入/等待、哪些状态延续 | 原servo命令10tick网格、目标64tick网格可沿用作时序分析，但目标切换不是完成事件 |
| `deadline_or_duration` | 真实期限、最大时间或可自由完成；来源与所有方法共同权限 | **UNSPECIFIED**；不将64tick、80tick或旧评估长度追认成达成期限 |
| `path_constraints` | 实际位置/速度/输入/碰撞/接触等必要要求；约束还是诊断明确区分 | servo实际域、reference域、U、原tube可作已有执行资格审查；哪些构成机器人任务硬要求尚待物理定义 |
| `completion_and_hold` | 顺序完成、终端判定、必要持续时间、超时/接管/技术无效规则 | **UNSPECIFIED**；不从一次采样入集推持续停稳 |
| `disturbance` | 外力/载荷/模型变化的来源、时序、支持范围或分布、是否可预知 | servo原W=.04及隐藏相位场景已知；其真实phase不供planner预览。机器人需实测装置/载荷条件，数值未定 |
| `observations` | 各模块可见状态/历史/传感信息，未来任务预览长度及扰动未知量 | 原actor17维观测与planner的x/z/目标预览已明确；所有强对照必须相同 |
| `control_authority` | 低层输入、命令范围/频率、伺服/限幅、允许减速等待绕行 | servo c±.45、eta .8–1.2、每10tick保持、U1.2；不能偷偷重置z或提高某组命令频率 |
| `cost_and_budget` | 完成优先级、时间/资源代价、模型/辨识/学习/在线优化成本 | 原task表达保持；原total另列。新任务的期限或精度不能靠权重临时补出 |
| `evidence_scope` | 名义、有限场景、概率或全扰动保证分别声明；未证明项保留UNKNOWN | 原记录只覆盖所测短程场景；不等于机器人成功率或鲁棒后段可达证明 |

可执行的机器可读结构应是：

```text
contract_version, instance_id, task_graph
state_and_memory_schema, observation_schema, command_clock
stage[j]: entry_predicate, completion_predicate, transition_rule,
          deadline_or_free_time, hold_requirement, source_of_tolerances
path_constraints, disturbances_and_information, control_permissions
task_cost, failure_rules, evaluation_scope, total_compute_budget
```

只有阶段完成谓词及其物理依据明确后，才能输出“全部阶段成功/失败、完成时间”等数值。此前可以分析原task成本、旧tube资格和给定控制类的可行边界，但不能把这些中间量称为完整任务完成性。

任务合同应当可被所有方法共同证伪，而不是给候选单独挑选一个有利入口。名义无扰、原有限扰动场景与逐拍 \(|w_n|\le.04\) 的鲁棒问题分别定义；后者比原相关相位族更大，不能把其保守不可行直接说成原场景必败。

## 4. 推荐能力对象：由后段合同反推增强状态入口

实际有用的能力不是“越快归零越好”，而是给定后段与剩余资源时还能完成什么。对冻结actor \(\theta\) 定义后段可行入口

\[
\mathcal E^{\theta}_{j+1}(\mathcal T)
=\{\xi:\ \exists\ \text{合法因果宏命令策略，能满足已给定后段合同 }\mathcal T_{j+1:J}\}.
\tag{C4}
\]

\(\xi\)至少包含实际x、持续z、当前持有命令、全局命令更新时钟、阶段编号及可用任务预览；冻结design/actor是该集合的版本条件。若planner使用扰动历史估计或模式belief，其内部状态也必须纳入，不能假装全部可由当前x/z决定。

原目标段64tick与命令10tick不对齐。例如目标切换n=64时，n=60开始的命令还要用于n=64,…,69，共6拍；该目标切换不自动成为物理任务阶段完成事件。**后段入口不能默认n=64可立即换命令。**否则它给分析器额外控制权限，使一个实际上不可接续的状态被误判为可行。

在名义确定对象中，给出一条满足全部剩余合同的连续取值命令序列，就提供(C4)的可行见证。若采用鲁棒合同，应使用正确的因果量词：允许宏决策利用已发生状态，但不能用 \(\exists C(w_{future})\) 的全扰动预知序列替代因果策略。固定开环宏序列对全部扰动有效是充分见证，但找不到这种开环序列不证明不存在更好的闭环重规划。当前\(\mathcal T\)的完成条件未给定，(C4)是能力对象定义，不是已经算出的集合。

这一定义自然允许两种解释：同样小的局部误差可对应不同z/执行器记忆，导致后段可行性不同；也可能某个较大偏差反而保留有利速度/作用，使下一任务更易完成。是否存在这种差别必须计算或证明，不预设所有恢复都应接近静止平衡。

**入口条件不能按候选方法的偏好定义。**所有方法共享相同外部阶段目标与路径要求。各自 \(\mathcal E^\theta\) 可以不同，但它们都相对于同一合同；不能先用拟方法最方便的入口集规定任务，再据此否定基线。

## 5. 固定策略必须获得的强比较

按以下顺序审查，前层已能解释的失败不继续归到反馈瓶颈。

| 层次 | 冻结策略获得什么 | 若问题在该层被解决，如何归因 |
|---|---|---|
| B0 原有限候选 | 已核actual执行模型、原搜索预算及原reference-only gate | 仅为历史起点，不作为最强基线 |
| B1 正确使用已知条件 | 同一池、同actor/model，对所有方法统一使用已声明的actual/reference/input/tube检查；阶段达成检查仅在合同有物理定义后加入 | 已有可行候选却未选中属于selector/约束合同缺口，不是反馈能力不足 |
| B2 连续命令优化 | 同一精确执行模型及完整合法c/eta区间，宏更新频率不变；预先声明的连续优化、多起点与独立前向核验 | 有验证可行序列即说明原有限搜索不足。非凸求解失败只记未找到，不记冻结策略不可行 |
| B3 足够后段规划 | 完整剩余合同或有效的后段可行终端集；给基线与候选同样任务预览，允许合理重规划、命令适配和合法等待/减速 | 若解决，属于时域/终端条件/命令安排不足，不是必须学习新反馈 |
| B4 同信息强反馈设计 | 同模型、状态/历史、输入权限与合同的标准鲁棒PO/TO或充分整定经典反馈；学习预算/教师信息明确 | 若与候选同信号/同结果，不能称独有耦合；可研究数据、计算或表达取舍 |

B2/B3的“充分”不凭增加若干随机种子就成立。应给出可行见证、收敛/界或全局搜索/松弛间隙等具体证据。一个公平部署预算内的算法比较与一个给基线更充分计算的瓶颈诊断，可以同时做，但需分别计账；不把额外离线求解成本隐藏成同预算优势。

冻结策略的配套模型须准确描述当前完整support/观测/动作链。允许命令补偿使用所有共同可用状态/历史，但不得给候选更多更新频率、未来扰动或执行器权限；若放宽命令节拍/预览作诊断，所有组同等开放并标明是扩大权限。参考z不得重置以人为“修复”误差记忆。

### 5.1 先区分继承状态与当拍控制能力

每个旧查询先记录当前x/z、tube资格、执行器状态及已持有命令。若进入查询前已经超出要求，或者由于原对象的输入相对阶/执行器滞后，即使放松为任意当拍u与合法reference下一状态也不能在一拍内满足旧tube，正确归因是**继承状态与即时物理可恢复性限制**。这不是冻结网络在同一拍“没学会选对动作”的证据。

若用无界执行器动作、放松的合法reference集作外包下界，并证明最小下一拍tube误差仍超预算，这可以排除该时刻所有原权限命令的即时修复；但放松的不可行结果仍只对应这一拍及该旧tube要求。它不证明未来不能恢复，也不证明未定义的后续任务失败，更不能替代“更早规划或反馈本可避免进入该状态”的反事实分析。

因此，原140个空池的进一步一拍界或连续命令搜索，应准确记作**旧tube资格诊断**。一拍物理界已排除的实例无需再以有限搜索失败充当神经能力负证据；其余未排除实例继续区分selector、连续搜索与模型/时域。没有物理阶段完成合同前，不生成新的阶段成功率。

## 6. 上下界与“真反馈瓶颈”的分类

这里的上下界指可行集合及性能界，须说明方向，不能把一个局部求解器结果当作上界证明。

| 证据类型 | 合法含义 | 不能推出 |
|---|---|---|
| 已验证的冻结θ合法命令轨迹 | 对应入口属于冻结策略的可行内集；其完成成本为可实现性能上界（最小化口径） | 全部入口可行、全局最优 |
| 冻结θ连续命令NLP/CEM失败 | 该预算/初始化未找到解 | 固定反馈不可达、学习必要 |
| 冻结θ问题的有效外包/全局不可行证据 | 可排除该外包覆盖范围内的合法命令实现 | 超出被证明模型/扰动域的失败 |
| 放松策略，允许原物理输入u直接选择 | 扩大的控制类，提供物理可行集合外界；若该放松也被证明不可行，原类必不可行 | 若自由u可行，就一定存在同观测/同结构神经反馈；也不证明学习是唯一解 |
| 给未来扰动的非因果oracle | 仅为乐观外界/成本下界 | 可部署因果能力或公平强基线 |
| 某一当前θ不能完成、另一个同权限反馈有可核因果见证 | 支持该实例存在反馈/接口能力差异，前提是前者已充分排除命令规划解释 | PPO训练必能找到、候选共同学习比普通鲁棒优化更高效 |

可考虑的证据链为：先证明合同在物理权限下可行；再给冻结θ足够命令规划仍无法完成的可靠边界；最后展示同信息、同输入权限的反馈改变确能扩大后段可完成入口，并被MPC用于改变计划。任何一环只有“没搜到”时，应保留UNKNOWN，不用“新能力”填补。

对于因果鲁棒任务，放松为任意逐拍u会扩大控制类，但如果其动作还能偷看未来w，外界又更宽；需要显式标出是哪一层。实际反馈变化是否可由同容量actor表达、是否需要新的观察、是否违反输入/支持条件，都要另验。

## 7. 如何判断原servo是否已被强support控制解决

当前已有证据表明：六个support检查点在所测短程原任务上actual/reference域、tube、一步及空support指标均为零；更充分预测/重规划只能带来小幅task改善。这不证明所有扰动和目标都可行，更不能填补尚无定义的阶段成功谓词；但它是必须尊重的强反方。

如果B1–B3加上当前support反馈已经满足旧任务的全部实际要求，或者在未来有物理依据的后段合同中已达到目标，就应直说：**这个对象没有留下需要反馈学习填补的已证缺口。**可以保留它作为接口/可行性基准，不能再收紧期限、缩小捕获集、增大扰动或挑目标序列，让原策略“必须失败”。

若penalty失败但support与经典已充分整定方法通过，只能先证明不同控制结构/约束处理的差异；不能以penalty为唯一基线宣布新的MPC+RL共同学习必要。若只有新接口模型更准或强selector即可解除瓶颈，贡献应收窄为建模/规划。

即使某一反馈瓶颈得到确认，学习的价值仍需和同信息标准鲁棒PO/TO比较。增加控制变量、换网络或换平台不自动构成创新；同一个完整问题给出相同梯度/最优解是正常结果。

## 8. 与狗/臂共同任务的连接及本页未完成项

SC-1/P捕获选项没有采用，不是狗/臂实验或默认下一实验。在机器人中，后段合同应来自任务几何与运动要求：狗转向/通行的扫掠包络、速度与接触条件；臂通道/放置的位姿、残余运动与负载条件。并不要求所有阶段先回到静止平衡，也不直接套用servo的P或2e−4。
